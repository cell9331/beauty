## 1. 接入 Face Landmarker（iOS）

**CocoaPods**：`MediaPipeTasksVision`。模型文件 `face_landmarker.task` 放进 bundle。
以下 API 以官方当前文档为准，这里只给结构：

```swift
import MediaPipeTasksVision

let options = FaceLandmarkerOptions()
options.baseOptions.modelAssetPath = modelPath
options.runningMode = .video            // 同步取结果；.liveStream 为异步回调
options.numFaces = 2
options.minFaceDetectionConfidence = 0.5
options.minFacePresenceConfidence = 0.5
options.minTrackingConfidence = 0.5
options.outputFaceBlendshapes = true                 // 眨眼/张嘴/微笑，比自己算 EAR 更稳
options.outputFacialTransformationMatrixes = true    // 头部姿态
let landmarker = try FaceLandmarker(options: options)

let image = try MPImage(pixelBuffer: pixelBuffer, orientation: .up)  // 方向参数务必设对
let result = try landmarker.detect(videoFrame: image, timestampInMilliseconds: ts)
// result.faceLandmarks[i]: 478 个 NormalizedLandmark (x, y, z)
```

### 输出与坐标

| 项 | 说明 |
|---|---|
| 点数 | 478 = 468 面网格 + 10 虹膜（468、473 为左右虹膜中心，469–472 / 474–477 为环） |
| x、y | 相对**输入图像宽、高**归一化。**必须先分别乘以宽和高变成像素**，再做任何距离/角度计算，否则宽高比会拉伸形变 |
| z | 相对深度，量级与 x 相近，**不是米**。近处更小 |
| 变换矩阵 | 4×4，规范人脸 → 当前人脸。用于姿态；符号/轴约定要用真人转头实测标定 |
| blendshapes | 52 个 ARKit 风格系数，如 `eyeBlinkLeft/Right`、`jawOpen`、`mouthSmile*`。左右含义用实测校准 |

### 模式选择

| 模式 | 优点 | 缺点 |
|---|---|---|
| `.video`（同步） | 结果与帧严格对应，无额外延迟逻辑 | 阻塞调用线程，需放在独立推理队列 |
| `.liveStream`（异步） | 不阻塞 | 结果滞后，需按时间戳对齐，做外推 |

建议：**推理放独立串行队列，用 `.video`，只保留最新帧**；渲染线程取"时间戳最近"的结果。

### 重要提醒

1. **不要重复滤波**：Tasks 内部有跟踪，但是否带平滑不要假设。做法是用固定视频序列分别测"原始输出抖动"和"加 One Euro 后抖动"，确认你的滤波是**有效增益**而不是叠加拖影。
2. **多脸没有稳定 ID**：Tasks 结果里不带跨帧 ID，需要自己用质心/IoU/点距做跟踪。
3. **侧脸点是"猜"的**：大偏航时被遮挡半边的点由模型补全，不代表真实位置。用姿态和 presence 做强度衰减。
4. **模型授权**：核对你使用的 `face_landmarker.task` 及规范模型文件的当前许可条款。

## 3. 局部坐标系与尺度

`code/Landmark478.swift` 的 `FaceFrame478`：

- **原点**：4 个眼角（33, 133, 362, 263）的均值
- **x 轴**：33 → 263 的单位向量
- **y 轴**：x 轴旋转 90°，指向下巴
- **尺度**：33↔263 的距离（外眼角距）

**为什么不用瞳距做尺度**：虹膜点随视线移动，看左右时瞳距会变，所有位移跟着缩放抖动。外眼角几乎不受视线影响。

**状态量**
- 眨眼：优先用 blendshape（`eyeBlinkLeft/Right`），备选 EAR（R `[33,160,158,133,153,144]`，L `[362,385,387,263,373,380]`）
- 张嘴：`|13−14| / |61−291|`，或 `jawOpen`
- 姿态：变换矩阵；备选用 z 近似 `z(454) − z(234)` 与水平距离之比（符号需标定）

## 4. 478 点的网格方案

### 4.1 为什么比 68 点省事
478 点（468 面网格）已经足够稠密：眼睑、嘴唇本身就是 8–16 个点的闭合链。因此：

- **不需要样条加密**（68 点方案里必须加密）
- **不需要 TPS 做"少量点→加密点"插值**。改用**权重图**（见 4.3）
- 但点位噪声更直接地暴露，**滤波要求更高**

### 4.2 顶点布局（`gen_topology_478.py` 生成）

| 段 | 内容 | 位移 |
|---|---|---|
| 0–467 | 面网格点（虹膜 468–477 **不入网格**，随周围顶点插值运动） | 由功能产生 |
| 额头扩展点 | 上缘弧 `54,103,67,109,10,338,297,332,284` 沿上轴外推约 0.35 脸高 | 发际线/额头功能；默认随脸 |
| 颈部扩展点 | 下缘弧沿下轴外推约 0.30 脸高 | 去双下巴 |
| 外环点 | 外轮廓的凸包外扩约 0.25 脸宽 | **恒 0** |
| 边界锚点 | 画面四边 | **恒 0** |

**拓扑来源**：MediaPipe 规范人脸模型 `canonical_face_model.obj`（468 点 + 三角面，路径 `mediapipe/modules/face_geometry/data/`，请自行下载并核对许可）。面内部直接用它的三角面（官方设计过，适合形变），面外用 Delaunay，脚本会检查面积覆盖比，不合格回退整体 Delaunay。

> 烟测说明：脚本我只在合成数据上验证过流程（两种模式都能产出），没有用真实规范模型跑过，请你用真实 obj 生成并看预览图。

### 4.3 权重图（行业常用做法）

不要在运行时写"遍历这些索引做位移"的硬编码，而是**离线给每个功能预生成一张 468（+扩展点）的权重表**：

```
weight[f][v] = smoothstep 衰减( 顶点 v 到该功能"种子点集"的距离 / 影响半径 )
```
- 种子点用本文第 5 节的索引；距离在**规范脸画布空间**计算，一次性生成并写入资源。
- 运行时：`位移[v] += Σ_f  强度_f × weight[f][v] × 方向_f × 姿态权重 × 状态权重`
- 好处：边界平滑、可视化调试（把权重画成热力图）、改范围不改代码、美术/算法可迭代。
- 左右对称功能用镜像对（第 2.1 节表）保证对称。
- 脚本 `region_weights()` 是最小示例，已演示右眼大眼的权重导出。

### 4.4 固定顶点保护
- 虹膜 10 点不入网格，但**大眼时虹膜也要跟着放大**：用虹膜中心所在三角形做重心坐标插值得到其位移；眼睑闭合/睁眼时用开合度限幅，避免虹膜超出眼睑。
- 外环、边界顶点的位移强制为 0。

### 5.3 整脸 / 3D 塑颜

478 点自带 z，加上变换矩阵，可以做"准 3D"：

1. 用变换矩阵把点转换到**规范（正脸）空间**。
2. 在规范空间里做对称/上下/左右/倾斜（直接作用于 3D 点）。
3. 再变换回当前姿态，投影到 2D，得到目标点。

| 功能 | 做法 | 难度 |
|---|---|---|
| 对称 | 规范空间里按镜像对（第 2.1 节表）把偏差向对称靠拢，强度上限 50% | ★★ |
| 上下 / 左右 / 倾斜 | 规范空间里对五官点整体平移/旋转，外轮廓同步跟随 | ★★★ |
| 真 3D 塑颜 | 需要 3DMM 拟合 + 纹理映射，工程量大 | ★★★★ |

> 注意 z 不是真实深度，大幅度 3D 位移会"面具感"。建议限幅小。

## 6. 478 点特有的坑

| # | 坑 | 对策 |
|---|---|---|
| 1 | **左右搞反**：MediaPipe 的 right/left 是被摄者的，图像上相反；blendshape 左右也要实测 | 统一在未镜像空间用本文约定；写单测画点 |
| 2 | **直接在归一化坐标算距离** | 一律先乘宽、高转像素 |
| 3 | **用瞳距当尺度** | 用外眼角距(33↔263)；虹膜随视线动 |
| 4 | **滤波叠加** | 先测 SDK 原始抖动，再决定是否上 One Euro，避免双重平滑拖影 |
| 5 | **眼睑/内唇点高频抖动** | 这些点用更强滤波；眨眼/张嘴状态用 blendshape 驱动而不是从抖点算 |
| 6 | **虹膜点入网格** | 虹膜 468–477 不入拓扑，用重心坐标跟随；否则瞳孔被撕裂 |
| 7 | **以为 10 是发际线 / 478 带耳朵脖子** | 都没有，需外推 + 分割 |
| 8 | **侧脸被遮挡半边点是猜的** | 偏航角 >45° 开始衰减，>60° 关几何形变 |
| 9 | **多脸无 ID** | 自己做跟踪，滤波器按 ID 绑定 |
| 10 | **规范人脸拓扑直接用** | 它为 3D 贴图设计，需检查眼睑/嘴内三角在形变下是否翻转；保留翻转检测 |
| 11 | **z 当真实深度** | 仅作相对量；做 3D 位移时严格限幅 |
| 12 | **输入方向未设** | `MPImage` 方向参数错会让检测质量下降甚至点位错位；前置+竖屏+镜像逐个验证 |
| 13 | **每帧重新三角化** | 拓扑离线固定，运行时只更新顶点 |
| 14 | **经验点位未校验就写进代码** | 先跑 `draw_indices.py` 逐点确认 |

## 8. 开工顺序（478 版）

1. **接入与核对（2–3 天）**：Face Landmarker → 像素坐标 → 在预览上画点；跑 `draw_indices.py` 校验所有 [经验] 点位。
2. **局部坐标系 + 滤波（3–5 天）**：`FaceFrame478`、One Euro；测量抖动指标。
3. **拓扑与网格渲染（1 周）**：`gen_topology_478.py` 用真实 obj 生成；顶点缓冲 + 索引缓冲 + 渲染；翻转检测。
4. **权重图与首批功能（1–2 周）**：瘦脸、大眼、下巴、鼻翼；强度/限幅/姿态/眨眼衰减。
5. **其余五官（3–5 周）**：眼、眉、鼻、嘴全套；联合限幅。
6. **分割类（2–3 周）**：唇色、白牙、祛红血丝、眼瞳。
7. **高阶**：发际线/额头/去双下巴 Pro（头发、颈部分割）、准 3D 塑颜。

性能与坑点沿用 docs/07、08、09。
