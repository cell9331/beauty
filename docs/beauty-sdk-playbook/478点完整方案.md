# iOS 美颜 SDK · 478 点完整方案（可公开发布版）

目标：基于 MediaPipe Face Landmarker 478 点，做一个**可公开发布、可扩展、可长期维护**的 iOS 美颜 SDK。
本文回答三件事：**架构怎么搭、每个功能用什么确定的技术实现、公开发布要避开哪些坑**。
点位索引细节见 `docs/12-478点落地手册.md`，本文引用其中的索引与分组名。

> **关于本文的可信度**
> - 点位索引中标 **[官方]** 的，已与 mediapipe 0.10.33 的 `FaceLandmarksConnections` 连接表逐项比对。
> - 标 **[经验]** 的点位，我没能做几何校验，必须先用 `tools/draw_indices.py` 叠图确认。
> - 文中提到的 Apple/第三方 API 与系统版本要求、模型与数据授权，**发布前请对照官方文档核对**（文末有"待核对清单"）。我没有在真机上编译、运行过 Swift/Metal 代码，`code/` 下均为设计骨架。
> - 数值（半径、限幅、eps 等）都是**起始值**，需在你的相机与目标机型上标定。

## 1. 总体架构

### 1.1 分层与模块（Swift Package / XCFramework 多 target）

```
┌──────────────────────────────────────────────────────────────┐
│ Public API 层   BeautyKit        对外唯一稳定接口（Swift + ObjC 头）  │
├──────────────────────────────────────────────────────────────┤
│ Engine 层       BeautyEngine     编排：帧上下文、特征调度、质量分级    │
│   ├─ FaceTracking   状态机：滤波/ID/姿态/眨眼/丢脸渐变               │
│   ├─ Geometry       语义层 + 权重图 + 位移合成 + 注入性保证           │
│   ├─ Photometric    肤色/调色/局部上色的 Pass 定义                    │
│   └─ Quality        设备画像、热管理、降级策略                         │
├──────────────────────────────────────────────────────────────┤
│ Render 层       BeautyRender     Metal 后端：纹理池、RenderGraph、Pass │
├──────────────────────────────────────────────────────────────┤
│ Provider 适配层（可插拔，各自独立 target，核心不依赖第三方）          │
│   BeautyLandmarkMediaPipe   BeautyLandmarkVision   BeautySegmentation… │
├──────────────────────────────────────────────────────────────┤
│ Assets          BeautyAssets     拓扑、权重图、语义映射、LUT、曲线（带 schemaVersion）│
└──────────────────────────────────────────────────────────────┘
```

**关键原则**

| 原则 | 做法 | 理由 |
|---|---|---|
| **核心零第三方依赖** | `BeautyKit/Engine/Render` 只依赖系统框架；MediaPipe 放在独立适配 target | 避免与宿主 App 的 MediaPipe/protobuf/abseil 符号冲突；宿主可自带关键点来源 |
| **语义层隔离模型细节** | 功能代码只引用"语义区域"（`rightEye.upperLid`、`lips.outer`…），索引来自 `face_model_spec.json` | 换关键点模型（或 MediaPipe 升级）不改功能代码 |
| **几何与像素分离** | 几何产出"目标顶点"，像素类 Pass 只读 mask/参数 | 单测几何无需 GPU；Pass 可独立替换 |
| **一次几何重采样** | 全部几何功能合成**一张位移场**→一次网格渲染 | 避免多次重采样模糊、累积畸变 |
| **能力协商 + 优雅降级** | 每个功能声明所需 `Capability`；缺失则禁用并返回原因码 | 没有头发分割时发际线功能自动不可用，而不是出错 |
| **帧时间戳驱动，不读系统时钟** | 滤波 dt 来自 `CMTime` | 可复现、可离线回放测试；少触及隐私清单的 required-reason API |
| **参数快照不可变** | 渲染线程每帧读取一个值类型快照 | 无锁竞争，参数半更新不会进入渲染 |

### 1.2 语言与跨平台决策

| 方案 | 适用 | 取舍 |
|---|---|---|
| **Swift 核心 + Metal**（推荐，仅 iOS） | 团队以 iOS 为主 | 开发快；`simd` 类型好用；将来上 Android 要重写几何层 |
| C++17 核心 + Obj-C++ 桥 + Metal | 计划跨 Android/桌面 | 几何、滤波、状态机可复用；需 `RenderBackend` 抽象（Metal/Vulkan/GLES） |

两者都要求：**几何/状态机/滤波代码不 import UIKit、不碰 Metal**，只依赖数学类型，保证可单测与离线回放。

### 1.3 一帧的数据流

```
CVPixelBuffer ──▶ [LandmarkProvider] ──▶ FaceObservation(478×(x,y,z), blendshapes, matrix, ts)
                                              │
        ┌─────────────────────────────────────┘
        ▼
FaceTracker（ID 关联 → 校验修复 → 规范空间 One Euro → 姿态/眨眼/张嘴 → 强度门控）
        ▼
FaceContext（滤波点、FaceFrame、状态量、门控 g∈[0,1]）
        ├──▶ GeometryFeatures[*] 各自返回 DisplacementContribution
        │        ▼ 合成 → 联合限幅 → 正则化 → 注入性线搜索 → 目标顶点
        └──▶ PhotometricFeatures[*] 声明 Pass 与 mask 需求
                 ▼
RenderGraph（同一 command buffer）：
  [降采样] → [磨皮 Pass] → [调色/局部上色 Pass(源空间)] → [网格 Warp Pass] → [CAS 锐化] → 输出
```

## 2. 可扩展设计（公开 SDK 的核心价值）

### 2.1 五个扩展点

| 扩展点 | 接口 | 例子 |
|---|---|---|
| 关键点来源 | `LandmarkProvider` | MediaPipe 478、Apple Vision 76（功能子集）、宿主自带 |
| 分割来源 | `SegmentationProvider`（skin/hair/person/neck） | MediaPipe Image Segmenter、`VNGeneratePersonSegmentationRequest`、自训 Core ML |
| 几何功能 | `GeometryFeature` | 新增"耳朵缩小"只需写一个类 + 一份权重图 |
| 像素功能 | `PhotometricFeature`（声明 RenderPass） | 新增"黑眼圈" |
| 自定义 Pass 注入 | `RenderPassInjection` | 宿主在 warp 之后加滤镜/LUT |

### 2.2 功能描述符（数据驱动）

```swift
public struct FeatureDescriptor {
    public let id: String                 // "geometry.eye.size"
    public let category: Category         // .skin .faceShape .eye ...
    public let stage: Stage               // .photometric / .geometry / .post
    public let requires: Set<Capability>  // [.landmarks478, .hairSegmentation]
    public let parameter: ParameterSpec   // 范围、默认值、曲线 ID、是否对称/分左右
    public let costHint: Cost             // 供质量分级使用
}
```
参数曲线（UI 0–100 → 物理量）用**单调三次 Hermite（PCHIP）**存在资源 JSON 里，不写死在代码，便于调优与远程配置。

### 2.3 资源包 `BeautyAssets`（带 `schemaVersion`）

| 文件 | 内容 |
|---|---|
| `face_model_spec.json` | 模型 ID → 语义区域/锚点/镜像对/三庭定义 |
| `topology_478.bin` | 离线生成的固定三角索引 + 顶点类型（`gen_topology_478.py`） |
| `weights/*.bin` | 每个几何功能的顶点权重图（离线烘焙） |
| `curves.json` | 参数曲线与预设（自然/标准/夸张） |
| `luts/*.png` | 1D 色调曲线 LUT、肤色/唇色预设 |

资源与代码**独立演进**：改效果不改二进制；`schemaVersion` 不兼容时明确报错而不是静默出错。

### 2.4 质量分级与设备画像

```
DeviceProfile = { MTLDevice.supportsFamily(.apple…), physicalMemory, thermalState, lowPowerMode }
QualityTier   = .ultra / .high / .balanced / .low / .emergency
```
每个 `QualityTier` 规定：输入缩放、磨皮降采样倍数、是否启用 ARAP 正则、检测频率、启用哪些特征。升降档带**迟滞（hysteresis）**，避免来回抖动。

### 2.5 并发契约（写进文档并测试）

- `setParameters(_:)`：任意线程，**线程安全**，内部原子替换不可变快照。
- `process(...)`：由宿主保证**串行**调用（同一 engine 实例）；多路并发用多实例。
- 推理在内部串行队列、"只保留最新帧"；渲染不阻塞推理。
- 所有回调线程/队列在 API 文档里写清。

## 3. 核心技术栈（按模块，写明为什么这么选）

### 3.1 渲染与色彩

| 项 | 采用的技术 | 避免 |
|---|---|---|
| 纹理上传 | `CVMetalTextureCache` + IOSurface 零拷贝；输出用 `CVPixelBufferPool` | CPU 拷贝、`getBytes` 回读 |
| 像素格式 | 相机输出 `32BGRA` 或双平面 YUV（`420YpCbCr8BiPlanar` full/video range）并在着色器内按矩阵转换；中间纹理 `rgba16Float` | 8bit 中间纹理反复量化导致色阶断层 |
| 色彩空间 | 解码 sRGB 传递函数到**线性光**做曝光/混合；感知调整用 **Oklab/OKLCH**（比 CIELAB 色相更稳）；输出重新编码；尊重 `CVBuffer` 的色彩属性（P3/sRGB） | 在 gamma 空间做亮度加法 |
| 多 Pass 合并 | 调色类 Pass 在**同一 render pass 内用 programmable blending / imageblock（TBDR 友好）** 合并 | 每个小效果一个全屏 Pass |
| 瞬态纹理 | `MTLHeap` + 可别名（`makeAliasable`）；单 pass 内中间目标用 `memoryless` | 每帧创建纹理 |
| 管线编译 | `MTLFunctionConstantValues` 做变体；`MTLBinaryArchive` 缓存，初始化阶段预热 | 首帧懒编译卡顿 |
| 并行 | 3 帧 in-flight + `DispatchSemaphore`，`MTLCommandBuffer` 完成回调释放资源 | CPU/GPU 争用同一缓冲 |
| 模糊/缩放 | MPS：`MPSImageGaussianBlur`、`MPSImageBox`、`MPSImageGuidedFilter`（核对系统版本）、`MPSImageLanczosScale` | 自写低效大核模糊 |
| 分析 | Xcode GPU Frame Capture、Metal System Trace、`os_signpost`、`MetricKit`（诊断，需用户授权采集） | 凭感觉优化 |

### 3.2 几何形变（核心）

**目标**：自然、不抖、不撕裂、背景稳定、可叠加。

| 层 | 技术 |
|---|---|
| 表示 | **固定拓扑三角网格**（规范人脸 468 点三角面 + 额头/颈部扩展点 + 外环 + 边界锚点）；离线生成，运行时只更新顶点 |
| 映射 | **Piecewise Affine Warp（分段仿射）**：顶点位置=目标点、UV=源点，硬件光栅化做重心坐标插值，天然 inverse mapping、无空洞 |
| 位移合成 | **Handle-based deformation + 权重图**：`D(v) = Σ_f s_f · W_f(v) · T_f(v)`，其中 `T_f` 是该功能的相似变换（平移/径向缩放/旋转/剪切），`s_f` 为强度，`W_f` 为权重图 |
| 权重图生成 | 离线烘焙；用**测地距离**（网格图上 Dijkstra / Fast Marching / Heat Method）+ **smoothstep（Hermite）衰减**；**按语义区域分割**（上唇与下唇、上睑与下睑分别生成，避免欧氏距离"漏到对面"） |
| 平滑 | 位移场做 **Laplacian smoothing**（可用 **Taubin λ|μ** 避免收缩）；轮廓切向平滑用曲率流 |
| 大形变高质量档 | **ARAP（As-Rigid-As-Possible）**：Igarashi 2005 / Sorkine & Alexa 2007。约束点=驱动点，固定点=外环/边界；左端矩阵只依赖拓扑与固定集，可**预分解**（Accelerate/LAPACK 或预存稠密逆，N≈600） |
| 注入性（防翻转） | 每帧计算有向面积；对步长做**线搜索（line search）**，保证所有三角形面积为正且比例 > ε；失败则回退上一帧位移 |
| 联合限幅 | 全局位移预算（脸宽比例）+ 顶点级限幅；**软限幅**（`tanh`/Hermite 压缩）而非硬截断，避免出现"拉到上限就停"的折痕 |
| 背景保护 | 外环衰减 + 零位移边界锚点；强保护场景叠加**人像分割**，在人像边界附近压低位移 |
| 采样 | 线性过滤 + clamp；压缩幅度大的区域（如缩头）启用 mipmap + 各向异性过滤 |

> **不要用**：全图 TPS、每帧 Delaunay、CPU 逐像素 warp、串联两次 warp、单纯欧氏距离权重（会泄漏到相邻器官）。
> **TPS/RBF 的位置**：478 点已稠密，不再需要"少量点插值到加密点"。若某功能确实只有少量控制点（例如额头扩展点），在**网格顶点**上做 **RBF（thin-plate 或 Wendland 紧支撑核）插值，加正则项**，而不是在着色器里逐像素算。

### 3.3 时序稳定与状态机

| 项 | 技术 |
|---|---|
| 去抖 | **One Euro Filter**，在 **Procrustes/Umeyama 相似变换对齐的规范空间**里逐点滤波；尺度用**外眼角距（33↔263）**，不用瞳距（虹膜随视线动） |
| 备选/增强 | 常速模型 **Kalman（CV 模型）**；对眼睑、内唇等高频点用更强滤波 |
| 位移层平滑 | 对最终位移再做轻度 EMA，并对**用户参数变化做斜率限制（slew-rate limit）** |
| 延迟补偿 | 同步推理优先；否则**匀速外推**一帧（用滤波器的速度估计） |
| 多脸 ID | **匈牙利算法（Kuhn–Munkres）**在 IoU/质心距离代价上关联；每个 ID 持有独立滤波与状态 |
| 姿态 | 优先用 `facialTransformationMatrixes`；备选 **PnP（EPnP/IPPE）** + 规范 3D 点；欧拉分解后做 yaw/pitch 门控（`smoothstep`） |
| 眨眼/张嘴/微笑 | **blendshape**（`eyeBlink*`、`jawOpen`、`mouthSmile*`）；备选 **EAR（Soukupová & Čech 2016）**、MAR |
| 丢脸 | **门控渐隐渐入（200–300ms）**，状态机：`tracking → degraded → lost → recovering` |
| 校验 | NaN/越界/突变检测 + 规范空间恢复；置信度低则降级 |

### 3.4 分割与 mask

| 需求 | 技术 | 备注 |
|---|---|---|
| 皮肤/头发/身体 | **MediaPipe Image Segmenter（多类自拍分割模型，含 hair、face-skin 等类别）** 或 Apple `VNGeneratePersonSegmentationRequest`（人像） | 核对模型授权与当前提供的类别 |
| 边缘细化 | **Guided Filter 抠图细化（Fast Guided Filter, He & Sun 2015）**：低分辨率分割 → 用全分辨率图像做引导上采样 | 避免锯齿与光晕 |
| 时域稳定 | mask 域 EMA + 与关键点多边形先验融合 | 分割逐帧会闪 |
| 嘴唇 | 外唇/内唇折线 → **centripetal Catmull–Rom 样条**平滑 → 光栅化为 R8 mask → **SDF（符号距离场）羽化** | 折线直接填充会有棱角 |
| 牙齿 | 内唇闭合多边形 ∩ **软颜色门控**（Oklab 低彩度、高亮度的 smoothstep） | 闭嘴时为空 |
| 巩膜 | 眼睑闭合多边形 − 虹膜椭圆（**Fitzgibbon 直接最小二乘椭圆拟合**，用 469–472 环点） | 眨眼时关闭 |
| 眉毛 | 上下缘链围成的多边形外扩 | 供擦除/分层 |

> 不要直接引入 BiSeNet + CelebAMask-HQ 权重并商用：数据集许可常限制非商用，见第 6 节。

## 4. 功能 → 技术实现（逐项）

约定：索引分组名见 `docs/12` 与 `code/Landmark478.swift`。
统一前置：**局部坐标系 `FaceFrame478`（原点=四眼角均值，x=33→263，尺度=外眼角距）**，位移用该尺度归一；所有几何功能都受 **姿态门控 × 眨眼/张嘴门控 × 丢脸门控 × 联合限幅 × 注入性保证**。
下表只写"技术"，限幅数值见 `docs/04–06`。

### 4.1 美肤（Photometric，源空间，位于 warp 之前）

| 功能 | 技术实现 | 关键参数/要点 |
|---|---|---|
| **磨皮** | **频率分离（Frequency Separation）**：低频=保边平滑，高频=原图−低频；输出=低频+α·高频。保边平滑用 **Guided Filter**（引导图=亮度或 G 通道，`MPSImageGuidedFilter` 或 box-filter 计算着色器）；在 **1/2–1/4 分辨率**计算，再用**联合双边上采样（Joint Bilateral Upsampling）**回原分辨率；半径∝脸宽；`eps` 随噪声估计（**Immerkær 噪声方差估计**）自适应；叠加**蓝噪声颗粒（blue-noise grain）**避免塑料感 | 皮肤 mask（人脸皮肤分割 ∩ 关键点多边形先验，排除眼/眉/唇/鼻孔/发丝）羽化；强度用 PCHIP 曲线 |
| **美白** | 解码到**线性光**，做曝光增益 + **单调三次 Hermite（PCHIP）色调曲线（1D LUT 纹理）**，**高光肩部（shoulder）压缩**防过曝；或在 **Oklab L** 上调；用 **ITA（Individual Typology Angle）** 估计肤色，曲线随肤色自适应；同步轻微色度补偿防发灰 | 仅作用于皮肤 mask；多肤色测试用 Fitzpatrick I–VI **与 Monk Skin Tone（10 级）** 两套 |
| **红润** | **OKLCH 色度（chroma）沿皮肤色相方向提升**（色相取 mask 内中值）；腮红用**各向异性高斯 splat**（锚点来自颧骨/颊部关键点）+ **Soft Light** 混合（W3C 合成公式） | 联合预算，防"醉酒脸"；不碰唇、眼 |
| **皮肤锐化** | 放在 warp 之后：**CAS（Contrast Adaptive Sharpening）** 或 **USM 作用于亮度通道 + coring（噪声门限）**；眼/眉/唇边缘权重更高 | 与磨皮强度联动，防互相抵消；限制 halo |

### 4.2 脸型（Geometry）

| 功能 | 技术实现 |
|---|---|
| **脸宽** | 轮廓弧长参数化 `u∈[0,1]`；沿**局部 x 轴向中线**的平移；权重 = **钟形 Hermite 曲线**（颧骨下–下颌角峰值，近耳 127/356 与近下巴 136/365 衰减）；R/L 用镜像对保证对称 |
| **小脸** | 以脸中心为枢轴的**相似缩放（uniform scaling）**；权重向外环 smoothstep 衰减到 0；与脸宽共享预算 |
| **V 脸** | 下颌线链**平移**（朝下巴顶点方向）+ 152 沿 y 轴**上提**；沿弧长 **Hermite 轮廓**；下颌角处限幅 |
| **面部流畅** | 轮廓折线上的 **曲率流 / Taubin 平滑**（先 λ 再 μ 防收缩），仅法向小位移；保护下颌角 |
| **太阳穴** | [经验点] **高斯 RBF 径向外凸**（法线方向），影响半径小；头发遮挡时按头发 mask 衰减 |
| **颧骨** | [经验点] **高斯 RBF 向内/后收**；与脸宽、下颌角共享位移预算 |
| **下颌角 / 下颌线** | 下颌角点**平移 + smoothstep**；下颌线**样条平滑**（Catmull–Rom 重参数化） |
| **下巴长短** | **局部缩放（Gustafsson local scaling）沿 y 轴**，以 152 为峰、高斯衰减；与下庭共享预算 |
| **尖下巴** | 148/176/152（及镜像）沿 x 轴向中线**平移** + 152 轻微下移 |
| **发际线** | 额头扩展点 + **头发分割 mask 衰减**的竖直平移；上移需要"露出皮肤"→**Push-Pull（Gortler 1996）金字塔填充**取低频，再**回注皮肤高频纹理**；下移不"长头发"，限幅小；刘海遮挡时禁用 |
| **去双下巴** | 颈部扩展点上提内收的网格形变 + **人像/颈部 mask**限定 + 俯仰角门控 |
| **去双下巴 Pro** | 在上面基础上做**颏下阴影衰减**：对颏下 ROI 做**低频亮度平坦化（Retinex 风格，用 Guided Filter 提低频）**，再 **Poisson/梯度域混合**回写；不依赖生成模型 |

### 4.3 整脸 / 3D 塑颜

| 功能 | 技术实现 |
|---|---|
| **对称** | 用变换矩阵把点**去姿态（de-pose）到规范空间**；按镜像对计算偏差，向对称解**凸组合**靠拢（上限 ~50%）；再**回姿态（re-pose）**投影 |
| **上下 / 左右 / 倾斜** | 规范空间中对五官点集做**刚体变换**（平移/旋转），外轮廓点由权重图跟随；再 re-pose。z 仅作相对量，**严格限幅** |
| **真 3D 塑颜** | 避免 BFM/FLAME（见第 6 节授权风险）。v1 用 MediaPipe 规范几何 + 变换矩阵做"准 3D"；真 3D 需自有 3D 人脸模型与数据 |

### 4.4 比例

| 功能 | 技术实现 |
|---|---|
| **三庭统一框架** | 沿面部 y 轴定义三个分界（发际线扩展点、眉间 9、鼻下点 2、下巴 152），做**单调分段线性/PCHIP 的 1D 重映射（piecewise monotone remap）**，再对每个器官施加**刚体平移（保持形状）**——只改"间距"，不压扁五官 |
| **中庭 / 人中 / 下庭** | 上述框架中调整对应分段的长度；人中联动上唇（0、37、267）；与下巴长短共享预算 |
| **短脸** | 全脸沿 y 轴**仿射缩放**，五官自身用反向补偿保持形状（feature-preserving，高质量档用 ARAP） |
| **额头 / 颅顶** | 额头扩展点 + **头发分割**；与发际线同一套填充策略 |
| **小头 / 头包脸** | **人像分割**限定头部区域的整体缩放，外环固定；缩小后露出的背景用 **Push-Pull/低频填充**；强烈建议后期功能，v1 不做 |

### 4.5 眼睛（以右眼 R 为例，L 镜像）

| 功能 | 技术实现 |
|---|---|
| **大小** | **径向局部缩放**（`dst = C + d·(1 + a(1−t²)²)`，`a<1.25` 保单调）作用于眼睑链及眼周顶点；`C` 取 33/133 与 159/145 的中点；**虹膜随网格重心坐标插值放大**，并用**眼睑开口 mask 裁剪**；blink 门控 |
| **眼距** | 眼簇的**相似变换平移**，外缘 smoothstep 衰减 |
| **上下** | 眼簇沿 y 轴平移；与眉眼间距**碰撞保护** |
| **眼尾上扬** | 以内眼角 133 为锚的**局部剪切（shear）**：外眼角沿 −y，权重沿眼睑链线性衰减 |
| **眼高** | 以眼中线为基准的 **y 方向非均匀缩放**，上下睑分别权重；blink 门控 |
| **长度** | 以眼中心为锚的 **x 方向缩放**，两端点权重最大 |
| **提肌** | 上睑中段（160/159/158）的 **Hermite 抬升曲线**；闭眼衰减 |
| **眼瞳大小** | **虹膜椭圆拟合（Fitzgibbon）** + 以 468 为中心的径向缩放，**半径受眼睑开口约束**，保证眼白可见 |
| **眼神矫正** | 478 点可估计视线偏移，但**重定向需要神经网络**（DeepWarp 类 / 3D 眼球模型）。v1 **不做**；作为可选插件（Core ML），自训或购买授权 |
| **眼睑下至** | 下睑中段的 **Hermite 下压** + 卧蚕高光（**Soft Light** 提亮层） |
| **倾斜** | 绕眼中心的**旋转（相似变换）**，左右镜像 |
| **内眼角 / 外眼角** | **锚点固定的仿射剪切**，邻点按链距离衰减；与眼尾上扬共享预算 |
| **对称** | 同 4.3，眼簇的 **Procrustes 镜像对齐** |
| **祛红血丝** | 巩膜 mask（眼睑多边形−虹膜椭圆）内，在 **Oklab 色度上抑制红向分量**，向**巩膜参考白（mask 内中值做 gray-world）**靠拢；排除睫毛 |
| **去脂（眼袋）** | ROI 由下睑折线做**偏移曲线（offset curve）**构造；**频率分离**后对低频做提亮与去彩（压青紫），高频保留；不依赖具体索引 |

### 4.6 眉毛（分层重合成）

核心：**把眉毛当作独立图层**。

1. 由上下缘链多边形（外扩）得到眉毛 mask。
2. **背景层** = **Push-Pull 金字塔填充 / Telea FMM 修补**得到的无眉皮肤，再回注皮肤高频。
3. **眉毛层** = 原图与背景层差异得到 alpha + 颜色（预乘）。
4. 对**眉毛层**施加几何变换，按 **Porter–Duff over** 合成回背景层。

| 功能 | 技术实现 |
|---|---|
| **上下 / 间距 / 眉头间距 / 倾斜** | 对眉毛层做**刚体/相似变换**；与眼睛**最小距离约束** |
| **粗细** | 沿**眉中心线法向偏移（offset curve）**，或 alpha 的**形态学膨胀/腐蚀**（高斯+阈值） |
| **长短** | 眉中心线的 **Catmull–Rom 弧长重参数化**；延长部分对纹理做 1D 拉伸并**渐隐（alpha ramp）**；缩短部分由背景层自然露出 |
| **眉峰** | 中心线上峰值控制点的编辑（Bezier/Catmull–Rom 控制点位移），与倾斜共享预算 |

### 4.7 鼻子

| 功能 | 技术实现 |
|---|---|
| **大小** | 以鼻中心为枢轴的**径向缩放（RBF 衰减）** |
| **鼻翼** | 鼻翼外轮廓链沿 **x 轴向中线平移**；权重沿链从鼻底 98/327（大）到 220/440（小）；**鼻孔保护项**（负权重 mask）保持鼻孔形状 |
| **鼻尖** | 1/4/5 的 **y 平移 + 小幅径向缩放**，联动人中 |
| **鼻梁 / 山根（立体感）** | 几何收窄 + **法线重光照（Normal-based relighting）**：用规范 3D 人脸网格法线，经姿态矩阵旋转，计算 **Lambert（N·L）+ 轻 Blinn-Phong** 得到明暗图，以 **Soft Light** 叠加；这是 2D 位移做不出"挺"的正确补法 |
| **提升** | 鼻部整体沿 −y 的刚体平移，人中联动 |

### 4.8 嘴唇与牙齿

| 功能 | 技术实现 |
|---|---|
| **大小 / 宽度** | 嘴中心为枢轴的径向缩放 / **x 向缩放**（嘴角锚点 61/291 单独权重）；张嘴门控 |
| **上下 / 左右 / 倾斜** | 嘴簇刚体变换；与人中/下庭共享预算 |
| **微笑** | 嘴角沿**斜上外**方向位移（弧形 Bezier 轨迹）+ 颊部提升（联动权重）；用 `mouthSmile*` blendshape 做强度调制，避免与自然表情叠加过度 |
| **M 唇** | 上外唇折线的**样条控制点编辑**：0 下压、37/267 上提、39/269 轻微外移 |
| **丰唇** | 唇折线的**法向偏移曲线（offset curve）**，**嘴角固定**；方向向外不盖牙 |
| **唇色** | **Oklab 色度替换**（保留 L），高光用 **Screen** 恢复；mask 为**样条平滑多边形 + SDF 羽化**；口红质感（哑光/滋润/金属）通过饱和度曲线与高光增益区分；先估计原唇色再映射，防过饱和 |
| **白牙** | 牙 mask（见 3.4）内 **降低 b\*/黄向色度 + L 小幅提升**，用 **ΔE（OK 空间）上限**防烤瓷；保留牙缝阴影（只改低频） |

## 6. 禁用/慎用清单（避免重复踩坑）

| 项 | 问题 | 替代 |
|---|---|---|
| **每帧 Delaunay** | 拓扑变化→闪烁，浪费性能 | 离线固定拓扑 |
| **全图 TPS / 逐像素 TPS** | 拉扯背景、开销大 | 权重图 + 网格；RBF 仅在顶点上 |
| **串联两次 warp** | 模糊累积、畸变放大 | 位移合成→单次渲染 |
| **欧氏距离权重** | 上下唇/上下睑互相泄漏 | 测地距离 + 区域分割 |
| **硬 mask 裁剪位移** | 轮廓外空出的区域无法补，出鬼影 | 外环衰减 + 锚点 |
| **用瞳距做尺度** | 视线变化导致抖动 | 外眼角距 |
| **在 gamma 空间做亮度/混合** | 偏色、过曝 | 线性光 / Oklab |
| **固定 alpha EMA** | 静止抖或转头拖影 | One Euro + 规范空间 |
| **直接读系统时钟算 dt** | 不可复现、触及隐私 API | 帧时间戳 |
| **BFM / FLAME 3DMM** | 常见授权限制商用（需单独商业授权），**务必核实** | MediaPipe 规范几何 + 变换矩阵；或自建 |
| **dlib 68 点预训练模型** | 训练数据（iBUG 300-W）限制商用，**核实** | MediaPipe 478 |
| **CelebAMask-HQ / 300-W / FFHQ 训练出的权重商用** | 数据集许可多为非商用/有附加条款 | 自采数据（知情同意）或购买授权；公开模型先查许可 |
| **InsightFace 等预训练权重** | 部分仅限研究 | 核实或换源 |
| **把 MediaPipe 链入核心** | 与宿主符号冲突 | 独立适配 target，协议注入 |
| **生成式/GAN 做形变** | 不可控、授权与延迟问题 | 几何 + 分层合成 |
| **CPU 回读像素** | 拖垮帧率 | 全程 GPU，输出走 `CVPixelBufferPool` |
