## 结论

1. 去脂的目标应是**上睑饱满外观的局部、可控减弱**，不能用一个亮度分数
   代表组织脂肪。必须先定义希望改变的可见结构和希望保留的睑缘、眼裂、
   睫毛与皮肤细节，再选择编辑器。通用美肤、去眼袋、去黑眼圈和增大眼睛
   都不能作为同一个效果的替代验收。
2. 同肤色物体属于**语义分割、遮挡识别与不确定性处理**。颜色守卫和脸框
   不能提供完整语义。可优先比较人脸解析与遮挡模型，结合有提示的分割；
   对含糊输入保留拒绝处理和显式蒙版。自动域须按类别、姿态和可见证据命名。
3. 本次查阅的一手资料中，未找到可直接移植、并已经证明满足本 SDK 上睑
   效果和保护标准的现成去脂实现。这是本次检索的结论，不是断言此类实现
   不存在。新方案仍需独立实验，论文演示不能代替本项目验收。
4. 预训练模型研究纳入范围；是否采用由许可证、可运行性和固定验收决定。
   不预设必须训练，也不继续把现有亮度代理调参当成已知可行路线。

## 两条建议路线（本项目推断，尚未验证）

### 皮肤、五官和遮挡保护

1. 先命名目标：仅处理选中人脸的可见皮肤，保护完整唇、眼、眉、发、背景、
   眼镜、手、口罩、贴片和麦克风等冻结类别。贴片须有可见边界/上下文。
2. 比较“解析 + 遮挡排除”与已获准的提示分割。每个候选必须保持正例皮肤
   的平滑/锐化方向，不能靠全图拒绝取得保护通过。
3. 候选皮肤区域与当前人脸支撑取交集；五官、遮挡、低可信边缘与 host 排除
   域取并集。如何置信度校准、边缘膨胀、原尺寸映射须在实验前冻结。
   上述组合也可能过度保护，不保证成功，须有皮肤覆盖率/有效性反证。
4. host 蒙版拥有更强的排除优先级，自动准入只能缩小编辑域，不能覆盖已知
   保护。原图最终硬合成保证保护域 RGB/alpha 源精确，羽化不能越界。
5. 完全相同的可观察输入却有相反材质标签，仍然不可同时保证。保留旧反例
   作为契约限制。若给点、框、蒙版或不同参考图，必须记录这是新增信息，
   不能把辅助路径算成无提示自动识别。

### 上睑外观

1. 正例、自然无目标负例、同结构不同光照/妆容的对照、睑缘/眼裂/睫毛保护
   先冻结。每个正例有独立目标外观或源定义结构，不能由生产分析器打分。
2. 第一分支比较受控局部目标与细节保持的多尺度修饰；第二分支仅在许可与
   可运行性通过后比较局部学习式修饰。**这些只是候选**，都有可能只改善
   色调却不能减弱目标饱满外观，此时判失败。
3. 普通眼/皮肤解析不是上睑饱满标签。ROI、目标外观、可信支持缺一不可；
   闭眼、重遮挡、浓妆或无法确定目标应原图退出。不能用眼高、提睑、移动眉
   或去黑眼圈冒充本控制的方向。
4. 若需要目标参考或局部提示，单列辅助路线和接口设计；它不能满足无提示
   自动需求，也不能直接塞进旧字段默认行为。生产接入前先通过候选门禁。
5. 真实组织量/三维脂肪测量不在目标；本项目要验证的是图像外观。自然风格
   生成肖像可作为独立效果证据，但校准色块或相同分析器残差不能替代外观。

## 验收与停止条件

- 两条路线各至多两种候选方法，每个候选最多两轮实现修复。改阈值、重选
  正例、缩减保护区或新增输入信息均视为契约变更，不能算原候选自动通过。
- 先冻结开发与留出输入、效果下限、保护容差、适用范围、拒绝率/覆盖下限、
  元数据和资源限额，再实现。留出输入不得被候选选择反复使用。
- 皮肤方向沿用适用原源的 20% 平滑变化降低 / 10% 锐化增加；新视觉域须
  单独预先校准，不强行套用这些数值。对象/完整五官保护与有效皮肤变化
  同时通过；只报告 IoU、变化像素数或跑通脚本不足以完成。
- 上睑须证明期望外观变化、目标无恶化、纹理保留、无环纹/色带/暗槽、
  不改变眼裂及身份相关保护；旧自然挑战结果保持历史身份，另报新快照。
- CPU 与实际执行 Metal-selected 路径分开计数；后者仍可能运行共享 CPU
  纹理阶段，不能把配置枚举或宿主 GPU 速度当成纯 GPU/设备证明。
- 到预算后若无候选通过，停止该分支并记录失败、缺少的信息或资源，继续
  可独立完成的工程项。默认隐藏和显式蒙版作为安全现状保留；**不得把失败
  处置、文档改写或辅助成功写成两个自动效果都已修复**。里程碑仍不能按原
  完整目标关闭，须由所有者决定新方案或明确调整范围。
