# v1.25 R3：两个长期问题的有限执行与终局处置

2026-10-03，依据所有者最新要求：连续自动执行，聚焦去脂和同肤色物体识别，
参考行业方法，从最简单开始，到确实无法继续的边界停止，并在本里程碑结清。
本文件调整**执行与关闭规则**，不降低任何已冻结的效果、保护或兼容阈值。
[R2数值契约](RETOUCH_MVP_REQUIREMENTS.md)、原失败和留出集保持只读。

## 执行顺序与边界

1. 复核一手行业资料，区分无提示自动、模型预测、人工/宿主提示三个输入条件。
   不为使用开源而下载无关模型，不把人工蒙版算自动识别。
2. SEG已有两个方法四个版本的真实失败，保持原预算耗尽；不再追加第五个阈值
   版本。复核现成方法能否直接提供所缺语义，再做最终能力处置。
3. EYE延续已获准的小规模诊断例外，先在原有独立参考和负例上补齐剩余最简单
   候选，最多E1-v2、E2-v1、E2-v2三次。它们连同E1-v1仍是原2×2预算，
   不读取正式留出、不改旧输入/数字、不改变SDK生产。先运行正确/错误控制，
   再执行事先登记的候选；不能为做满流程先大量生产30份参考。
4. 某候选小预检通过才值得准备完整EYE G0，之后仍须R2的G1–G3才能交付。
   若剩余候选连该简单诊断也未联合通过，立即终止自动效果分支，不再排下一轮。
   输入/构建错误单列，只修基础设施；不能用运行错误下算法无效结论。
5. 最后核对现有可用能力、默认隐藏与兼容，并实际运行archive-first全量门禁。
   只做必要的处置/契约同步，不扩展批量工具、UI、训练或模型转换项目。

## 终局定义

此处的“结清”允许两种真实结果：

- **交付**：新自动能力通过完整原验收，记录确切适用范围。
- **关闭且未交付**：本轮可行路线失败或已到明确资源/信息边界，保留已证明能力，
  对失败自动目标停止研发、隐藏/不新增入口、取消本轮尚未执行的后续集成任务。
  记录为 `closed_with_unmet_objectives`，绝不写为两功能已实现或16/16通过。

新要求替代R2“功能不成功就始终保持里程碑active”的行政约束；没有替代效果
资格标准。能力缺口仍公开记录，但不再是自动续跑队列或下个里程碑的默认blocker。
以后只有所有者明确提出新输入条件、新方法/资源和新验收范围才重开；一般
“继续”不得复活被关闭的实验、重置预算或重复已有失败。

当前生产去脂仍suspended，旧字段零值/Codable/显式调用兼容不变。主机提供的
物体+完整唇区保护持续可用，仅代表辅助保护。两个自动目标的结果分别报告。
