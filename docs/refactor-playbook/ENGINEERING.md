# 工程、验收与候选迁移顺序

[返回入口](README.md)。本章是设计建议，不是已批准的里程碑或发布清单。

## 在现有 target 中放什么

| 当前 target | 当前责任 | 重构时适合承载的内容 |
| --- | --- | --- |
| BeautyCore | 参数、配置、错误、metadata、结果与canonical carrier。 | 经明确授权的新值模型；保持框架/检测器细节不进入public。 |
| BeautyDetection | Vision/MediaPipe、坐标桥接、验证后的请求内支撑。 | 区域适配、检测版本准入；未来时序机制需独立契约。 |
| BeautyEffects | 参数解析、规则、冲突、局部处理与合成。 | 位移规则/效果预算与保护策略，独立于具体renderer。 |
| BeautyRender | backend、Metal资源和执行。 | 将验证后的计划光栅化/采样；新mesh API/backend须另计划。 |
| BeautyResources | 预设、滤镜、LUT等受控资源。 | 若新增拓扑资源，先决定唯一owner、版本与哈希验证。 |
| BeautySDK | 公开入口、路由和生命周期。 | 统一输入/typed failure/neutral/输出契约，不承载相机或编辑UI。 |

可把 `LandmarkPreprocessor`、`FoldoverGuard` 等名称作为责任描述，
不急于创建新target或额外管理层。CPU参考可继续作为可重复oracle；手册的
“禁止CPU warp/回读”针对实时成本，不覆盖当前有意保留的参考与像素验收路线。

## 管线顺序由坐标所有权决定

推荐先画清每层输入：原始源、canonical源、已着色源、几何目标与最终输出。
源空间mask作用于源图，若先warp再处理mask，则mask也须一致warp到目标；
因此原手册P1/P2→warp→锐化是一种便于对齐的候选，不是所有算法不可改变的顺序。
局部单位从同一不可变源独立提出，碰撞回源、精确保护和原尺寸输出应优先保住。
现有source-raster特殊形变不能未经验证删除或合并。

建议新管线分清两个阶段：**计划阶段**完成准入/状态/预算/有效性，
**执行阶段**进行受控像素与几何操作，再完成后处理/输出。
普通调用的观察是同步请求内的，所有参数按请求快照；同一个engine仍由caller串行使用。
native detector的锁不代表整个engine可并行调用。

2026-10-10的[固定图片编辑入口](../sdk/PREPARED_PHOTO_EDITING.md)将“一次固定输入、多次
参数快照”的资源复用用于实际Demo：显式深拷贝单个source，按用途/检测raster复用
usable/noFace，失败重试，换图/release/reset清除。它不复用编辑结果，也不复用视频旧帧。
每次网格、source准入、局部合成和mask仍按现有规则执行；原尺寸导出仍fresh检测。

本次另行授权的playbook重构已在既有target内抽取请求内
[共同静图geometry stage](../../BeautySDK/Sources/BeautyEffects/Render/BeautyStillImageGeometryStage.swift)，
供CPU与Metal executor复用source修整/准入、最终点和后置平移。它保留每条路线原来的
阶段raster与着色顺序，没有把所有source-raster效果错误地改成单次普通warp。
范围和验证见[执行记录](../../plans/history/2026-10/A-2026-10-09-playbook-sdk-refactor.md)。

## 性能预算怎样成为证据

手册1080p/30fps、推理8ms、3帧in-flight和30%余量均是起点。
若未来目标是30fps，33.3ms是帧周期，但推理/GPU/CPU流水可以重叠；
吞吐、端到端延迟、结果年龄和展示延迟要分别测，不能仅相加平均pass耗时。

| 度量 | 实验记录应包含 |
| --- | --- |
| 时延/吞吐 | 输入格式、分辨率、脸数、参数组合、backend、预热、持续时间；P50/P95/P99、掉帧与结果年龄。 |
| GPU | command提交到完成、同步等待、CPU准备与复制；保留依赖/lifetime直至完成。 |
| 内存 | 同时活跃的像素/纹理/模型/缓冲总量及临时峰值，区分估算与实测。 |
| 热与耗电 | 真实设备型号/系统、环境/持续时间；模拟器不授予对应设备声明。 |
| 降级 | 明确哪些功能关闭/缩小、什么事件触发、迟滞与恢复；不能静默减参。 |

预创建pipeline、复用纹理、像素buffer纹理映射和有限in-flight值得评估；
并非一定需要MTLHeap或固定三缓冲。更深的队列可能增加延迟，须按测量选容量。
`CVMetalTextureCache` 不等于端到端零拷贝：当前MediaPipe有CPU raster转换，
当前纹理与局部合成也在CPU；须分别核查每次格式/方向/颜色转换。

当前输入像素上限50,000,000，active texture上限8,388,608；
三个RGBA8 raster上界96MiB仅是该stage预算，不是进程峰值。
RGBA16F每像素8字节，1920×1080单纹理约15.8MiB，多pass/in-flight要累加。
限额若变化须先证明checked arithmetic、峰值和typed failure。
照片超预算也要拒绝/有界处理，不能沿用“照片不降级、随便慢”的说法。
当前误差与资源契约见 [RELIABILITY](../../RELIABILITY.md)。

## 验收矩阵

遵循 [图片效果验收政策](../validation/IMAGE_EFFECT_ACCEPTANCE.md)，在候选输出前固定目标、
保护区、负例、强度与容差。生成肖像和代码生成几何图都可提供有效输入；
图像来源不降低资格，但覆盖的输入范围必须写清。
下表是按风险选择用例的索引；每次只验证本次改动及直接依赖的最小充分子集。
公共模块影响扩散时按具体调用路径扩大，不自动重跑全 SDK、全部功能或设备/字体/方向矩阵。

| 层 | 最小有意义的检查 | 不可由它替代的结论 |
| --- | --- | --- |
| 输入/坐标 | 八方向×镜像、非零extent、长宽比、检测缩放、尺寸/色彩/alpha、typed recovery。 | 一般识别精度。 |
| 支撑 | 有序语义路径、无效单脸/可选姿态、无脸/恢复；授权输入的区域正负例。 | 478点即准确、匿名置信marker即概率。 |
| 几何 | 源/目标有效、边界/覆盖、近退化、各字段signed极值、组合、圆环/直线/脉冲图。 | 只凭“三角翻转数为0”宣称自然。 |
| 效果 | 目标方向/有意义变化、负例不恶化、源定义保护、neutral、重复、元数据和公开SDK路径。 | 变化像素计数、函数返回成功或只有SSIM/PSNR。 |
| 组合 | 同源独立mask、碰撞回源、着色/纹理/几何顺序、CPU/Metal各自范围与容差。 | 单项通过即叠加通过。 |
| 时域（若新增） | 静止、阶跃、匀速、快转头、表情、丢帧/丢脸/换人/重置；滤波前后残差与滞后。 | 两张图片或同图重复就证明视频稳定。 |
| 成本（若声明） | 指定目标环境端到端、峰值、持续行为；失败/降级分支也测。 | 单次模拟器推理时间即真机30fps。 |

金图用于回归而非效果真值；变化可能是合理改进，也可能是偏移。
时域相邻帧差分应先扣除/配准真实运动，否则会惩罚正常转头。
抖动像素阈值要随输出尺寸或脸尺度定义，不能照抄1080p的0.3px。
颜色测试按源图可观测肤色、明度、色度和光照分层；
原手册的I–VI标签不单独代替这些图像覆盖或人口泛化证据。

调试图和原始点/mask只在受控请求或临时验证环境使用；聚合回执可持久化，
raw像素/几何/私有路径不进入仓库证据。标准 SDK 结果只有固定事件和聚合指标；
已有所有者 `OwnerDiagnostics` SPI 可给本地 overlay 提供瞬时正向 x/y，详见
[坐标与诊断边界](LANDMARKS.md#统一空间明确边界)。该已授权入口不允许持久点位、
日志上传或扩大结果 payload，也不因手册建议新增 `os_signpost` 数据路径。
资源升级依据 [SECURITY](../../SECURITY.md) 的实际用途/版本/哈希/许可核实，
本文不提供法律适用、App Store发布或数据集商业许可结论。

## 已实施基线与后续候选

静图首批改造和组合修复已经实施，证据分别在[静图记录](../../plans/history/2026-10/A-2026-10-09-dense-face-refactor.md)
与[组合记录](../../plans/history/2026-10/A-2026-10-09-combination-ui.md)。下表区分当前实现和后续候选；
候选须有明确范围及独立 Active 计划，不自动从手册 M0 相机/UI 开始，也不沿用团队周数估计。

| 范围 | 已实施基线 | 后续候选与所需证据 |
| --- | --- | --- |
| 契约/导航 | 当前 API/default、输入输出、provider、资源/失败 owner 与分类索引已经建立。 | 新责任提取须保持已有像素/失败契约，按直接依赖验证；当前授权见 PLANS。 |
| 静图几何 | 固定全画布逆网格、位移/梯度/姿态限制及 dense mapped 独立字段已实施。 | 语义脸面 mesh、TPS、GPU 原生网格仍需独立覆盖、组合与 CPU 像素 oracle。 |
| 美肤 | 有界双边低频、独立平滑/增强、几何与 host 保护及 context 复用已实施。 | 脸尺度/多尺度、引导上采样与更广外观域尚未交付，须证明方向、颜色/边缘及保护。 |
| 五官 | 已使用实测鼻/唇/轮廓、可见虹膜和区域准入；各字段限定域按 taxonomy 使用。 | 新联动、纹理补全或扩大适用域逐字段/组合验收，不自动提升全表。 |
| 可选视频 | indexed 跳帧不复用观测；当前检测为 CPU image mode，没有视频跟踪/滤波交付。 | 时间戳/身份/过期、跟踪、滤波与队列需要序列正确性；设备性能另测。 |

一般语义解析、3D建模、去脂与已关闭SEG不是上述步骤的默认依赖。
旧失效文档可在明确整理任务中删改；归档、冻结证据与现行契约先识别owner再处理。
实现变更按 [QUALITY_SCORE](../../QUALITY_SCORE.md) 运行最窄有效检查和所需完整门禁；
最初文档阅读没有重跑SwiftPM；本次单独授权的静图实现按[完成记录](../../plans/history/2026-10/A-2026-10-09-dense-face-refactor.md)执行新验证，不重签此前历史检查点。
