## 需要修正的关键说法

| 原材料说法 | 项目里的准确理解 |
| --- | --- |
| MediaPipe 478 + 姿态足以准3D/高阶功能 | 提供支撑，不提供分割、组织/眼球形态或可泛化的3D美颜证据。 |
| Vision固定76点 | 原表属于粗略选型描述；当前SDK不把不同系统/请求修订的点数固定为76。 |
| 内部一律未镜像像素坐标 | 当前为输入方向/镜像校正后的归一化图像坐标；可在距离计算时显式换像素。 |
| 网格天然无空洞 | 是输出查询方式；仍需完整有效覆盖、无退化/重叠和正确边界。 |
| 删除坏三角 | 会留洞；修复点位/剖分并重新检查，不只跳过三角。 |
| TPS必须λ>0且只解K | 完整TPS含仿射项/约束；λ可以为零，正则不能代替几何可解条件。 |
| 每帧二分就是最大无折叠强度 | 需安全区间前提与最终验证；源退化/NaN和非单调路径另处理。 |
| 低置信度复用旧点渐隐 | 当前拒绝坏支撑、不借旧点；视频渐隐要有可靠时序/跟踪和明确过期规则。 |
| 眉移动必须先擦除再warp | 连续warp与搬移不同；抹掉warp的采样源会丢内容，需明确独立层。 |
| Lab或线性空间即可保证自然色 | 还需转换、色域、alpha、曝光与组合测试；浮点纹理本身不决定色彩空间。 |
| CPU warp / 回读一律禁止 | 是实时优化建议；当前CPU参考、局部合成与像素oracle有意保留。 |
| 白牙内唇亮色阈值、去脂下睑提亮 | 候选像素代理，不能自动宣称语义/组织效果；去脂目标也与现有上睑字段不同。 |
| 非零自然默认、真机30分钟及第三方集成门禁 | 与当前neutral默认、生成图验收及owner-local SDK边界不同，不直接采用。 |

公式和事实依据随正文就近引用；新增阈值/性能/人群/视觉结论必须有相应实测。
技术推导在正文显式标为推导，静态代码问题在下表显式标为审阅发现。

## 四份代码骨架的静态发现

| 文件 | 值得理解的部分 | 集成前缺口 |
| --- | --- | --- |
| `OneEuroFilter.swift` | 自适应截止频率；局部相似变换/残差。 | 有限输入/参数与dt验证；空集、退化相似变换、乱序/重复/长间隔、原子状态提交、每脸身份生命周期。 |
| `DisplacementSolver.swift` | 单功能位移、总位移预算与降强度。 | 数组/索引/有限值/正半径准入；源面积为0被跳过；NaN可能绕过比较；默认t=0安全；二分单调性未证明；TPS尚未实现。 |
| `MeshWarp.metal` | 目标位置 + 源UV的采样方式。 | 缺host的pipeline/索引/资源与同步实现；保护混合可能重影；磨皮示意处理half4，需单独保alpha；工作空间及全纹理尺寸未定义。 |
| `gen_topology.py` | 标准脸上一次生成拓扑、固定索引。 | 仅68点粗示意且语义顺序未验证；无眼唇约束/加密点；clip可能重合；删除小面积三角留洞；coverage只打印总面积/朝向，不会据此拒绝；header格式需对应reader。 |

脚本的边界顶点用 `W−1/H−1`，coverage却除以 `W·H`，本身也混合了像素中心和画布面积。
外环实现按中心径向外扩，不能保证是轮廓法线。必须先形成精确坐标/资源规范再实现。
这些发现不是“已复现崩溃”或真机失败；它们说明骨架没有完成生产准入与验证。
