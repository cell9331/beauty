## Trust Boundaries

| Boundary | Description |
| --- | --- |
| Request-local face observation → control-point payload | Validated internal geometry becomes bounded GPU input. |
| Control-point payload → geometry shader | Provider values cross into interpolation and sampling math. |
| Composed canonical carrier → geometry pass | Source-owned local-retouch bytes remain the immutable request input. |
| Metal output → backend result | GPU bytes and bounded aggregates are validated before publication. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-72-05 | Tampering | Face support/control-point serialization | mitigate | Reuse `BeautyFaceGeometryAdapter` and the unified provider pipeline; reject non-finite/out-of-range points and enforce one bounded payload inventory. |
| T-72-06 | Denial of Service | Warp dispatch/interpolation | mitigate | Validate point count, radius/falloff, dimensions, sample coordinates, finite math, clamp, bounded threadgroups, and cleanup before publication. |
| T-72-07 | Information Disclosure | Geometry diagnostics and source carrier | mitigate | Keep points and canonical bytes request-local; publish only existing aggregate diagnostics and run privacy/static mutations. |
| T-72-08 | Fail-open/Tampering | No-face, collision, and degraded support | mitigate | Omit ineligible geometry passes, preserve face-agnostic siblings, consume composition-owned source bytes, and assert no synthetic support/collision generation. |
| T-72-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installation or dependency change is part of this plan. |
