<interfaces>
`BeautyBackendRequest` already carries the validated normalized
`BeautyEffectPlan`, optional selected face observation, canonical still-image
carrier, and bounded local-retouch summary. `BeautyMetalBackend` currently
bridges BGRA or canonical RGBA8 bytes to one identity `BeautyMetalRuntime`
transaction. `BeautyMetalRuntime` owns device/queue/pipeline setup and all
request resource cleanup; it must remain package-internal and must retain the
existing dependency seams and terminal error behavior.

Define `BeautyMetalPass` and its color/warp/composed-retouch payloads in
`BeautyRender` using finite, bounded Swift value types. The runtime should
encode an ordered pass list in one command transaction using private texture
ping-pong and one final readback. The backend maps current CPU coefficients and
filter IDs into the color payload, converts BGRA to RGBA before Metal and back
afterward, and keeps all support/composition ownership outside the runtime.
</interfaces>

| Boundary | Description |
| --- | --- |
| `BeautyEffectPlan`/request-local support → pass payload | Validated package values become Metal uniform/control data. |
