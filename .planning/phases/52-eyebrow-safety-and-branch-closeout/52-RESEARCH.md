## Common Pitfalls

### Pitfall 1: A “comment-only” cap freeze that leaves duplicated authority

**What goes wrong:** `BeautySafetyCaps` says final while `EyebrowWarpProvider` still divides and validates against a separate `provisionalCap` literal. [VERIFIED: codebase grep]  
**Why it happens:** the values are currently both `0.25`, so tests that check only output do not detect ownership drift. [VERIFIED: codebase grep]  
**How to avoid:** drive provider formulas and maximum acceptance from the seven final cap constants and add exact-cap / next-above-cap provider assertions. [VERIFIED: `52-CONTEXT.md`]  
**Warning signs:** the word `provisional` remains in active eyebrow source, or a provider maximum changes without a `BeautySafetyCaps` test failure. [VERIFIED: archived checker pattern]

### Pitfall 2: Incomplete dead-zone semantics

**What goes wrong:** zero is tested, but `±Float.ulpOfOne`, the first representable magnitude above it, negative peak, NaN, and infinities are not separated. [VERIFIED: current test grep]  
**Why it happens:** existing representative tests mostly use `0.2`, `0.25`, or `1`. [VERIFIED: current test grep]  
**How to avoid:** assert exact provider emptiness at `-ulp`, `0`, and `+ulp`; then separately prove eligible direction above the dead zone where the displacement also clears the provider's `0.000001` geometric epsilon. [VERIFIED: `EyebrowWarpProvider.swift`; `52-CONTEXT.md`]  
**Warning signs:** a tiny request creates an active domain with no points, or a provider-empty tiny value remains in totals/metrics. [VERIFIED: codebase behavior contract]

### Pitfall 3: One missing side suppresses all eyebrow work

**What goes wrong:** pair-only spacing failure is treated as a domain-wide failure. [VERIFIED: existing field-local tests show this would be incorrect]  
**Why it happens:** the public facade exposes one `.eyebrows` domain even though eligibility is per named field and often per side. [VERIFIED: codebase grep]  
**How to avoid:** the descriptor matrix must state the narrowest missing/malformed fixture per field and compare effective values with named emissions. [VERIFIED: `52-CONTEXT.md`]  
**Warning signs:** a left-only fixture zeros vertical, thickness, length, head spacing, tilt, or eligible peak work. [VERIFIED: existing tests]

### Pitfall 4: Reused scaling occurs before/after conflict more than once

**What goes wrong:** `.125` becomes `.0625`, or the conflict loop evolves from already-scaled values and changes the final reciprocal evidence. [VERIFIED: locked risk in `52-CONTEXT.md`]  
**Why it happens:** both freshness scaling and conflict scaling touch the same effective structure. [VERIFIED: codebase grep]  
**How to avoid:** assert all seven reused strengths from the unconflicted descriptor fixture, then add a reused mixed-domain convergence case proving one `reusedGeometryScale = 0.5` plus one shared conflict scale. [VERIFIED: `52-CONTEXT.md`]  
**Warning signs:** repeated calls differ, signs flip, or the retained total is calculated from scaled rather than capped values. [VERIFIED: existing convergence contract]

### Pitfall 5: The 44-row arithmetic test passes while dispatch disagrees

**What goes wrong:** a field participates in conflict metrics but emits no points, or emits twice in the pipeline. [VERIFIED: locked risk in `52-CONTEXT.md`]  
**Why it happens:** arithmetic, sanitization, and dispatch are separate code paths. [VERIFIED: codebase grep]  
**How to avoid:** build all final provider arrays from `plan.effectiveStrengths`, sanitize a copy, compare it exactly with the plan, concatenate arrays in stable order, and compare exact pipeline points and geometry point count. [VERIFIED: current `CombinedEffectSafetyTests`]  
**Warning signs:** active domains omit `.eyebrows`, `geometryPointCount` differs, or pipeline equality needs sorting. [VERIFIED: existing test contract]

### Pitfall 6: Checker reports clean on a tool failure

**What goes wrong:** `rg`/Git/path errors are interpreted as “no match.” [VERIFIED: archived checker threat registers]  
**Why it happens:** grep-style tools use exit `1` for clean no-match and values above `1` for errors. [VERIFIED: archived checker source]  
**How to avoid:** retain explicit `0/1/>1` classification, validated repository-relative no-symlink paths, and one mutation self-test per failure branch. [VERIFIED: archived Phase 44/48 checker source]  
**Warning signs:** an unavailable executable, missing file, or repository escape still produces checker success. [VERIFIED: archived checker source]

### Pitfall 7: Owner synchronization changes the scope claim

**What goes wrong:** “implemented” is read as Demo/device/commercial/release readiness, or later v1.14-v1.16 rows become implicitly covered. [VERIFIED: `52-CONTEXT.md`]  
**Why it happens:** branch status is shorter than the supporting scope statement. [VERIFIED: existing blueprint patterns]  
**How to avoid:** every promoted owner must say SDK-core scope and repeat the explicit nonclaims; Phase 52's checker must reject release/audit/archive success language. [VERIFIED: archived Phase 48 checker]  
**Warning signs:** a root owner says launch-ready, the Demo gains eyebrow controls/imports, or the milestone is marked audited before the independent workflow. [VERIFIED: `52-CONTEXT.md`]
