# Plan 05-02: Add Facade Resource APIs and No-Op Color/Filter Contracts

## Phase Goal

**As a** host app developer, **I want to** access built-in filters and presets through the public facade, **so that** Demo and host code can validate resources without importing internal SDK targets.

<objective>
Expose the Phase 5 resource catalog safely through `BeautySDK` and lock the no-op visual contract for color/filter parameters.

Purpose: EFFECT-02 needs color parameters to flow through SDK-backed snapshots; EFFECT-03 and EFFECT-08 need public facade APIs for available filters, built-in presets, and strict resource validation.
Output: A host-facing resource facade, facade compile tests, color/filter parameter validation tests, and no-op engine compatibility tests.
</objective>

## Trust Boundaries

| Boundary | Description |
| --- | --- |
| `BeautyResources` internals -> public `BeautySDK` facade | Resource internals must not leak into Demo or host imports. |
| Host-supplied `BeautyParameters.filterId` -> resource validation | Unknown IDs are untrusted resource references and must be rejected by resource validation. |
| Color/filter parameters -> engine output | Phase 5 must not claim visual rendering that is not implemented. |

</threat_model>
