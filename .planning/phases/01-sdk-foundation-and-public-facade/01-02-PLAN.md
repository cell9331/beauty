# Plan 01-02: Implement Public Value Models, Defaults, Validation, and Preset Decoding

<objective>
Implement the public value-model layer required by the facade: configuration, 31-field parameters, presets, results, errors, validation warnings, and tests proving defaults, clamping, Codable behavior, and typed validation failures.
</objective>

<user_story>
As a host app developer, I want to construct and validate SDK model values from `BeautySDK`, so that I can prepare parameters and presets before calling the engine.
</user_story>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| Non-finite numbers reach rendering | high | Centralize finite checks and test `.nan`, `.infinity`, and `-.infinity`. |
| Preset JSON executes or triggers unknown behavior | high | Ignore unknown fields and never interpret JSON as code or file paths. |
| Unknown resource IDs partially apply presets | medium | Reject preset validation with typed error and test `filterId: "missing"`. |
| Public errors leak sensitive data | medium | Keep associated values short and redacted; test error strings do not include raw JSON or paths. |
</threat_model>
