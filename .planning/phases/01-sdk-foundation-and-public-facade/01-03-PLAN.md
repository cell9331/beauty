# Plan 01-03: Implement No-op BeautyEngine Process and Typed Errors

<objective>
Implement the no-op processing foundation: `BeautyEngine` initialization, explicit-parameter `process(...)` overloads, SDK-created outputs for supported inputs, idempotent `reset()`, render/copy primitives, and typed error behavior.
</objective>

<user_story>
As a host app developer, I want to run a no-op frame or image through `BeautyEngine`, so that I can integrate the SDK before visual effects exist.
</user_story>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| No-op success returns caller-owned input | high | Tests assert output object is not the same pixel buffer reference where applicable. |
| Unsupported pixel formats proceed into undefined rendering | high | Validate pixel format and dimensions before copy/output work. |
| Release path uses crash shortcuts | high | Static scan rejects `fatalError`, `try!`, and forced casts in SDK sources. |
| Diagnostics leak image metadata or paths | medium | Typed error messages stay short and redacted. |
</threat_model>
