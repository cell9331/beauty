# Phase 64 Research — Sclera Output, Adversarial Safety, and Independent Closeout

## Summary

Phase 63 already owns the runtime algorithm and passed actual native Vision on
the authorized pair. Phase 64 should not tune it by default. The smallest safe
delta is one public renderer case, a sclera-specific strict decoder/private
runner adapted from Phase 61, two deterministic closeout oracles, a fresh
original-detail review, and an atomic single-row product promotion.

The renderer already supports `--no-watermark`, so baseline and active outputs
can be compared exactly without adding a presentation bypass. The reviewed mask
is evaluation-only and is loaded only after public-facade rendering.

## Output Architecture

Append `scleraRednessReduction_1p00` beside the existing teeth case with only
`BeautyParameters(scleraRednessReduction: 1)`. Advance exact inventory from 73
to 74 and narrow only obsolete pre-output absence assertions. Keep the one
public processing loop and all existing case IDs unchanged.

The private runner discovers the one ignored Phase 62 sclera bundle through its
existing fixed-output authority, stages only two originals plus the no-face
control under opaque regular names, renders baseline and active cases, then
invokes a bounded standard-library decoder. Exact output count is six.

The decoder reuses Phase 61's no-follow/CRC/chunk/decompression/dimension/alpha
controls and applies the frozen criteria from `64-AI-SPEC.md`. Reviewed masks
may be split into image-left/image-right aggregate regions to prove at least one
positive eye materially improves; no raw split or metric is serialized.

## Adversarial Oracles

Add `BeautyScleraRednessAdversarialCloseoutTests` beside provider tests.

1. Construct independent protected-coordinate truth, then vary valid contours
   and pupil positions/sizes within the provider's accepted support envelope.
   Recoloring is irrelevant to this oracle: emitted proposals must never claim
   protected truth.
2. Recolor protected truth to bright, low-saturation, red-excess values likely
   to pass the score, execute the real provider and composition owner, and
   compare final RGBA. Iris, pupil, highlights, lash/margin, skin and exterior
   remain exact.
3. Re-run one-eye invalid, valid-invalid-valid and parallel request patterns to
   show local recovery and no stale support.

If an oracle finds a defect, production protection may be strengthened but not
relaxed. Any source correction triggers all Phase 63 private/focused gates and a
fresh Phase 64 output/review run.

## Promotion Transaction

Use a fail-closed checker with default and `--allow-promotion` modes. Default
requires the exact eye ledger row to remain future. After every gate passes,
change only `祛红血丝` to implemented across the canonical ledger/detail owners;
all aggregate owners keep `眼睛 = partial` and identify only `去脂` as future.
A separate post-promotion run is mandatory before routing to Phase 65.

## No New Unknowns

No dependency, model, API field, detector seam, renderer bypass or new fixture
is required. The main risk is false containment from protected native colors,
which is exactly why both color-independent and recolored final-output oracles
are mandatory and cannot be substituted by the genuine pair.
