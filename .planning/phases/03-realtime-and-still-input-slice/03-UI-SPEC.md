## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Badge vertical padding, tight inline spacing |
| sm | 8pt | Mode header gaps, category rail gaps, subcategory gaps, status row gaps |
| md | 16pt | Screen padding, shell vertical spacing, panel padding, preview internal spacing |
| lg | 24pt | Preview text horizontal padding, large preview text separation |
| xl | 32pt | Reserved for future larger editor group gaps; do not introduce unless layout needs it |
| 2xl | 48pt | Reserved for major empty-state separation |
| 3xl | 64pt | Reserved for full-screen section separation; avoid in Phase 3 compact editor shell |

Exceptions: iOS touch targets use a 44pt minimum height for mode buttons, category pills, subcategory pills, compare controls, Settings, retry, and reset actions. Existing cards keep 8pt corner radius. Preview region keeps a 320pt minimum height so loading, permission, unavailable, and image states do not collapse.

## Typography

Use exactly these sizes and only the regular and semibold weights in Phase 3 UI work.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16pt | regular 400 | 1.5 |
| Label | 13pt | regular 400 | 1.3 |
| Heading | 20pt | semibold 600 | 1.2 |
| Display | 28pt | semibold 600 | 1.2 |

Usage rules:

- `Display` is only for the preview-area empty or unavailable heading.
- `Heading` is for the active panel title and compact state headings.
- `Body` is for preview explanations and primary row labels.
- `Label` is for badges, values, range endpoints, secondary status text, and compact actions.

Accent reserved for: selected Camera or Photo mode, selected bottom category, selected Facial Features subcategory, active before/after compare segment, slider tint, non-blocking status dot, `Open Settings`, and `Try Again`. Do not use accent for every interactive element.

Supporting neutrals:

- Disabled text: `#8A8F98`.
- Disabled surface: `#EEF0F3`.
- Accent wash: `#EEF3FF`.
- Preview shadow: black at 6% opacity, radius 12pt, y 4pt.

Additional state copy:

| State | Required Copy |
|-------|---------------|

| Photo mode entry | Photo |
| Camera permission preview heading | Camera access needed |
| Camera permission preview body | Allow camera access to preview processing on this device. Photo mode is still available. |
| Camera Settings action | Open Settings |
| Camera unavailable heading | Camera unavailable |
| Camera unavailable body | Live preview cannot start on this device. Use Photo mode to continue testing the SDK path. |
| Camera retry action | Try Again |
| Photo empty heading | Choose a photo |
| Photo empty body | Select an image to process locally through BeautySDK. |
| Photo picker action | Choose Photo |
| Photo loading text | Processing photo... |

## Visual Contract

Phase 3 must feel like the existing editor becoming live, not a new flow.

| Area | Contract |
|------|----------|
| First screen | Keep `EditorShellView` as the first screen. Do not launch directly into Camera and do not request camera permission on launch. |
| Top mode row | Camera and Photo entries stay at the top and become enabled mode switches. Selected mode uses accent fill or accent border with selected accessibility trait. |
| Preview area | The existing white rounded preview card remains the single surface for fixture, live camera, chosen photo, loading overlay, permission, unavailable, and error states. |
| Bottom controls | Keep the bottom category rail and parameter panel visible in Camera and Photo modes. Mode changes must not reset category, subcategory, or parameters. |
| Loading | Overlay loading on top of the previous photo or fixture. Do not blank the preview during processing. |
| Error/status | Use a lightweight banner or status row inside the preview/card area. Preserve the last usable visual state whenever possible. |
| Disabled/future controls | Continue the existing badge and secondary reason pattern for controls outside Phase 3 scope. |
| Imagery | Use real camera preview for Camera mode, selected user image for Photo mode, and deterministic fixtures for previews/tests. Do not use abstract decorative artwork for inspectable image states. |

## Interaction Contract

| Interaction | Contract |
|-------------|----------|
| Camera tap | Select Camera, then request camera permission only if authorization is `notDetermined`. |
| Camera denied/restricted | Keep Camera selected, keep shell controls visible, show permission state in the preview area, and provide `Open Settings`. Photo remains selectable. |
| Camera unavailable/setup failed | Keep shell controls visible, show unavailable copy in preview area, provide `Try Again`, and keep Photo as the fallback path. |
| Photo tap | Select Photo and expose the system photo picker path plus deterministic fixture path for tests and previews. |
| Photo cancel | Treat as no-op. Keep current image or fixture and show no error. |
| Photo processing | Keep previous image/result visible, overlay `Processing photo...`, cancel or mark stale work when parameters change, and replace output only on success. |
| Compare | Camera and Photo share one before/after toggle. It switches displayed input/output only; it must not reset parameters, crop, orientation, selected mode, category, or subcategory. |
| Slider updates | Sliders update displayed values immediately. Camera uses latest parameter snapshot and drops stale frames. Photo cancels or ignores stale processing before reprocessing. |
| Recoverable errors | Show friendly status copy, preserve previous visual output, and do not expose raw framework errors or sensitive paths. |

Accessibility requirements:

- Every enabled mode switch, compare control, Settings action, retry action, picker action, slider, category pill, and subcategory pill must have an accessibility label.
- Selected mode and compare state must expose selected state without requiring color perception.
- Disabled or unavailable states must include an accessibility hint explaining the reason.
- Compare must be reachable with a button or segmented control, not gesture-only.
- Dynamic Type must not overlap the preview, mode row, panel title, slider value, or action buttons.

## State Matrix

| State | Preview Surface | Primary Action | Secondary/Fallback |
|-------|-----------------|----------------|--------------------|
| Initial editor | Empty/fixture card with `Choose Camera or Photo` | `Choose Photo` | Tap `Camera` |
| Camera requesting | Same card with lightweight progress/status | none | Photo remains available |
| Camera authorized running | Live preview card | Compare toggle | Existing panel and category controls |
| Camera denied/restricted | Permission explanation card | `Open Settings` | `Photo` |
| Camera unavailable | Unavailable explanation card | `Try Again` | `Photo` |
| Photo empty | Fixture/photo empty card | `Choose Photo` | `Camera` |
| Photo loading | Previous image/fixture plus overlay | none | Existing controls remain visible |
| Photo loaded | Processed image card | Compare toggle | `Choose Photo` for replacement |
| Photo decode failed | Previous image/result plus non-blocking message | `Choose Photo` | Existing controls remain visible |
