## Scope Guard

Plan 03-01 is slightly above the normal file-count warning threshold by design. Keeping the generated Info.plist purpose strings in this first wave prevents protected-resource code from landing before local-first camera/photo purpose copy, and keeping Wave 0 tests in the same plan preserves the Nyquist dependency chain. Executors must not add unrelated Camera features, SDK internals, root-doc updates, or later Photo/compare behavior to this plan.

- `CameraPermissionState`: app-layer permission states `notDetermined`, `requesting`, `authorized`, `denied`, `restricted`, and `unavailable`.
- `CameraPermissionClient`: injectable permission client that maps `AVCaptureDevice.authorizationStatus(for: .video)` and requests access only from the Camera tap path.
- `SystemCameraPermissionClient`: production AVFoundation-backed implementation of `CameraPermissionClient`.
- `CameraPreviewFrame`: value model carrying `CVPixelBuffer`, `CGImagePropertyOrientation`, timestamp, source, and extent for camera frames.
- `CameraSessionState`: app-layer camera session states for idle, configuring, running, unavailable, and failed setup.
- `CameraSessionController`: AVFoundation session owner that configures BGRA `AVCaptureVideoDataOutput` with late-frame discard and emits `CameraPreviewFrame`.
- `CameraPreviewLayerView`: thin SwiftUI/UIKit bridge for displaying the live `AVCaptureSession` inside the existing preview card.
- `EditorInputMode`: value state for Camera and Photo mode selection if no equivalent name already exists.
- Generated Info.plist build settings `INFOPLIST_KEY_NSCameraUsageDescription` and `INFOPLIST_KEY_NSPhotoLibraryUsageDescription` with copy from `03-UI-SPEC.md`.
- `CameraPermissionStateTests.swift` and `CameraSessionControllerTests.swift`.
