# Source-only anatomical coverage diagnostic

2026-09-15. Diagnostic definition, not a registrar, metric amendment, anatomy
qualification or portrait score. Independent review required before source I/O.

The current source carrier contains Vision noseCrest/nose points, but no labeled
bilateral root boundary. Before implementing another automatic registrar, test
the necessary (not sufficient) condition that their vertical extent overlaps
the existing sixteen root measurement rows. This cannot identify root sides,
justify global nose-contour extrema, or authorize extrapolation into missing rows.

`scripts/phase95-root-anatomy-coverage.py` reuses the SHA-pinned existing source
admission driver and its exact comparator/metric/adapter definitions, bounded
180-second process-group transport and strict aggregate JSON parser. Source code
is assembled in memory at one exact unique boundary BEFORE structural registration.
No original file or frozen definition is changed. No source coordinate, pixel,
profile or child diagnostic is exported or persisted.

The diagnostic keeps original single-source/manifest/contracts hashes, original
canonicalization and ROI reconstruction. A source-only Vision observation maps
noseCrest/nose points with the same bounds and Y convention used for the eyes.
All coordinates must be finite/unit-bounded, arrays3...32, and nonzero vertical
extent. Count the unchanged16 row-bin centers inside each observed minY...maxY
range. Counts describe only vertical overlap, NOT bilateral topology, source
measurability, root-side classification or full anatomical coverage.

Only status, original source/contracts hashes, root-row count, two overlap counts,
Vision revision, false anatomical-boundary qualification/source registration and
zero portrait-scoring attempts leave the child. Two independent source-only child
runs must agree exactly. Source bytes are rechecked within each child; definition
and OS/compiler/environment identities are rechecked by the parent. All unexpected
exceptions become a fixed generic rejection; native diagnostics stay discarded.

`--inspect-source` requires a new independent reviewer-authored
`95-ROOT-ANATOMY-COVERAGE-REVIEW.json`: schema
`phase95-root-anatomy-coverage-review-v1`, status pass, reviewer agent ID, empty
findings, and complete exact snapshot matching the driver's snapshot plus this
diagnostic, this spec and its pinned driver bytes. No receipt is created by the diagnostic.
Missing/stale review fails before child execution. `--self-test` invokes generated
coverage arithmetic only; it does not execute sourceOnly. Unknown modes reject.

Generated verification includes complete/absent/partial vertical overlap, invalid
arrays/nonfinite/zero-span support, exact output schema, booleans masquerading as
counts, changed identities, duplicate JSON keys, failing child exit and stale or
invalid review. Runtime input/output/resource policy remains the pinned driver's.

No automatic alternative is certified by this diagnostic. A positive count needs
further anatomical justification; a zero count rules out unextrapolated use of
that observed vertical support for those rows. Neither permits a new fixture,
weaker threshold, favorable edge selection or bypass of the root semantic goal.
