# Source-visible candidate diagnostic — 2026-09-22

This successor is a source-only diagnostic, not a registrar or portrait gate.
The owner's request to continue and complete v1.22 permits further necessary
measurement development; generic development authorization is not the blocker.
Actual structure ownership and tested measurement applicability remain required.
Original source, ROI, effect threshold and every historical receipt stay fixed.

## Limited image model

Use exact lumaQ8 in the existing canonical source and original16 row bins, with
original source-derived eye exclusions. Search each side of the original ROI
midpoint. Retain every opposed step pair with four samples of plateau support
on each side, at least8 luminance units of mean contrast, and at most4 units of
range in each plateau. The ENTIRE exterior flank to its admitted search bound
must also have at most4 units of range. Thus a stronger interior stripe cannot
replace another clearly visible exterior boundary merely by gradient ranking.
Keep all same-polarity paths whose two edge gaps vary at most4 pixels between
registered rows. At least12 source-visible rows are required. More than64 paths
is unavailable, not truncation; no candidate outputs participate in selection.

An edge is a gap between adjacent source pixel centers, not an exact subpixel
anatomical coordinate. This narrow plateau model does NOT cover arbitrary smooth
shading, irregular texture, or below-noise outer boundaries. A generated below-
noise exterior boundary plus strong internal stripe demonstrates nonidentifiability:
candidates may exist while anatomical ownership remains false. Neither positive
candidate counts nor passing generated tests qualifies the original portrait.
No automatic admission or metric rename follows from this diagnostic.

## Execution and privacy

The adapter assembles pinned existing Swift definitions in memory and replaces
only the old source registration tail with extraction of16 rows and exclusion
limits. Profiles flow through bounded pipes to the Python process, stay in memory,
and never reach logs, files or reports. Native stderr is discarded by the existing
reviewed180-second/16MiB process-group transport. Only sanitized counts, identity
hashes, typed status and explicit false qualification/registration/scoring flags
are exported. Two complete source-only runs must agree and input identities must
remain stable. No output image is opened or scored.

Before --inspect-source, an independent reviewer must author
95-ROOT-SOURCE-CANDIDATES-REVIEW.json: phase95-source-candidates-review-v1,
status pass, reviewer_agent_id, exact --review-inputs files and empty findings.
That review permits this diagnostic only, never measurement admission. Source
execution cannot produce that review or95-ROOT-MEASUREMENT-ADMISSION.json.
The strict registered source and complete correspondence model would still be
required before any future use by the portrait comparator.
