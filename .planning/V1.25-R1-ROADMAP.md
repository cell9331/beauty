# Roadmap: Beauty v1.25 上睑外观与皮肤语义修复

Started: 2026-10-03. Status: planning; 0/6 phases complete, 0/16 requirements verified.

所有者明确重开去脂与同肤色物体识别，要求研究论文/开源实现并规划修复。
当前交付行为未改：去脂默认隐藏、资格 suspended，通用无蒙版物体仍未实现。
[研究](../docs/RETOUCH_RESEARCH_AND_V1_25_2026-10-03.md)提供候选依据，
不提前保证候选成功。Phase 编号接历史 v1.24 的 97–99，始于 100；历史
目录与回执保持原路径只读，不使用旧工具解析的 v1.17 作为编号依据。

## Goal

所有者在预先冻结、有可观察依据的静图域，取得有效的上睑外观减弱，以及
同时保护同肤色遮挡物/五官的自动皮肤处理；不支持输入安全退出。工程库存、
现行文档和实际验收一致。两条自动效果未通过不得按完整目标结项。

## Phases

- [ ] **Phase 100: Freeze observable domains and independent oracles** — 建立可证伪目标与开发/留出验收，先解决错误目标问题。
- [ ] **Phase 101: Qualify candidate sources and local feasibility** — 核对许可/依赖并比较有限分割候选，不凭论文分数准入。
- [ ] **Phase 102: Repair automatic skin, occlusion and lip protection** — 在命名域同时通过物体/五官保护与有效皮肤处理。
- [ ] **Phase 103: Repair controlled upper-eyelid appearance** — 通过独立外观、纹理和伪影判据后才允许接入。
- [ ] **Phase 104: Integrate accepted routes and current batch validation** — 接入已通过分支、保留主机退路、新建当前库存工具。
- [ ] **Phase 105: Verify compatibility, effects and current documentation** — 完成新代码全量门禁及文档闭环，不覆盖历史失败。

## Phase Details

### Phase 100: Freeze observable domains and independent oracles

Goal: 所有者能审查每一正例为何有目标、每一保护区为何须保持、哪些信息确实
可由自动请求获得；不能再让编辑器用自身评分宣称成功。
Depends on: none.
Requirements: RSC25-01, EYE25-01.
Plans: TBD; first execution task.

Success criteria:
1. 明确上睑可见饱满外观目标、独立参考/结构与禁止的别名效果；冻结双侧正例、无目标负例、交叉光照/化妆及保护 oracle。
2. 同色遮挡类别、可见差异、姿态与最小尺度具名，包含手/贴片等歧义；原完全同输入反标签案例继续作为不能保证的契约边界。
3. 开发/留出集合、数值/视觉阈值、覆盖下限、拒绝政策、资源限额和方法预算在运行候选前冻结，结果后不得自改标准。

### Phase 101: Qualify candidate sources and local feasibility

Goal: 所有者能取得可运行且权利范围明确的有限方法比较。
Depends on: Phase 100.
Requirements: RSC25-02, SEG25-01.
Plans: TBD.

Success criteria:
1. 候选逐项固定源码版本、权重/来源摘要、用途与许可、上游数据限制、依赖/运行环境；不明权重不进生产。SAM 3 的访问/CUDA 限制仅影响其备选分支。
2. 在隔离本地工具中比较最多两类分割方案（解析/遮挡组合及许可通过的提示/概念分割），保留当前守卫与正确显式蒙版控制，报告保护与有效皮肤方向的联合结果。
3. 自动无提示与新增提示信息的结果分开，模型输出映射和置信度/边缘策略在留出验收前固定；可运行性失败不记成效果失败。
4. 上睑编辑至多选择两类有新依据的候选：独立目标下的多尺度局部编辑及许可通过的局部学习式修饰。找不到合格候选则记录阻碍，不转成无限调参。

### Phase 102: Repair automatic skin, occlusion and lip protection

Goal: 所有者在具名域不必提供目标蒙版即可同时获得保护和有效处理。
Depends on: Phase 101.
Requirements: SEG25-02, SEG25-03, LIP25-01.
Plans: TBD.

Success criteria:
1. 冻结同肤色遮挡域物体与眼/眉/发/背景源精确，目标皮肤满足平滑/锐化方向及覆盖下限，不能全图停处理通过。
2. 原深肤色低对比唇缘失保护源和新姿态/尺度边缘域的无蒙版路径通过完整唇保护；保留原失败脚本/阈值，另报新测试结果。
3. 无脸、遮挡支持矛盾、未知类别和不可信边缘按冻结策略退出；host 二值排除具有最高优先级，不跨请求复用。
4. 留出输入达标，边缘回映射/保守膨胀不过度吞掉有效皮肤；真实 CPU 与 Metal-selected 路径证据分开。

### Phase 103: Repair controlled upper-eyelid appearance

Goal: 所有者能获得可控目标外观，且不是调暗、放大眼睛或移动眉的替代。
Depends on: Phases 100–101; 若依赖新的自动保护，还须 Phase 102 对该支持通过。
Requirements: EYE25-02, EYE25-03.
Plans: TBD.

Success criteria:
1. 在无额外 host 目标信息的冻结自动域通过双侧、强度可控、独立目标外观和留出输入检查；仅残差分数降低或安全 no-op 判失败。
2. 自然风格负例、交叉光照/妆容、闭眼/遮挡退出和完整保护通过；眼裂、睑缘、睫毛、眉与身份相关区域按 Phase 100 的独立定义保持。
3. 原始细节尺度检查无新增环纹、暗槽、色带或塑料质感；纹理、alpha、元数据、neutral、repeat 与失败恢复通过。
4. 至多两方法、各两实现轮后仍失败则停止本分支。保持旧字段/显式兼容和默认隐藏，不将目标参考辅助成功冒充自动效果通过。

### Phase 104: Integrate accepted routes and current batch validation

Goal: 所有者可复现通过的 SDK 路线，并有适配当前库存的工具。
Depends on: 已通过 Phase 102 / 103 的分支；批量工具可独立推进。
Requirements: INT25-01, INT25-02, BAT25-01, BAT25-02.
Plans: TBD.

Success criteria:
1. 只接入通过候选；先用宿主本地预处理接现有蒙版，必要的 SDK 接口/资源设计单独按根级 owner 核对，研究期不直接塞模型进库。
2. 既有显式物体 + 完整唇并集蒙版继续满足原保护与方向门槛，自动/提示辅助/源图退出分别核对；其他效果不继承未测保护。
3. 资源缺失/无效/超限有明确失败和恢复，原始输入仅请求内存在，运行阶段不自动联网下载、写媒体或泄露几何。
4. 新批量工具从当前 CLI 清单与独立规范库存核对身份（当前 98 默认/99 注册），正确识别缺失/重复/失败，逐案例验证结果；旧 75/65/8 wrapper、manifest 与回执保持只读。

### Phase 105: Verify compatibility, effects and current documentation

Goal: 所有者可从实际结果核对新里程碑完整程度及其限制。
Depends on: Phase 104; 完整结项还须 Phase 102 与 103 的自动效果条件全部通过。
Requirements: VFY25-01, VFY25-02, DOC25-01.
Plans: TBD.

Success criteria:
1. 适用尺寸/方向/镜像/sRGB/alpha、neutral/repeat、primary-face、禁用/跳帧/缺脸和 typed failure 恢复通过，真实后端计数清楚，无 API 默认/Codable 退化。
2. 实际运行 `bash scripts/run-no-skip-swiftpm.sh`，先档案与 SDK-only boundary，再全部必选 opt-in、非零测试、零失败、零 skip；有代码改动后不得复用此前 1076/0/0。
3. 文档/taxonomy/功能列表与行为逐项一致，原失败和旧回执只读，不把模型运行成功当作效果资格；两自动效果未通过不得按完整目标关闭。

## Boundary and stop rule

SDK-only、所有者本地静图，现有 API、无分发和隐私政策继续适用。预训练模型
方法研究在范围内；实际资产使用必须通过逐项准入。不授权训练/微调、外部
云图像编辑、UI、实时视频、三维生成生产集成、新 GPU backend 或设备保证。
生成输入可完成效果资格，真人和设备补充不成为默认 blocker。

两条路线各最多两候选方法、每方法两轮实现。任何候选若保护、目标效果或
留出标准失败则拒绝；预算耗尽停止并保留未完成项。只完成研究/隐藏/退路不能
标记两个问题已解决；只有所有者明确调整范围才可另作收尾，不自动绕过需求。
