## 1. 测量的对象和量

对象是原source中有依据的山根可见形态宽度标记，左右属于同一形态；不是
ROI内任意两个像素，也不是变形provider自己发出的控制点。先固定source对象，
再在各实际输出中定位同一对象，避免输出侧重新挑选更容易通过的结构。

对一个固定解释h中的测量单元i，定义：

- `w(role,h,i) = x_right(role,h,i) - x_left(role,h,i)`；位置以canonical全图像素为单位。
- `D(role,h) = Σ weight(i) × [w(role,h,i) - w(candidate,h,i)]`，权重非负且总和为1。
- 先传播定位/对应区间并汇总有符号变化，再转为全图宽归一化Q16。
- source与neutral各自的收缩下界至少16；每个原sibling的差区间到零的距离至少16。
- 对同一组仍合理的解释全部成立；目标信号、保护、元数据、确定性仍是同时条件。

单位、方向和原比较对象不变。行数、行位置、权重及可见结构模型属于待选方法，
必须有测量含义并在输出评分前确定，不按本次6行结果挑选。没有观测的区域
如何处理取决于被定义的量；不得删除不利单元后仍声称在测原来的量。

## 2. 当前尚缺的关键依据

需要说明一组候选为何定义山根宽度，以及在何种条件下可观察。现有证据不足：

| 已有材料 | 能证明 | 不能证明 |
| --- | --- | --- |
| Phase93生成像素及其独立真值 | 实现对已定义生成结构的收缩与保护 | 当前自然图像上哪条边属于所测形态 |
| 公开mesh索引和拓扑 | 标记对应、链连接与左右关系 | 这些链等于当前照片的宽度边界 |
| 15/16先验、6/16可见候选 | 已试局部模型的适用性计数 | 哪个候选有宽度语义，或不足原因是什么 |
| 跨行连续性设想 | 可作为几何一致性约束 | 连续内部纹理不是宽度边界 |

因此，当前不能负责任地选择“继续补跨行模型”或“把六行注册进去”。独立生成
真值可以验证一个明确模型的行为；若模型与自然图像的语义联系仍未解释，它不能
独自补上这个缺口。也不反向要求通用解剖检测器、物理骨宽真值或每张照片认证误差。

## 3. 可复用代码及适用条件

- `phase95-root-sampler-correspondence.py`：实际RGB的水平线性采样对应；只适用于
  已验证的水平采样、色彩处理与1-byte误差条件。不能直接套到含纵向位移的区域。
- `phase95-root-forward-span.py`：从已给出的对应区间和有效单调斜率界求forward位置。
  函数成功不证明其采样/斜率假设适用于每个sibling。
- `phase95-root-correlated-change.py`：共享source位置的不确定性差分，可避免重复扩大
  相同位置误差；其`measure_changes`仍固定12..16行，不能当作通用聚合接口。
- `phase95-root-visible-registration.py`：已测试的局部候选生成器；保留为候选，不能
  因通过生成测试就升为source语义注册器。
- 现有comparator的信号、保护、metadata核验和closeout的日志/原子签发机制可复用。
  旧dark-centroid测量及v2分类不能提供本次root通过信用。

使用生产场信息仅可核验采样模型/安全适用性，不能将意图位移当作实际效果值。
对noseTipLift需证明测量区域没有纵向影响，或采用适用的对应算法；不能省略它。

## 4. 必须一起修改的端到端接口

方法选定后执行一次连贯修订，不先单独把gate放宽到任意method/任意行数。
当前v3不是现成的新测量生产链，其准入接口只是预设的消费者。

| 环节 | 当前实现 | 后继必须达到的具体结果 |
| --- | --- | --- |
| source registration | v2 draft注册及仅覆盖率诊断 | 独立解释的对象、位置不确定性、聚合定义和source身份；原始坐标只在内存 |
| root measurement | 多个生成组件，未实际dispatch | 将同一注册传给source/neutral/candidate/三个siblings，计算实际像素结果 |
| comparator | 旧rootWidthContraction；输出clean-65-v2 | 调用真实后继测量并输出与其身份绑定的报告，不能只改字符串 |
| clean driver | load_registration固定旧comparator hash | 同时核验原source/ROI/manifest与新的实现身份，不覆盖原ROI记录 |
| evidence validator | root_admission固定12..16行及五文件 | 严格接受选定方法的真实schema和完整依赖身份；不建立任意自报PASS接口 |
| full-closeout/finalize | v3消费者、稳定快照和原子签发 | 消费同一新identity；保留失败拒绝、65输出、focused和完整no-skip要求 |

原ROI凭证证明原source/ROI事实；其旧comparator hash不是要求新实现必须拥有相同
字节。后继另建版本化身份并绑定原凭证，禁止覆盖旧凭证或移除source/ROI一致性。
新版本号和精确schema与已选方法同时确定，避免先造另一套待实现的固定接口。

## 5. 验证顺序与停止条件

1. 先给出第2节缺失的source宽度标记依据及其条件；没有依据则记录具体缺口，
   不启动新的原图覆盖诊断，也不把缺口转成用户人工标注任务。
2. 选定定义后，用独立生成真值覆盖真收缩、零变化、膨胀、共同平移、亮度变化、
   固定外形/内部移动、错误先验、遮挡、各sibling复制及阈值附近正反例。
   同时验证每个输出路径的采样模型；不能只测聚合函数。
3. 在同一实现修订中完成第4节接入；先以生成输入验证真实producer→consumer链，
   包括旧版本、漂移身份、缺失比较、不可测和失败输出均不能成为PASS。
4. 复用既有独立review流程审查整个修订；随后才执行一次有明确判别目的的原图
   注册/完整效果验收。不可测、效果失败、执行失败分别记录，不用重复执行替代修复。
5. 同一最终版本通过65输出、安全兼容和archive-first全量回归后，再进行最终审核
   与原子签发；正常行政记账不重触发回归。

本轮没有满足步骤1，不声称设计已可直接实现。确定的成果是测量数学含义、
代码复用边界和必须一起修复的接口清单；唯一前置研究问题是source标记的语义依据。
不重下模型、不重跑929回归、不降低16Q16、不新增默认人工或设备门禁。
