## Contract audit and candidate

The Phase 89 manifest and generated SwiftPM oracle agree on the same row
darkness-centroid second-difference metric and original `+16 Q16` floor.
Source-only localization found that most generated roughness is integer-pixel
staircase between straight contour samples, so earlier point-curvature fields
did not address the measured defect. An in-memory subpixel alignment probe
improved the generated metric without changing the protected regions.

The current candidate uses two observed lateral runs, excludes the central
chin, applies an opaque-only subpixel raster adjustment from immutable source
bytes, and then uses bounded contour points. A later bounded source-edge
check selects the measured pixel crossing only when a unique strong edge
exists within four adjacent pairs; weaker or ambiguous rows use the original
half-pixel alignment. CPU and Metal still-image paths
share the raster adjustment. For sparse 10–12-point contours the point provider
uses a wider lateral support while still excluding the central arc; the raster
adjustment retains the narrower support. No model, weight, UI, network path,
new backend, or shader was added.

## Evidence and limitation

The unchanged generated SwiftPM FACE-01 eight-predicate gate passes. The
generated public facade changes lateral pixels, preserves central/background
and alpha, and recovers after invalid support. Generated CPU/Metal still-image
parity and generated orientation/mirror fail-closed behavior pass.

An additional independent in-memory silhouette oracle now measures the actual
left/right boundary crossing rather than the original stripe's darkness
centroid. On a rough contour rasterized by rounding each observed edge to its
nearest pixel, mean absolute boundary second difference falls from about
`0.709` to `0.172` pixel units; protected central/background pixels and repeat
output are unchanged. A straight observed side is an unchanged negative
control. Before the source-edge correction, an exploratory inward-rasterized
edge increased the same metric from about `0.706` to `1.213`. That counterexample
led to a second generated assertion: the current candidate now reduces both
nearest and inward boundary roughness below half their respective source
values while preserving central/background pixels. The correction has not
been measured on a rough natural portrait. Neither generated case is a natural
portrait or device-quality result.

An owner-local 65-case portrait batch completed twice and retained seven
previously active semantic passes. FACE-01 produced 5,647 changed pixels and
126,841 absolute RGB delta. The old portrait comparator left FACE-01 on the
synthetic fixture's fixed outer ROIs, so it counted **0** target pixels and all
5,647 changes in the fixed central region. This is a portrait contract mismatch,
not evidence that those pixels were actually central anatomy.

A temporary source-only ROI probe derived two lateral target bands and a
separate central region from the portrait's observed contour before reading
the output. It placed all 5,647 changes in the target, with 0 outside, but the
existing row-centroid direction and sibling margins remained **0 Q16**.
The probe was exploratory and removed from the comparator. Visual inspection
of this already smooth portrait did not establish a discernible contour
improvement. A source-admitted positive example and an independent metric
that measures its actual edge are still needed. Generated mechanical success
must not be promoted into portrait or visual efficacy.

This portrait run preceded the later sparse 10–12-point admission correction;
the observed portrait used 17 contour points, so that branch is unaffected.
The run is diagnostic rather than a final-current-identity acceptance receipt.

The first complete no-skip run found one compatibility regression: a sparse
11-point observed contour lost FACE-01 admission in the 44-field combined
case. The lateral eligibility rule was corrected, and its focused 17-test
class passes. After the source-edge correction, the final-source archive-first
gate passed: 944 SwiftPM tests, zero failures, zero skips, all eight opt-ins,
archive verification,
SDK-only boundary, backend-neutral, Metal-runtime, feature-pass, configuration,
parity, consumer, and CPU-reference checks. `git diff --check` passed. This
is source/safety regression evidence, not the missing portrait effect proof.

A later direct 65-case renderer diagnostic used isolated output but omitted
the Phase 95 source-registration environment. It completed the mechanical
cases and emitted a `semantic_fail` aggregate across the registered directions;
that report is not comparable with the earlier registered portrait batch and
does not revise its seven passing directions. FACE-01 retained the same
5,647 changed pixels / 126,841 RGB delta under the old fixed comparator ROI.
The diagnostic outputs and temporary report were removed. The required
source-admitted rough positive and smooth negative pair remains unavailable.

Taxonomy remains `partial`; this milestone remains active. Old Phase 90/95
