### Pattern 1: Test-Local Cancellation Publication Discard

Run one synchronous opaque invocation to completion, hold only the host's publication boundary, cancel the wrapper, release publication, assert a fixed discarded outcome, then run a fresh request and prove it receives only its own aggregate identity. The gate and outcome type belong in the test file, not production. [VERIFIED: D-58-07, Phase 52 host-publication precedent, existing synchronous harness]

```swift
// Source pattern: Phase 52 cancellation closeout + current synchronous Phase 53/55 harness.
let task = Task { () throws -> PublicationOutcome in
    let completed = try harness.invoke(
        entry: .processResult,
        image: image,
        parameters: .init()
    )
    await publicationGate.markInvocationCompleteAndWait()
    guard !Task.isCancelled else { return .discarded }
    return .published(completed.aggregateSupportValueID)
}

await publicationGate.waitUntilInvocationCompleted()
task.cancel()
await publicationGate.release()
XCTAssertEqual(try await task.value, .discarded)
// Assert one intact invocation, zero retained context, then invoke again with a new value ID.
```

The test must not claim that cancellation aborts Vision, mapping, composition, or rendering, and must not change `BeautyResult<Output>` Sendability. [VERIFIED: D-58-07 and TD-013 boundary]

## Common Pitfalls

### Pitfall 1: Phase 57 Self-Test Is Run Against the Completed Tree

**What goes wrong:** Its fixture setup requires the verified pre-transition owner state, so current completed lifecycle produces `R57-COMPAT` before mutations. [VERIFIED: frozen checker `self_test()` and current STATE]

**How to avoid:** Run the unchanged checker against a read-only temporary fixture from verified revision `4125b75`, while separately requiring the current default exact completed-state result and independently auditing current owners. [VERIFIED: D-58-17]

### Pitfall 2: Cancellation Accidentally Expands TD-013

**What goes wrong:** A test is described as cooperative abort or as proof that arbitrary `BeautyResult<Output>` is safely Sendable. [VERIFIED: `DESIGN.md` TD-013 and D-58-07]
