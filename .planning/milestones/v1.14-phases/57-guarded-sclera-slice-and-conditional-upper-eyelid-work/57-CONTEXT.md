# Phase 57 — Guarded Sclera Slice and Conditional Upper-Eyelid Work Context

## Phase Boundary

Phase 57 consumes two immutable Phase 54 decisions. `sclera_redness` is
`closed` with `missing_genuine_positive` and `missing_genuine_negative`;
`upper_eyelid_fullness` is `closed` with those two reasons plus
`non_warp_design_unqualified`. Both rows have zero eligible, reviewed,
accepted, rejected, and naturalness weight values.

The only honest current result is exact absence for both candidates. The phase
proves that `祛红血丝` and `去脂` remain independently unpromoted without
changing shipped eye geometry, color effects, facade behavior, or compatibility.
It does not implement per-eye sclera mechanics, revive a rejected warp/smoothing
proxy for upper-eyelid fullness, reopen evidence review, or create an inert
zero-work field. The existing static disabled Demo rows remain visible and
unsupported exactly as shipped.

## Implementation Decisions

### Gate Authority and Conditional Requirement Meaning

- **D-01 / D-57-01:** Treat the exact `sclera_redness` and
  `upper_eyelid_fullness` rows in Phase 54's
  `54-EVIDENCE-DECISIONS.json` as the only admission authorities. Phase 57 may
  validate them but may not regenerate review, infer eligibility, or replace
  either row with a new decision source.
- **D-02 / D-57-02:** The two gates are independent peer decisions. Neither may
  borrow evidence or mechanics from teeth, the other eye candidate, shipped
  eye geometry/color, Phase 55 composition, or authorization-only media.
- **D-03 / D-57-03:** The closed sclera row selects the false branch of
  SCLERA-01: `scleraRednessReduction` remains absent from public initializers,
  stored fields, CodingKeys, JSON/default/reflection surfaces, Testing SPI,
  saved output, and runtime admission.
- **D-04 / D-57-04:** SCLERA-02 through SCLERA-05 are recorded exactly as
  `not_applicable_closed_gate`, not as implemented per-eye support, iris/highlight
  safety, containment, effectiveness, naturalness, or abstention behavior.
- **D-05 / D-57-05:** SCLERA-06 resolves exactly as `no_promotion`: facade,
  review evidence, privacy, compatibility, regression, Demo, and ledgers agree
  that `祛红血丝` stays `future` and branch `眼睛` stays `partial`.
- **D-06 / D-57-06:** The closed upper-eyelid row selects LID-02's explicit
  false branch: `upperEyelidFullnessReduction` has no public/internal field,
  provider, transform, renderer case, admission value, saved-output path, or
  inert route; `去脂` remains `future` and `眼睛` remains `partial`.
- **D-07 / D-57-07:** LID-03 and LID-05 are exactly
  `not_applicable_closed_gate`; Phase 57 makes no non-warp effectiveness,
  texture/identity, naturalness, facade-output, or admitted-slice claim.
- **D-08 / D-57-08:** LID-04 remains an affirmative proxy-rejection invariant.
  Existing `eyeHeight`, `upperEyelidLift`, brow translation, eye aperture/warp,
  global smoothing, dark-circle, and eye-bag behavior remain legitimate in
  their shipped domains but may not be renamed, coupled, routed, or cited as
  `去脂`/upper-eyelid-fullness substitutes.

### Evidence, Demo Taxonomy, and Ledger Ownership

- **D-13 / D-57-13:** The current rights-approved portrait is not a genuine
  sclera-redness or upper-eyelid-fullness positive and is not a complete
  feature-specific negative bundle. Spike outputs remain mechanics-only and
  contribute zero eligibility and naturalness weight.
- **D-14 / D-57-14:** Do not select files, request image uploads, run human
  original-detail review, generate before/mask/after output, track media, open a
  browser reviewer, or regenerate the Phase 54 decision. Missing evidence and

- **D-15 / D-57-15:** Preserve the exact static disabled Demo taxonomy rows
  `unsupported("eyes.fat", title: "去脂", ...)` and
  `unsupported("eyes.redness", title: "祛红血丝", ...)`, their order/badges/
  unavailable copy, and nil active mappings. Add no slider, parameter binding,

- **D-16 / D-57-16:** Preserve authoritative ledgers exactly:
  `去脂 = future`, `祛红血丝 = future`, and branch `眼睛 = partial` solely
  because both retouch rows are future. Do not close the branch, promote one
  row from the other's evidence, or rewrite shipped eye geometry as retouch.

### Privacy, Security, and Verification

- **D-17 / D-57-17:** Build one fail-closed checker from the hardened Phase 56
  pattern. Scan the complete production Swift source boundary, including newly
  added neutrally named files, for canonical and synonym candidate/provider
  routes. Sclera aliases include eye/conjunctiva/bloodshot/ocular redness and
  sclera whitening; eyelid aliases include eyelid/lid fat or fullness removal.
  Proxy checks must be semantic and context-aware so existing
  `upperEyelidLift`, `eyeHeight`, smoothing, dark-circle, and eye-bag features
  remain shipped but cannot be coupled to the candidate.
- **D-18 / D-57-18:** Verification output and durable evidence expose only fixed
  rule/task/threat IDs, exact status/reason allowlists, zero counts, and
  compatibility totals. They contain no portrait path/hash, grants/reviewer
  payload, eye/pupil/iris/landmark support, masks, vein-like descriptors,
  coordinates, pixels, output digest, raw source match, or raw error.
- **D-19 / D-57-19:** Author exact-absence and proxy-rejection tests before any
  evidence/owner promotion. Self-tests mutate temporary copies of actual
  decision, SDK, Demo, ledger, evidence, and owner fixtures; missing files,
  malformed JSON/frontmatter, scanner failures, and unclassified subprocesses
  fail closed.
- **D-20 / D-57-20:** Final validation alone runs complete focused suites,
  checker aggregate/live/per-threat modes, full SwiftPM, explicit iPhone 17e/
  iOS 26.5 Demo build/test, schema/UI/diff/decision/task/threat/owner gates, and
  exact codebase-drift classification. Every ASVS L1 HIGH row blocks. No
  algorithm, safety/effectiveness/naturalness, image, device/performance,
  commercial, packaging, shipping, launch, or release claim is inferred.
