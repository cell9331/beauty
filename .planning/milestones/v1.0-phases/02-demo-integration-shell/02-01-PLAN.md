# Plan 02-01: Refactor Demo App Shell Into Feature Directories and SDK-Only Dependency Wiring

<objective>
Wire `BeautyDemo` as a real host app for Phase 2 by linking the local `BeautySDK` facade product, adding the Demo test target, and replacing the default SwiftUI template route with an editor shell entry that honors D-01 through D-04.
</objective>

<user_story>
As a host app developer, I want the Demo app to compile against only `BeautySDK` and open directly into an editor shell, so that Phase 2 validates the public facade boundary before category and slider behavior is layered in.
</user_story>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| Demo imports an internal SDK target instead of the facade | high | Wire only the `BeautySDK` product, add a Demo import-boundary smoke test, and run the forbidden internal-import scan. |
| Manual `.pbxproj` edits corrupt the Xcode project | high | Keep project edits limited to package reference, product dependency, framework link, and test target objects; verify with `xcodebuild -list` and a simulator build. |
| Protected media access enters Phase 2 through Camera or Photo routes | medium | Render disabled mode entries with `Coming in Phase 3` copy and no camera/photo framework setup. |
| Default template survives as the product entry | medium | Route `WindowGroup` to `EditorShellView` and scan `BeautyDemo/BeautyDemo` for `Hello, world!`. |
| Broad repository worktree changes enter the commit | medium | Commit only the files listed for this plan and record unrelated dirty files as out of scope. |
</threat_model>
