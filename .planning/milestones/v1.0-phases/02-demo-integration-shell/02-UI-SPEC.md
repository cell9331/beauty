## Visual Hierarchy and Layout Contract

| Area | Contract |
|------|----------|
| Primary focal point | Static portrait preview area centered in the upper two-thirds of the screen. The preview must clearly read as the future editor canvas, not a generic blank panel. |
| Secondary focal point | Bottom category rail with Beauty selected by default. Active selection receives the only accent treatment outside focused sliders. |
| Tertiary focal point | Parameter panel above or attached to the category rail, showing the current category title, controls, disabled badges, and short status text. |
| Disabled modes | Camera and Photo mode entries remain visible near the top or preview edge, disabled, and labeled `Coming in Phase 3`. |
| Disabled panels | Disabled categories may open, but must show a phase badge and short reason instead of active controls. |
| Icon-only actions | Avoid icon-only controls in Phase 2. If an SF Symbol is used for mode/category decoration, pair it with visible text and accessibility label. |
| Preview placeholder | Use a deterministic portrait-fixture style placeholder. Do not request camera, photo library, or protected media access. |

Layout rules:
- First viewport must show preview, disabled Camera/Photo entries, bottom categories, and at least the start of the active Beauty panel.
- Bottom categories must appear in this exact order: Beauty, Face Shape, Facial Features, Makeup, Filters, Stickers, Background, Style.
- Facial Features subcategories must appear in this exact order: Eyes, Nose, Mouth, Eyebrows, Teeth, Hairline.
- Sliders use a label, current display value, range, reset button, and availability state.
- Reset All is visible in the active panel header or footer and must not look destructive.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge inner gaps, slider tick/value spacing |
| sm | 8px | Row gaps, category item inner padding, compact text spacing |
| md | 16px | Default screen padding, slider row padding, panel item spacing |
| lg | 24px | Panel vertical padding, preview-to-panel spacing |
| xl | 32px | Major preview/category separation on taller screens |
| 2xl | 48px | Large-screen preview breathing room |
| 3xl | 64px | iPad page-level spacing only |

Exceptions:
- Minimum touch target is 44px for interactive controls, matching iOS accessibility expectations.
- Slider thumb and native SwiftUI control metrics may follow system control sizing.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 13px | 400 | 1.3 |
| Heading | 20px | 600 | 1.25 |
| Display | 28px | 600 | 1.15 |

Rules:
- Use only weights 400 and 600 in Phase 2.
- Use Dynamic Type compatible SwiftUI text styles where practical, but preserve this hierarchy.
- Do not use viewport-scaled type or negative letter spacing.
- Disabled reason copy uses Label size, never Display or Heading size.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #F7F8FA | Main app background and preview surroundings |
| Secondary (30%) | #FFFFFF | Preview surface, parameter panel, category rail surface |
| Accent (10%) | #2F6BFF | Active category indicator, focused slider tint, primary status dot, focus ring |
| Destructive | #D92D20 | Reserved for future destructive confirmations only |

Accent reserved for:
- selected bottom category indicator,
- active slider fill/thumb tint,
- "Parameters applied" status dot,
- keyboard or accessibility focus ring if needed.

Color rules:
- Disabled controls use #8A8F98 text on #EEF0F3 surface.
- Coming-later badges use #EEF3FF background with #2F6BFF text.
- Error or unavailable-resource states use destructive color only when there is an actual recoverable error; planned future features use neutral disabled treatment.
- Do not use accent for every button, every icon, or every interactive row.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Apply Parameters |
| Empty state heading | Preview fixture ready |
| Empty state body | Adjust a Beauty slider to update the SDK parameter snapshot. Visual effects arrive in later phases. |
| Error state | Demo shell could not initialize. Rebuild the Demo target, then retry from the editor shell. |
| Destructive confirmation | none - Phase 2 has no destructive actions |

Additional required copy:
- Disabled Camera mode: `Coming in Phase 3`
- Disabled Photo mode: `Coming in Phase 3`
- Filters disabled badge: `Coming in Phase 5`
- Future resource-backed categories: `Requires future resource support`
- Applied status: `Parameters applied`
- Visual pending status: `Visual update pending Phase 6`
- Reset one control: `Reset {Control Name}`
- Reset all controls: `Reset All Parameters`

Copy rules:
- Keep normal UI explanations to one short sentence.
- Do not expose roadmap IDs or implementation jargon in visible user copy.
- Disabled hints must explain availability without promising that the feature works.

## Interaction Contract

| Interaction | Contract |
|-------------|----------|
| Initial state | Editor shell opens with Beauty selected, default parameter values, disabled Camera/Photo entries, and static preview fixture. |
| Category tap | Available categories switch panels. Disabled categories may open a disabled panel, but no active controls are shown. |
| Facial Features tap | Shows Eyes, Nose, Mouth as usable structure; Eyebrows, Teeth, Hairline remain disabled with short badges. |
| Slider drag | Display value updates in the row; app state normalizes into `BeautyParameters` on commit or continuous binding update. |
| Single reset | Resets only the selected control to zero-effect default and leaves other controls unchanged. |
| Reset all | Resets all numeric display values and SDK snapshot fields to zero-effect defaults. |
| Filters category | Visible but disabled, including filter rows and intensity, marked `Coming in Phase 5`. |

Accessibility rules:
- Every slider has an accessibility label equal to its visible control label.
- Every slider exposes value text as `{value} percent` or `{signed value} percent`.
- Disabled controls expose a hint containing the phase badge copy.
- Category controls expose selected state.
