# Plan 02-03: Render Editor Shell Panels and Add Demo View-State/Import-Boundary Tests

<objective>
Complete the Phase 2 Demo integration shell by rendering descriptor-driven SwiftUI panels, exposing honest disabled states and slider/reset interactions, and closing `SDK-08`, `DEMO-02`, `DEMO-03`, `DEMO-04`, `DEMO-05`, and `DEMO-08` with automated evidence.
</objective>

<user_story>
As a QA and SDK integration reviewer, I want to launch the Demo into a real editor shell and run deterministic tests for its state, so that Phase 2 proves the host-app UI contract before media input and effects are added in later roadmap phases.
</user_story>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| SwiftUI rendering invents labels or availability outside descriptors | high | Render category rails, panels, and slider rows directly from the descriptor/state model tested in 02-02. |
| Disabled controls look active to users or accessibility clients | high | Apply disabled styling, disabled interaction, and accessibility hints containing badge copy. |
| Slider UI updates display text but not SDK snapshot state | high | Bind slider rows to `BeautyParameterStore` and keep view-state tests on store values. |
| Protected media, network, or SDK internals enter final shell | medium | Run media/network scans and internal-import scans before completion. |
| Completion evidence claims visual effects are active | medium | Use UI copy `Visual update pending Phase 6` and avoid effect-output claims in docs. |
</threat_model>
