## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Badge vertical padding and tight inline offsets |
| sm | 8px | Chip gaps, row gaps, badge horizontal padding |
| md | 16px | Default shell padding, panel padding, preview image padding |
| lg | 24px | Message horizontal padding and compact section breathing room |
| xl | 32px | Large internal preview gaps when a section needs separation |
| 2xl | 48px | Reserved for major section breaks only; do not add to Phase 5 panels |
| 3xl | 64px | Not used in Phase 5 Demo shell |

Spacing rules: use 8px for compact internal padding in status banners, bottom preview overlays, chip groups, and tight control rows. Use 16px for standard control-card and panel padding. 44px is required only as the minimum touch target height for mode, category, preset, filter, and reset controls; it is not a spacing token.

| Body | 16px | regular 400 | 1.5 |
| Label | 13px | regular 400 | 1.4 |
| Heading | 20px | semibold 600 | 1.2 |

Rules:

- Use only regular 400 and semibold 600 in Phase 5 UI.
- Use 13px for chip labels, badges, reset buttons, status copy, slider endpoint labels, and compact action buttons.
- Use 16px for slider row labels and normal preview body copy.
- Use 20px for panel and non-initial preview headings.
- Use 28px only for the first-screen preview heading. Do not use display type inside preset or filter chips.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F7F8FA` | App background and inactive enabled control backgrounds |
| Secondary (30%) | `#FFFFFF` | Preview surface, active panel surface, enabled rail chips, popover-like banners |
| Accent (10%) | `#2F6BFF` | Selected chips, slider tint, primary buttons, status dot, active badge text |
| Destructive | `#D92D20` | Destructive actions only; no Phase 5 control uses this by default |

Accent reserved for: selected Camera/Photo mode, selected top-level category, selected Facial Features subcategory, selected preset chip, selected filter chip, slider tint, bordered-prominent primary actions, status dot, resource-availability badge text, and `#EEF3FF` accent-tint badge backgrounds.

Supporting neutrals:

| Token | Value | Usage |
|-------|-------|-------|
| Disabled surface | `#EEF0F3` | Disabled categories and unavailable controls |
| Accent tint | `#EEF3FF` | Non-error badge background |
| Muted text | `#8A8F98` | Disabled labels and unavailable reasons |
| Status text | `#202F4D` | Processing/status banner text |

Rules:

- Do not introduce a new palette for presets or filters in Phase 5.
- Metadata-only filters must not use visual swatches that imply real LUT output. Use text chips only.
- The UI must keep honest copy that color/filter visual output remains pending Phase 6.

## Visual Hierarchy

Primary visual anchor: the active in-panel picker row plus the current slider group. Selected chips and the status dot draw first attention through the reserved accent color; slider labels and values form the next scan layer. Preview copy remains secondary and must not compete with the active picker, slider group, selected chip state, or status indicator.

## Phase 5 Interaction Contract

### Beauty Panel

- Keep the existing top-level category order: Beauty, Face Shape, Facial Features, Makeup, Filters, Stickers, Background, Style.
- Add the preset picker inside the existing Beauty panel, above Beauty sliders and color sliders.
- The picker must be compact horizontal chips, matching current category/subcategory rail behavior: 13px label, 8px corner radius, 44px minimum height, selected chip using `#2F6BFF` with white text.
- Preset application replaces the full current parameter snapshot. It must not layer on top of current slider values.
- After applying a preset, all represented display values must sync immediately: skin values, all eight color values, selected filter, and filter intensity.
- Beauty panel controls must appear in this order: preset picker, existing skin sliders, color sliders.
- Color slider labels must be exactly: Brightness, Contrast, Saturation, Temperature, Tint, Exposure, Highlight, Shadow.
- Use existing ranges: enhancement controls use `0...100`; bidirectional controls use `-100...100`. All eight Phase 5 color controls are bidirectional and must display `-100...100`.

### Filters Panel

- Change Filters from disabled to enabled, but do not move it in the top-level rail.
- The Filters panel contains a compact filter picker followed by one `Filter Intensity` slider.
- Filter options are exactly `None` plus two metadata-backed filters from the resource registry.
- `None` maps to `filterId == nil` and `filterIntensity == 0` unless the user manually changes intensity after choosing a metadata filter.
- `filterId` is categorical and must not be modeled as a slider row.
- `filterIntensity` uses `0...100` UI and maps to SDK `0.0...1.0`.
- Unknown or missing filter resources must not be selectable. If a resource was expected but unavailable, show it disabled with the missing-resource reason copy.

### Resource Failure States

- SDK/resource loading is strict; Demo presentation is friendly.
- If all presets fail to load, show the empty state copy in the preset region and keep current parameters unchanged.
- If all metadata filters fail to load, Filters remains visible and enabled only if `None` can still be selected; otherwise show empty state copy and no intensity slider.
- Do not show raw paths, raw framework errors, internal target names, JSON payloads, or local file locations.
- Missing resources are not destructive and must not clear the user's current parameter snapshot.

### Deferred Behavior

- Do not promise visible color rendering in Phase 5.
- Do not add real LUT assets, LUT parsing, identity LUTs, visual swatches, or filter style thumbnails.
- Do not add JSON import/export, a standalone preset page, a new top-level Presets category, or final QA/debug polish.

## Component Inventory

| Component | Contract |
|-----------|----------|
| `BeautyPanelView` | Composition point for preset picker, color sliders, enabled Filters state, and status row. |
| `BeautyCategoryRailView` | Existing top-level rail; preserve order and selection visuals. |
| `BeautySliderView` | Reuse for numeric color controls and `filterIntensity`; keep reset button and accessibility value format. |
| Preset chips | New compact horizontal chips inside Beauty panel; source from facade-visible presets. |
| Filter chips | New compact horizontal chips inside Filters panel; source from facade-visible filter definitions. |
| `BeautyParameterStore` | Owns display values, selected filter ID, preset application, and normalized `BeautyParameters` snapshot. |

Accessibility requirements:

- Every preset chip accessibility label must be `Apply {Preset Name} Preset`.
- Every filter chip accessibility label must be `Select {Filter Name} Filter`; `None` uses `Select No Filter`.
- Disabled resource chips must expose the missing-resource reason as an accessibility hint.
- Sliders retain meaningful values such as `+20 percent` or `35 percent`.
- Dynamic Type must not overlap chip text, slider values, reset buttons, or status copy. Horizontal chip rows may scroll.
