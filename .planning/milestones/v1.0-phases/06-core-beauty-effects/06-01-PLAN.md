</objective>

## Artifacts this phase produces

- `BeautyEffectsTests` target in `BeautySDK/Package.swift`.
- `BeautyEffectDomain`: internal `Equatable`, `Sendable` enum for `skin`, `color`, `filter`, `faceShape`, `eyes`, `nose`, `mouth`, and `lipColor`.
- `BeautyEffectPlan`: internal/public-to-package value containing active domains, skipped domains, warnings, metrics, and effective strengths.
- `BeautyEffectResolver`: pure resolver that turns normalized `BeautyParameters` plus filter validation state into an effect plan.
- `BeautySafetyCaps`: cap constants for `skinSmoothing: 0.60`, `skinWhitening: 0.50`, `skinRosy: 0.40`, `skinSharpen: 0.40`, `filterIntensity: 1.0`, and shared geometry cap constants used by later plans.
- `BeautyColorEffectPipeline`: deterministic MVP pixel/CI transform for skin, color, `soft_clean`, and `warm_light`.
- Updated `BeautyEngine.processResult(pixelBuffer:metadata:parameters:)` and `processResult(image:metadata:parameters:)` output routing.
- Engine fixture tests proving default no-op, non-zero visible output, filter-visible output, preset-visible output, and unknown-filter typed failure.

<threat_model>
## Trust Boundaries

| Boundary | Description |
| --- | --- |
| Public parameters -> internal effective strengths | Host-provided values keep public range but must be capped before visible output. |
| Filter ID -> resource validation -> effect transform | Unknown filter IDs are untrusted resource references and must not silently render. |
| Effect metadata -> public `BeautyResult` | Warnings and metrics may leave the SDK but must not contain sensitive image, path, or face-geometry data. |
