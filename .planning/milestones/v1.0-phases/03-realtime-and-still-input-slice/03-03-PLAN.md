<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PhotosUI -> Demo image pipeline | OS-owned photo selection becomes in-memory image data handled by the Demo. |
| Demo image pipeline -> SDK facade | Decoded `CIImage` and parameters enter public `BeautySDK` image processing. |
| SDK/image errors -> UI status | Decode and process failures must become friendly, non-sensitive copy. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03-01 | Information Disclosure | `ImageEditorPipeline` | mitigate | Do not log or display image paths, framework domains, or raw errors; tests assert friendly copy. |
| T-03-03-02 | Tampering | selected image data | mitigate | Decode to `CIImage`, validate finite non-empty extent through SDK processing, and preserve previous result on failure. |
| T-03-03-03 | Denial of Service | photo processing | mitigate | Process off main actor, represent loading explicitly, and cancel or ignore stale work on parameter changes. |
| T-03-03-04 | Repudiation | compare behavior | mitigate | Keep compare as display-only state with tests proving it does not reset parameters or selections. |
| T-03-SC | Tampering | package installs | mitigate | No third-party photo, image, or UI packages; use PhotosUI, CoreImage, ImageIO, and local `BeautySDK`. |
</threat_model>
