# Plan 03-02: Add Bounded Realtime SDK Invocation Without UIImage Conversion

## Phase Goal

**As a** Demo user, **I want to** keep using sliders while Camera frames process through `BeautySDK`, **so that** realtime input stays fresh and responsive instead of building unsafe queues.

<objective>
Connect the Phase 3 camera frame shell to the public `BeautySDK` no-op pixel-buffer path through a bounded Demo-owned pipeline. Keep processing outside SwiftUI `body`, avoid realtime `UIImage`, preserve last usable visuals on recoverable failure, and expose enough state for shared compare behavior.

Purpose: This closes PIPE-02 and PIPE-03 and prepares the Camera side of PIPE-06 without changing SDK internals.
Output: `CameraBeautyPipeline`, camera processing state, stale-frame/drop tests, and static no-`UIImage` evidence.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AVFoundation frame -> SDK facade | User-protected camera pixels enter public `BeautySDK` processing through Demo-owned validation and backpressure. |
| Slider state -> processing queue | Main-actor UI values become immutable parameter snapshots before off-main processing. |
| SDK error -> UI status | Typed errors cross into user-facing copy and must stay redacted. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02-01 | Denial of Service | `CameraBeautyPipeline` | mitigate | Bound in-flight work, replace stale pending frames, and assert dropped-frame counts in tests. |
| T-03-02-02 | Tampering | camera pixel buffers | mitigate | Process only `CVPixelBuffer` frames through `BeautyEngine`; rely on SDK unsupported pixel format validation and test error mapping. |
| T-03-02-03 | Information Disclosure | realtime media pipeline | mitigate | Do not log or persist frame pixels; preserve local in-memory state only. |
| T-03-02-04 | Information Disclosure | error/status UI | mitigate | Map `BeautyError.code` to UI-SPEC copy and reject raw `NSError`, framework domain, and path display. |
| T-03-SC | Tampering | package installs | mitigate | No external package installs; Apple frameworks and local `BeautySDK` only. |
</threat_model>
