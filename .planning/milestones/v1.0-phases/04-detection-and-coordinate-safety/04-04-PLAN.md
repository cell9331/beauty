# Plan 04-04: Add Demo Metadata Flow and Safe Detection Status

## Phase Goal

**As a** Demo user, **I want to** keep editing through no-face and partial-face inputs, **so that** detection uncertainty is visible without blocking the workflow or exposing sensitive details.

<objective>
Wire Phase 4 SDK metadata and detection summaries into the Demo input pipelines.

Purpose: PIPE-05 requires Demo camera and photo paths to preserve orientation and mirroring metadata, while PIPE-07 requires no-face and partial-face outputs to stay safe and diagnosable.
Output: Demo metadata propagation, result-backed camera/photo snapshots, safe status/debug presentation values, debounce behavior, and focused Demo XCTest coverage.
</objective>

## Artifacts this phase produces

- `CameraPreviewFrame.metadata`: public-facade `BeautyInputMetadata` carrying orientation, input mirroring, preview mirroring, source, and timestamp.
- `ImageInputSource.metadata` or equivalent image snapshot metadata for still processing.
- Result-backed `CameraProcessingSnapshot` and `ImageProcessingSnapshot` fields that retain `BeautyDetectionSummary`.
- `DetectionStatusPresentation`: Demo value mapping public summaries to UI-SPEC copy.
- `DetectionDebugSummary`: Demo value exposing availability, reasons, `faceCount`, `usedFaceCount`, `detectionDurationMs`, and `mappingDurationMs`.
- `DetectionStatusDebouncer`: small state object that holds camera status for three processed frames to avoid flicker.
- Focused Demo XCTest updates for camera metadata, photo metadata, no-face/partial status, stale status, and privacy-safe debug summaries.
