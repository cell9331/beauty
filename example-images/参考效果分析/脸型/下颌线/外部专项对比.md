# 与外部《下颌线阴影专项》的对比

比较日期：2026-10-17。对象为用户提供的《14-下颌线阴影专项》和三联配图，以及本目录的原始参考测量、当前分支实际 SDK 输出。这里只核对分析，不执行外部文档中的实现建议。

**两份分析对主要现象的判断一致：本样本主要是下颌下方的宽域阴影，没有可辨认的大幅几何变化。作为当前 SDK 改造依据，本轮分析的证据更完整；外部文档的“冷灰、去红”方向和具体实现参数不能直接采用。** 这不代表本轮已确定美图的内部公式。

## 逐项比较

| 项目 | 外部专项 | 本轮证据及判断 |
| --- | --- | --- |
| 几何类别 | SIFT 相似变换内点 99%，稠密光流平均位移 0.1–0.25 px | 结论相容。本轮另有独立 NCC 两尺度、局部位移分位数、稳定区留出和已知平移控制；接受点 P95 0.23/0.24 px，无 >2 px 点。全局内点率或平均光流不能单独排除局部形变，本轮也只能排除本图可分辨的大幅变化 |
| 阴影范围 | 约 150 px、约 0.2–0.25 倍脸宽，颈部有宽尾 | 主趋势互相支持。本轮中央源边缘下约 100 px 仍有明显变暗，约 160 px 接近背景差。这里是手工源边缘的纵向偏移，不是精确法向距离；本轮约 127 px 的退出过渡宽与外部 150 px 总范围不是同一指标，不能按数值大小判胜负 |
| 幅度 | 中线约 −10%，侧方更深 | 大体相容，但不能精确互证。本轮左/中/右源区域编码亮度中位 −11.15%/−7.25%/−7.77%，不同于局部峰值；外部没有提供可复跑的同域 ROI 和统计定义，不能把区域中位与峰值直接比较 |
| 颜色方向 | R 降幅最大，推断冷灰、去红，并建议按通道偏移或 Oklab | 本轮核对原文件 ICC 并做同域重算后，通道排序反转。外部色调方向存在很强的色域混比嫌疑，见下节；不能据此保证偏冷 |
| 材质边界 | 头发与衣服基本不变，因此推断颈部/皮肤/头发 mask | 观察本身合理，但结果不能唯一识别 mask 类型、分割模型或混合方式。UI 的“背景保护”开关也不能证明内部使用人像分割 |
| 当前代码 | 给出 478 点、SDF、Oklab、姿态与组合建议 | 这些是候选设计。本轮还核对了实际生产代码、准入与本图输出，区分薄域生产实现和未接入的宽域试验，能更直接说明 SDK 现在差在哪里 |

## 决定性的复核：先统一色域，再比较通道

原图文件无 ICC，本轮明确按 sRGB 假设；参考截图带 Display P3 ICC。仅执行 `convert('RGB')` 不会把 P3 转成 sRGB。对相同源观察区、相同像素、相同统计，只改变是否执行 ICC 转换，结果如下。表中数值是逐像素“参考/源”的编码通道比中位，越小代表该通道降得越多。

| 同一观察区 | 处理 | R | G | B | 降幅最大的通道 |
| --- | --- | --- | --- | --- | --- |
| 左下颌下 | 直接比较 P3 字节与假定 sRGB 原图 | 0.8735 | 0.8983 | 0.9359 | R |
| 左下颌下 | 参考按 ICC 转 sRGB 后比较 | 0.9209 | 0.8772 | 0.8421 | B |
| 中央下颌下 | 直接比较 P3 字节与假定 sRGB 原图 | 0.9167 | 0.9355 | 0.9780 | R |
| 中央下颌下 | 参考按 ICC 转 sRGB 后比较 | 0.9636 | 0.9156 | 0.8725 | B |

外部给出的 0.884/0.908/0.949 与“未统一色域”的通道排序相同；本轮不是用不同区域之间的差异解释排序，而是在同一观察区中复现了排序反转。额头控制区也提供旁证：未转换时 R/G/B 比约 0.9541/1.0120/1.0317，转换后约 0.9910/1.0000/0.9923，原先明显的红减、蓝增在非阴影区域大幅消退。

**这是外部色调判断不可靠的强证据，还不是对其测量过程的完全复现。** 提供的 Markdown 和配图没有给出原测量脚本、精确 ROI 或 ICC 流程，因此不能断言已查明其具体错误行。也不能由本轮一张图反过来规定所有人像都应采用某种暖色配方；无标记源图的 sRGB 假设及共同中性态仍未被独立确认。

## 具体实现建议有多少证据

- 单侧下颌距离场、约两成脸宽的宽尾、皮肤/头发/衣服保护，都是值得验证的候选方案；不能称为已还原的闭源算法。
- `L=0.22`、指数 1.2、侧向 1.25、去红系数 0.35 是设计参数，未由这张图唯一识别。外部也把其中部分明确标为目视起始值。
- Oklab 的 L 降低 10% 不等于编码亮度或线性亮度降低 10%，应把最终输出转换回同一测量域再校准。跨肤色稳定性需要多素材验证，当前单样本不足以保证。
- 单端截图不能确定张嘴、俯仰、偏航、实时滤波、多人脸，或“去双下巴”是否共用反号阴影场。此类建议不能升级为参考事实。
- 本轮“共同 gain 不能解释”严格指当前代码使用的**编码 RGB 三通道同乘**。这一结论不能直接推广成所有线性光或感知颜色空间中的中性明暗模型均不成立。

## 对当前 SDK 最有把握的判断

当前生产实现不改几何，这一大类方向正确；它的源下颌下允许域只有 `0.005S…0.045S`，本图最终输出是薄且断续的带。实际公开照片路径编辑 2136 像素，136 个非零列，每列变化数中位 16、最大 19；与参考百余像素的宽尾差别明确。

这不是单纯“强度太小”：已编辑区域的中央中位接近参考，部分像素又比条件参考更暗。因此最确定的待改造项是**范围、连续性及色调响应**，不能统一加深来补覆盖。实际数值与验证边界见 [代码差异](代码差异.md)。本轮实际运行仅覆盖该源图的 macOS Vision 照片 CPU/Metal 路径。

本轮仍有局限：只有一个右端样本；原图是条件中性源；观察区和纵向边缘由源图确定但仍含人工选择；弱纹理区域的亚像素几何不可充分识别。故本轮适合指导下一轮受控试验，不能取代多素材及用户外观验收。

本次新增验证只做同域色域重算，未修改 SDK/App，未运行构建、模拟器或真机回归。本地可复跑入口见 [本地测量说明](本地测量说明.md)。
