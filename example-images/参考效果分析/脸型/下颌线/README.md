# 下颌线：参考与当前代码差异

> 最新状态：本项已按本轮证据改造并安装真机，见[实施说明](实施说明.md)。以下保留改造前取证与代码比较，不能视作当前实现。

> 最新分析：[中央缺口、入口与下缘的重新归因及修复方案](残留问题重分析与修复方案.md)。中央材质误拒、RGB 预算与尾型需分别处理；离线候选尚未合入 SDK。

> 代码与图片速查：[问题代码与效果对照](问题代码与效果对照.md)，逐项列出关键行号、执行链及因果证据。

本轮分析日期：2026-10-17。范围仅为参考取证与现有实现比较，没有改 SDK 或宿主效果。

**现有样本支持“下颌下较宽区域的局部明暗变化”，没有支持可辨认的下颌几何收缩。** 当前生产实现同样不改变几何，但它的可编辑域是一条很薄的、严格依赖源光照资格的带，并采用编码 RGB 统一乘增益；参考可观察到的宽尾和通道变化均超出这两个假设。不能仅调大 `jawlineShadow` 数值就认定模型一致。

输入只有 `IMG_2034` 的右端截图。原图是条件工程中性源，尚未证实是该控制共同零态；`IMG_2033` 是下颌角右端，不能作为下颌线左端。故下列幅度是“对齐原图 → 2034”的条件差，不能拆成左右半幅或推断滑杆中间档。

| 比较项 | 本轮参考事实 | 当前代码含义 |
| --- | --- | --- |
| 几何 | 独立 NCC 两尺度接受 196、204 点；无 >2 px 移动点；接受点位移 P95 0.23、0.24 px | 下颌线生产路径只改 RGB；这一大类与样本一致 |
| 编码亮度 | 下颌下左、中央、右区域中位分别 −12.93、−11.51、−11.94 /255 | 最大 18% 是编码 RGB 理论减益上界，另受源对比度、局部权重、资格和羽化削减，不能与区域中位直接等同 |
| 色彩响应 | 中央 R/G/B 相对变化中位约 −3.64% / −8.44% / −12.75%；单一共同 gain 解释后仍有明显残差 | 三通道同乘，不能表达这类通道间差异 |
| 纵向范围 | 源下颌边缘下方约 100 px 的中央带仍有 −8.87/255 中位变化，约 160 px 仍约 −2/255 | 几何域限制在源下颌下方 `0.005S…0.045S`，总厚度最多 `0.04S`，还须通过源暗侧/材质资格 |
| 组合 | 这一个右端截图不能确定参考 App 的组合策略 | 生产下颌线拒绝与几何、纹理类效果共用源坐标；允许列举的点式颜色效果 |

`S` 为当前代码的观测脸轮廓横向跨度，并非眼距。上表编码亮度先将截图的 Display P3 ICC 转为 sRGB；原图无 ICC，按 sRGB 假设处理。背景约 −1/255 的整体传输差、锐边重采样残差不归因于下颌线。解码线性光下的下颌下左/中央/右亮度中位分别约 −21.07% / −13.96% / −14.86%，与编码百分比是不同域。

本图实际公开 SDK 右端运行**通过源资格**，强度为 0.25，10 条合格射线、2845 个合格编辑像素，最终 RGB 变化 2136 像素。CPU、实际 Metal 及直接生产 `Evidence.apply` 的结果逐字节一致；SDK 中性输出与本次原图也逐字节一致。实际不是无效果，但仅覆盖很薄的断续带：136 个非零列，每列变化像素数 P5/P50/P95 为 12/16/18，最大 19。相同完整左/中央/右下颌下观察区的 SDK 亮度变化中位均为 0，而参考保持上表的非零变化。

在 62288 像素的源下颌下/颈皮肤观察并集中，参考条件编码差低于 −3/255 的 48148 像素里，SDK 改变 1607 个，占 3.34%。这只是指定观察域和阈值的条件覆盖，不能称语义分割真值或参考零态的 IoU。局部已编辑像素还可过暗：SDK 最深编码差 −27.83/255；因此主要问题是范围和色调形状，不能把整体欠覆盖简单当成统一欠幅。
