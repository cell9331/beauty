# 发际线：参考与当前代码差异

> 改造前历史快照；当前模型、幅度与范围见[实施说明](实施说明.md)。

2026-10-17，核对本工作分支当前代码。此页为差异统计，本轮未改 SDK/宿主；参考测量与不确定性见[分析链路](分析链路.md)。

## 实际照片路径

宿主通过 [`BeautyFaceShapeSlider`](../../../../BeautySDK/Sources/BeautyCore/Models/BeautyFaceShapeSlider.swift) 把滑杆位置 `p∈[0,1]` 映射为 `hairlineHeight=(2p−1)×0.25`，中心是宿主工程零态。直接 API 正值使该竖直边界下移，滑杆右端同号；参考左→右也以下移为主，因此竖直方向一致，不能据此宣布模型一致。

[`FaceShapeWarpProvider`](../../../../BeautySDK/Sources/BeautyEffects/Warp/FaceShapeWarpProvider.swift) 的 `hasSourceHairlineGeometry` 要求新鲜人脸、有效归一化 bounds、至少 6 个有效轮廓点、有范围的轮廓、左右实测眉语义等，给 `sourceRefinementMask` 设置资格。旧控制点不足时，只要该资格成立，规划仍可保留请求；几何资格不等于像素发肤边界资格。

照片 [`BeautyStillImageGeometryStage.prepareSourcePrefix`](../../../../BeautySDK/Sources/BeautyEffects/Render/BeautyStillImageGeometryStage.swift) 在源前缀调用 [`HairlineBoundaryRefiner`](../../../../BeautySDK/Sources/BeautyEffects/Render/HairlineBoundaryRefiner.swift)，然后进行其他阶段。非零发际线请求抑制旧 `hairlinePoints`；源像素检测拒绝时保留源图，不回退双点代理。因此不能只读旧点模型或借历史 no-op 推断这版也不生效。

## 模型、幅度和范围

以下 `H_f` 为当前检测脸框的像素高度，`S_f` 为有效轮廓横向跨度，`r` 为源曲线局部半径。参考是左端→右端的对应；代码系数是从原源图到单端的上限，二者不直接等同。

| 对照维度 | 参考端点观测 | 当前照片实现 | 差异性质 |
| --- | --- | --- | --- |
| 两分量 | 中央头发向下约 34 px，左右发丝向内约 17～18 px；方向随位置转变 | 保持 x，逐列只改变 sampleY | **明确模型差异**：水平分量恒为 0，调竖直增益不能补齐内收 |
| 主体方向 | 单共享向内径向锚点可解释 28 个强运动点，12 点留出正交残差 P95 0.83 px | 沿每列发肤曲线设置相同竖直方向；没有二维共享锚点 | **明确模型差异**：切向/径向结构不同 |
| 主体范围 | 强运动延伸到发肤边界上方较宽头发区域和两侧，中央纵带 10%宽约 268～274 px | 只处理中央脸框横向一半内的源边界带；coherent 半径约 `0.06S_f`，并受眉间隙限制 | **明确范围差异**：候选窄带不能覆盖参考头发区域 |
| 峰形与过渡 | 竖直中央峰两尺度 33.7～34.5 px；上下过渡约 89～90 / 108～110 px | hard 平台/线性尾，soft 四次 bump，coherent C¹ 小平台 ramp+源保护+约束；支撑均由源曲线局部半径决定 | 形状和上下伸展需分别比较，不能按单峰值换算 |
| 幅度上限 | 直接可测仅端点总差，不能自动除二 | 单端初始 `0.018H_f`；soft 再限 `0.25r`、coherent 限 `0.29r`；保护与梯度预算可进一步缩小 | 先识别实际路线和有效位移，再统计真实差额；API cap 不是实测像素幅度 |
| 五官及头顶 | 核心眉眼、鼻口、远区与头顶近稳；外围侧发有运动 | 源带外严格保留；coherent 还拒绝跨过不透明度/细枝保护源像素 | 保留核心方向相符；冻结范围比参考宽，不能把所有发丝固定当目标 |
| 端点与零态 | 只知道 2035 左→2036 右，原图共同零态未证实 | 宿主中心为 0、左右为 ±0.25；采用工程上的双端对称参数 | 不能据端点差断言产品对称或 SDK 单端“差一倍” |

代码实际采样为 `I_out(q)=I_src(q_x,q_y−σ A(q))`，`σ` 由合成强度符号决定，`A(q)≥0`。这是输出网格上的逆采样描述，不能把 `A(p)` 当作同一材料源点的前向位移。比较 SDK 双端时应先找到共同原源点，再取其两个输出位置之差；也可以直接对 SDK 左端→右端再次测对应，但不能逐点相减不同坐标域的场。

## 像素资格和保护的具体约束

当前 `HairlineBoundaryRefiner` 有三条来源不同的路线，均只读取请求内源图：

- hard 路线在脸框上方有限搜索区逐列寻找深色→亮色跳变，要求红通道跳变至少 35、前后色阶和不透明度支持，且整条曲线高度变化有限。
- legacy soft 路线允许分布式过渡，要求每列暗侧、亮暖侧、通道关系、不透明度、连续行斜率和拱形；有另一条得分接近的完整曲线时拒绝。
- bounded coherent 路线在最长边不超过 960 的分析图寻找完整曲线，保留原 soft 的色彩与峰资格，另核对额肤来源及狭发枝保护；禁止靠补洞通过缺列。第二条分离完整路径达到第一条得分 85% 时拒绝。检测后只把源曲线恢复到原图，不生成缺失的头发/皮肤。

coherent 的源固定非负位移场在最长边 512 的物理网格上定义，细枝及不透明源足迹作保守投影，支撑保持在每列源半径内。场只许减小，最终把双线性格的梯度角界限制在约 0.45；单端采样前核对沿途不穿越保护像素。由此幅度可能显著低于 `0.018H_f`。这些是当前工程保护规则，参考材料并未证明必须冻结所有相同位置。

额头与发际线共用同一前缀：`s=clamp(hairline−forehead×cap_h/cap_f,±cap_h)`。两项同时启用时会合成甚至抵消；本轮公开 SDK 核对只启用发际线，防止把另一个控制的影响误作发际线本身。

旧 [`hairlinePoints`](../../../../BeautySDK/Sources/BeautyEffects/Warp/FaceShapeWarpProvider.swift) 的双点、单端 `0.045H_f` 和点半径仍存在于代码，并非本轮照片输出的幅度来源。实时像素缓冲路径不在本次照片测量结论中。

## 本图 SDK 实际核对

本轮对一次 macOS 生产 Vision 源观测，以原图工程源单独运行公开发际线左右端 **−0.25/+0.25**；只启用本项。**两端均与 SDK 中性输出逐字节相同，实际变化像素 0，位移幅度和生效范围均为 0。**两端实际目标→源坐标场也严格为单位映射；所以任意同一个原源点的前向端点差都是 0，逆求解残差 0、失败 0，无需错误地相减后向场。

| 本图资格或输出 | 实际结果 | 能说明什么 |
| --- | --- | --- |
| 人脸/规划 | 一次源检测、一个人脸；源几何资格成立；有效强度保留 ±0.25 | 不是未检测到脸、滑杆未传入或规划强度被清零 |
| 发肤源曲线 | `sourceCurveFound=0`，coherent `completePath=0`、`admittedCurve=0` | 源像素路线拒绝，没有回退旧点代理 |
| 候选列诊断 | 240 列，缺颜色列 0；经过峰/保护/肤源资格后无可用峰列 169；competition veto=0 | 不能归因成竞争曲线拒绝；当前来源资格无法构成完整路径，不由日志倒推参考算法 |
| 额肤来源细分 | 额肤 prototype 与独立光照来源均建立，但仍有候选肤族/连接拒绝 | 某个来源子步骤成立不等于完整发际线资格成立 |
| 本图实际幅度/支持 | 左右端各 0 改变像素，双端前向场各处为 0 | 本输入上没有参考的约 34 px 下移和约 17～18 px 内收，也没有参考的宽区域 |
| 路径核验 | 当前原模块、仅加坐标 observer 的逐字复制模块、公开 CPU 输出逐字节一致；本图左右端 CPU/Metal 逐字节一致 | 此 no-op 是当前公开照片路径的实际输出；不是只测到未接入的实验副本 |

将参考低端纹理独立匹配到原图，再取同一个原源点的 SDK 双端差：r14 参考接受146点中同材质链通过145、拒绝1；r20为129中通过128、拒绝1。仍用各自纹理、峰唯一性和闭合判据，不用 SDK 或参考光流作筛选。

| 同材质比较 | 移动 >2 px 点数 | SDK 幅度最大 | 与参考端点向量差 P50 / P95 / 最大 |
| --- | --- | --- | --- |
| r14 | 58 | 0 px | 9.35 / 33.70 / 33.95 px |
| r20 | 40 | 0 px | 13.51 / 33.68 / 33.83 px |

其余87/88点分别列存，不能稀释移动点差额；r14异常假峰也沿原判据保留。此处差值是对所接受参考对应的差，不是知道闭源真值后的全图精度。原图共同零态仍未确认，但 SDK 两端全域恒等，因此这一结论不依赖把原图错当参考零态。
