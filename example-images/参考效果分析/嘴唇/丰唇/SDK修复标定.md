# 丰唇 SDK 修复标定

日期：2026-10-17。本页记录基于 `c871bfff` 原生基线继续改造时的固定观测标定过程。下列数值来自新鲜 iOS 原生观测在 macOS 上重建后运行的实际 Swift SDK 映射，不属于随后真机渲染的执行次数。该版后续独立的新鲜原生检测、facade 及 CPU/Metal 输出验证见[公共修复记录](../M唇与丰唇修复记录.md)；所有者已确认本轮嘴部功能暂定收尾，见[人工验收](../人工验收.md)，尚存参考差异保留。不能沿用[基线复核](SDK对照复核.md)的次数或保护结果作为新版证明。

所有位移均为统一到 1170×1608 截图照片网格的低端→高端端点跨度，x 向右、y 向下。699×960 预览按独立 x/y 尺度及像素中心换算。参考没有共同零态，名义系数不是中性到端点的实测强度，端点总差也未除二。

## 修复的结构与候选参数

旧模型把绝对鼻部保护折入弯曲唇缝的相对纵向下界，使两个本应微动的中央上方皮肤点始终为零。真实原生几何已确认它们位于绝对保护平面下方，却落在旧相对下界之外。现在把请求局部源坐标的绝对保护包络与唇缝相对组织包络分开；绝对上方过渡使用观测可用间隙，避免极窄夹逼。保护包络的横向平台覆盖上下支撑并集。

仅调上下斜率与共用包络时，唇内纹理、外缘和皮肤尾部无法同时接近参考。候选增加一个源深度响应参数，以及一个上唇相对下唇的宽度因子：

```text
t = y - seam(x)
B(t) = S5(clamp((t / delta + 1) / 2, 0, 1))
K(t) = 1 - a + a * S3(clamp(abs(t) / depth(t), 0, 1))
b(t) = (1-B) * upperRate + B * lowerRate
X(x,t) = (1-B) * Xupper(x) + B * Xlower(x)
Dlocal(x,y,u) = (0, u * Z(x,y) * Y(t) * t * K(t) * b(t) * X(x,t))
```

响应率 `b` 与横向包络 `X` 分别混合后相乘，与实际 `Model.sample` 一致；不能把两者合并为上下加权乘积之和。此处为说明公式纠正，既有数值来自实际 Swift 查询，不由旧文档公式重算。

`S3` 为三次 smoothstep，`S5` 为五次 smoothstep；`depth(t)` 采用源观测的上下深度。`a=0` 保留线性组织响应，较大 `a` 抑制唇缝附近与内部响应，到观测深度恢复原幅。上下横向包络共用纵向范围，仅上唇的横向边界乘相对宽度因子。模型保留局部竖直约束，没有增设未经验证的 screenX 平移。

完整采样导数包含唇缝斜率、深度响应、上下包络混合的 `B'` 项，以及绝对源包络乘积链。准入继续使用连续区间导数证书与受约束逆映射；密网只排查证书保守程度，不替代证明。比较顺序始终为从低端查询逆求同一源点，再计算两个端点的前向位置。

以下是 236 个受限实际映射候选中选出的名义配置，已四舍五入到六位小数；每张输入仍接受自身安全证书的缩幅。它们是本实现的设计标定值，不代表参考软件内部算法。

| 参数 | 候选值 | 单位或含义 |
| --- | ---: | --- |
| upperRate / lowerRate | 0.363750 / 0.450000 | 名义上下响应率 |
| innerHalfWidth / outerHalfWidth | 0.197500 / 0.422500 | 源嘴宽归一化距离 |
| upperSkinReach / lowerSkinReach | 0.163750 / 0.197500 | 超出源观测深度的嘴宽归一化延伸 |
| depthCurvature | 0.112500 | 深度响应混合量 |
| upperWidthScale | 1.234375 | 上唇横向支撑相对下唇的倍率 |

对应 `main` 分支仓库相对路径：配置为 `BeautySDK/Sources/BeautyEffects/Render/BeautyMouthFullnessConfiguration.swift`；源厚度、保护、曲线导数及上下支撑独立行为的定向测试为 `BeautySDK/Tests/BeautyEffectsTests/BeautyMouthFullnessCalibrationTests.swift`。

## 分区结果：同时保留改善与退化

沿用原始源纹理选择的 67 个缩放 NCC 对应，活动 20、近静止 47。固定尺度方法单列，不把背景合入活动点降低误差。下表为完整二维端点向量残差 P95，单位 px；少量样本的 P95 不代表连续区域精度。

| 原源图分区 | 数量 | 基线 | 候选 | 解释 |
| --- | ---: | ---: | ---: | --- |
| 全部活动对应 | 20 | 5.946 | 5.570 | 小幅改善 |
| 全部近静止对应 | 47 | 3.390 | 1.785 | 尾部分位数改善，仍有局部带动 |
| 中央上唇 | 2 | 1.863 | 3.660 | 退化；上移偏强，且样本很少 |

| 中央下唇 | 10 | 5.488 | 5.594 | 高分位数未改善，不能只看中位幅度 |
| 上方中央皮肤 | 7 | 2.922 | 3.920 | 原截断消除，但移动点幅度偏强 |

中央下唇十点均保持向下，dy 中位由基线 13.92 调为 18.14 px，参考为 16.33 px；逐点 dy 偏差中位为 +1.42 px。上唇两点 dy 中位为 −9.00 px，参考为 −6.09 px，存在过度上提。原先被截断的两个上方移动点现在为 −6.98…−6.18 px，参考约 −2.99…−2.75 px，也仍偏强。

下方 guard 的 dy 偏差由 +9.23 降至 −0.21 px，但二维残差仍约 1.10 px；小水平分量没有因此复现。中央下唇参考 dx 全正、SDK 小负的差异继续保留，不将“竖向主方向一致”扩大为二维方向完全一致。

47 个近静止对应中，SDK 模长≥1 px 的数量由 4 增至 5。P95 改善与这一计数同时成立，不能据此宣称作用范围全部修正。

## 数据角色与新增下方皮肤证据

原源坐标 tile 和整列 shape 划分保留。已多次查看的唯一中央下方活动皮肤点改为明确的 **mechanistic guard**，纳入拟合，记录其原角色；此后不再称其未参与拟合。其余源空间复核集合没有直接进入数值优化，但已经被反复查看，不能称 blind、未见数据或完全独立测试集。

按新协议，训练与 guard 的分组损失由 2.8371 降至 0.7307，剩余未直接拟合空间复核的损失由 0.8262 降至 0.1344。这些是分组加权目标，不是像素误差，也不与旧协议直接比较。

另在源图下方皮肤按固定 tile 独立选点，未按 SDK 残差筛选。56 个 tile 的 15/21 px 两窗口分别接受 6/10 个，共同可靠 6 个；方法差异中位 0.052、最大 0.091 px，参考模长最大 0.093 px。可靠点只覆盖更下方两侧，中央没有新增可靠点，不能补成中央活动尾部的连续衰减曲线。

六个新增静止点位于本候选紧支撑之外，可由外部恒等和单调逆映射推出端点跨度为零。**这是源支持域推论，未新增执行六次 SDK 或真机查询，不计入旧查询数量，也不是新版像素保护验证。** 最终若追加实际查询，需单列新点与执行数。
