## 比较方法

参考配对仍是 M 唇 `IMG_1969→IMG_1970`、丰唇 `IMG_1971→IMG_1972`；裁剪、稳定区恒等对齐及原有独立检查见各项[分析链路](M唇/分析链路.md)与[分析链路](丰唇/分析链路.md)。本轮原像素与原裁剪逐字节核对，不重新做局部可变形配准。

M 唇补测在预先固定的源纹理空间分区取点，15×15、21×21 两种模板独立搜索；保留模板间差异、全部拒绝和扩大搜索后的结果。丰唇继续以缩放纹理匹配及七列上下唇缘为主要证据；其稠密光流在唇部不闭合，不拿光流峰值标定幅度。轮廓只约束形状，不冒充已知 dx=0 的材质对应。

真机为同一 iPhone 13 Pro／Apple A15 GPU／iOS 26.4.2。两个源端点各走实际 `PhotoRenderer.load`，得到 699×960 预览，再执行一次生产 MediaPipe 478 点检测；没有手工替代轮廓。同一图的新鲜原生观测仅在请求内存中固定，用于实际 BeautyEngine CPU/Metal 比较。

参考纹理点使用整数像素中心的数组索引坐标，SDK 使用实际像素中心坐标。两者按实际宽高分别换算，包含半像素偏移：

```text
q_preview = (q_reference_index + 0.5) * (preview_size / base_size)
p = actual_F_low_inverse(q_preview)
V_pair = [actual_F_high(p) - actual_F_low(p)] / (preview_size / base_size)
```

699 宽的取整与 960 高的比例略有差异，因此不把一个理想缩放常数用于两个轴。原 macOS Vision 结果采用不同检测几何及旧查询中心约定，不与本轮数字混作同版本基线。

普通 App 的左右端输出从同一输入分别生成，不直接拿其右端图冒充参考高端。另生成诊断用的相对重放图：对目标 q 求 `p=F_high_inverse(q)`，再从参考低端图的 `F_low(p)` 位置单次双线性采样。它展示实际端点间映射，不是另一个候选算法，也不是普通 facade 的单端输出。

## 实际执行与限制

- M 唇：1,035 条方法记录，679 个不同源中心，含原 410 条及新增 625 条。重叠模板和同点的多方法记录不构成独立统计样本。
- 丰唇：282 条纹理方法记录及 42 条形状查询；形状查询为七列×上下两缘×三组定位设置，三组用于敏感性而非增加独立样本。
- 两项另有 9,882 个预先固定网格查询，仅表示实际 SDK 场，不是新增参考观测。合计 11,241 个同源查询全部有结果，失败 0；最大低端逆回代残差约 `9.9821×10⁻⁵` 预览像素。
- 实际执行 24 次 facade 请求，覆盖两个源、CPU/Metal、零态、左右端、两个中间档及归零。非中性实际输出与同请求映射逐字节一致；CPU/Metal 逐查询一致。两后端仍共用当前嘴部 CPU 采样实现，不声称纯 GPU 嘴部采样。
- 两个中间档在固定同源点上通过方向趋势检查；参考没有中间档，因此这只是实现设计验证。零态/归零、源不变、alpha、输出范围及眼、鼻、左右外颊、下巴五个预选观察窗均通过实际像素检查，不扩大成完整解剖区域资格。
- 相对重放的两张图逐像素逆解、有限性、alpha 和保护窗检查通过，无失败回退、无越界钳位。此结论不等于参考外观通过。

本轮仅运行这个两项真机测量入口及资料检查，没有重跑全 SDK，也没有把此前 95 项嘴部测试算成本轮新增验证。临时测试尾段、编译标志和专用 scheme 已精确撤回；正常 App 严格签名检查通过并恢复安装、前台启动，数据保留。
