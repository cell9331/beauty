# 参考效果分析资料库

所有参考效果分析统一在这里归档：**总目录 → 部位 → 功能**。每个功能把可审阅证据、分析链路和实现方案放在一起，便于持续补充与复核。

## 五个部位

| 部位 | 已归档功能 | 入口 |
| --- | --- | --- |
| 脸型 | 脸宽、小脸、面部流畅、太阳穴、颧骨、下巴长短、尖下巴、V脸、下颌角、发际线、下颌线 | [脸型](脸型/README.md) |
| 眉毛 | 上下、粗细、长短、间距、眉头间距、倾斜、眉峰 | [眉毛](眉毛/README.md) |
| 眼睛 | 12项有参考样本，另5项保留缺证记录 | [眼睛](眼睛/README.md) |
| 鼻子 | 大小、提升、鼻翼、山根、鼻梁、鼻头 | [鼻子](鼻子/README.md) |
| 嘴唇 | 大小、宽度、上下、倾斜、左右、M唇、丰唇、微笑；白牙仅缺证说明 | [嘴唇](嘴唇/README.md) |

## 统一目录约定

```text
参考效果分析/
├── README.md
├── 脸型/
│   ├── README.md                 # 本部位索引和公共测量约定
│   ├── 实现公共约定.md           # 多项共用的数学，按需设置
│   ├── 证据/                     # 本部位总览，按需设置
│   ├── 本地测量/                 # 共享输入/配准/脚本，按需设置
│   └── 脸宽/
│       ├── README.md             # 功能入口、范围和当前状态
│       ├── 分析链路.md           # 输入→对齐→测量→交叉检查→推导
│       ├── 实现方案.md           # 候选模型、标定、保护和验证
│       ├── 本地测量说明.md       # 本地材料清单与复测边界
│       ├── 证据/                 # 对照、dx/dy热图、横纵剖面
│       │   └── 位移证据.png
│       └── 本地测量/             # 原始对应、场和分项中间资料
├── 眉毛/
├── 眼睛/
├── 鼻子/
└── 嘴唇/
```

每个已分析功能采用上述结构；没有证据或尚未推导方案时，在入口明确标明状态，不用候选生成图补作测量证据。属于整个部位的坐标、输入对齐和采样约定集中维护，功能只写差异。

## 保存与更新

- 证据图保存在本项目的功能目录，文档使用相对链接和图片引用，不依赖会消失的会话目录。
- 聚合分析和方案 Markdown 可由 Git 跟踪；图片沿用项目现有忽略规则，`本地测量/` 整目录忽略。实际点位、逐像素场、蒙版及私有路径不嵌入聚合文档，也不强制加入版本库。
- 原始参考图片继续保留在既有输入目录；归档保存必要的对齐输入与追溯资料，不改原件。脚本快照的历史路径和依赖可能需要适配，保存不等于已验证可直接重跑。
- 分析日期、输入配对、坐标单位、零态资格、接受/拒绝统计和未知量随每项记录；实测数与设计参数分开。
- `实现方案.md` 必须写明候选、已实施或已验证的实际状态。当前实施与效果资格见各部位记录；脸型已分批接入，见[前三项记录](脸型/SDK改造记录.md)、[后五项记录](脸型/后五项SDK改造记录.md)、[后三项记录](脸型/后三项SDK改造记录.md)。已知残差保留，不能当作参考效果已经复现；下颌线最新归因见[代码与效果对照](脸型/下颌线/问题代码与效果对照.md)。
- 后续新分析直接进入对应部位/功能；重测保留输入身份与聚合变更记录，更新对应证据及链路，不把不同批次、方向或尺度混在一起。

初次归档只验证复制完整性、目录与链接、忽略规则和文档一致性，没有重跑历史测量。后续测量、实现、定向测试、构建与设备交付范围以各批记录为准；仅分析阶段与实现阶段的验证不能混称全量回归或最终外观通过。
