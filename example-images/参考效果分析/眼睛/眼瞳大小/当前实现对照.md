# Iris size: reference versus current implementation

[Shared current-code contracts and eleven-control summary](../十一项当前实现对照.md) · [Feature overview](README.md)

Reviewed 2026-10-17 against the current working files, including uncommitted changes. **Confirmed default-route spatial-behavior mismatch; research route remains unpromoted.** This review changes no SDK/host behavior and runs no new measurement, build or test.

## Reference facts

`IMG_1939 → IMG_1940` shows compact iris-region expansion together with central upper/lower lid and adjacent scleral motion. A strictly fixed original lid/aperture rim is inconsistent with those observed following regions. Exact core shape, boundary and neutral response remain uncertain. See [evidence](分析链路.md).

## Active implementation

Public/full-size rendering defaults to `.legacy`: [stage default](../../../../BeautySDK/Sources/BeautyEffects/Render/BeautyStillImageGeometryStage.swift#L55), [CPU call](../../../../BeautySDK/Sources/BeautyEffects/Render/BeautyGeometryEffectPipeline.swift#L266) and [Metal call](../../../../BeautySDK/Sources/BeautyEffects/Backend/BeautyMetalBackend.swift#L210). Dense support uses the dedicated circular/isotropic [BeautyIrisScaleRemap](../../../../BeautySDK/Sources/BeautyEffects/Render/BeautyIrisScaleRemap.swift#L196), with source aperture, eroded lid rim and material/donor handling. Sparse positive sizing in the full-size route remains contour-confined; unsupported negative sparse sizing abstains. See [continuous sparse admission](../../../../BeautySDK/Sources/BeautyEffects/Render/BeautyContinuousEyeMap.swift#L286).

## What differs

**The retained default moves the iris region while preserving the original lid rim; the reference shows lid/sclera following.** This is the clearest supported behavior conflict among these eleven controls. Circular symmetry and fixed support are additional unqualified choices, not separately proven defects.

The explicit package-only [calibrated selector](../../../../BeautySDK/Sources/BeautyEffects/Render/BeautyIrisGeometryRoute.swift#L7) and [following map](../../../../BeautySDK/Sources/BeautyEffects/Render/BeautyIrisFollowingMap.swift#L145) allow joint iris/lid/sclera motion without the legacy aperture clip. File existence does not make that the active public/editor implementation. No production calibration defaults were inferred.

The original-resolution public preview still defaults to [legacy](../../../../BeautySDK/Sources/BeautyEffects/Render/BeautyIrisPreviewCutpoint.swift#L73). Unlike the full-size sparse path, this preview invokes the dense-only remap and suppresses later pupil work after that stage. Thus a dense admission failure does not activate sparse pupil sizing there. The editor uses this public preview, not `.calibrated`.

## Qualification and missing discriminator

The [implementation record](实施与验证.md) and [side-by-side review](效果对照与补证方案.md) retain actual research replay and 44 historical directed passes. The frozen-fit endpoint refuses under `unsafeContraction`; an already explored applied fit has remaining iris-boundary/lid/scleral residuals and insufficient independent holdouts. These are not fresh photographic acceptance or a default migration. The owner's decision to retain the local outcome does not close those gates. New-route Metal, composition and host promotion remain unqualified.

Numerical constants above describe existing code or measured aggregates; they are not replacement defaults. See the shared comparison for inverse/forward domains, strength polarity, admission and source-sampling limits.
