# Iris-size migration plan

Original planning status: documentation-only. The subsequent user-authorized implementation and its **task-by-task disposition** are recorded in [Implementation and directed validation](实施与验证.md). The calibrated research route and focused tests are implemented; reference-effect qualification and default/host promotion remain blocked. This plan follows the [implementation comparison](../实现差异统计.md), [measured evidence](分析链路.md) and [candidate field](实现方案.md). The [shared programme](../改造计划.md) owns sequencing across eye controls; the [evidence-gap register](../证据缺口.md) owns **G01** (neutral/response), **G02** (support/kernel), **G03** (iris geometry/occlusion), **G13** (joint composition/performance) and **G14** (frozen reference-fit criteria).

The intended change is an iris-centred geometric expansion whose support can carry the observed eyelid and scleral motion. The current dense iris path scales material inside a fixed eye aperture and protects its lid rim. That behaviour cannot satisfy the qualified lid-follow observations. Replacing the gate is a semantic change: successful safety checks or a larger iris alone cannot qualify it.

## Evidence boundary and compatibility

| Usable target now | Unresolved quantity and consequence |
| --- | --- |
| The observed left-to-right endpoint pair has opposing horizontal expansion lobes and upper/lower outward vertical lobes. | **G01:** neither endpoint is a certified neutral, and no intermediate response was measured. A pair-relative research route is possible; a signed production calibration is not identified by this pair alone. |
| Source-selected correspondences show central eyelid and adjacent scleral follow motion. The lower-lid evidence includes a conflicting right-eye match that must remain in the evaluation. | **G02/G03:** exact support boundaries, the centre, occluded geometry, gain anisotropy and fine transition shape are uncertain. Do not turn the current circular core or the proposed compact kernel into a target fact. |
| Outer-canthus and external texture observations are relatively quiet; the nasal side has limited nonzero follow motion. | **G02:** protect the independently quiet regions while allowing the measured nasal transition. Do not impose an exact zero on the entire inner corner or full lid contour. |
| Dense fields and independent matches constrain direction and sample-specific motion scale. | **G14:** the current quantiles and cross-method differences are qualification evidence, not automatically acceptable reproduction-error thresholds. No threshold may be chosen from heatmap magnitude alone. |

Keep the existing public `pupilSize` field, serialized key, signed cap, exact-zero semantics and `BeautyEyeShapeSlider.irisSize` mapping unless a separately reviewed API change is required. The current centred linear mapping remains the **product mapping** while G01 is open; retaining it does not establish reference equivalence. Preserve slider position, undo/redo, reset, saved parameters and sibling intent. Do not silently reinterpret an old saved neutral value as the observed left endpoint.

No new raw pixels, correspondence coordinates, masks, dense fields or private input paths belong in this Markdown. Future measurement artefacts remain in the ignored local evidence collection; persistent receipts contain only allowed aggregates, source identifiers and method/version metadata.

## Ordered tasks and stop points

### IR-01 — Freeze a truthful comparator

**Dependencies:** G14; the current input qualification. **Output:** a local comparison manifest and an aggregate acceptance specification approved before fitting.

1. Reuse the qualified pair and common photo grid. Verify input identity, pixel-centre conventions, extent, photo-crop origin and source-to-target signs. Preserve already aligned bytes; do not locally register the deforming eye or resample it again for convenience.
2. Keep two domains distinct. The research family maps the observed left endpoint to the right endpoint, `F_0=identity`, `F_1≈reference`. This route can be fitted now without inventing a neutral.
3. For a production family rendered from one frozen canonical source point `p`, compute both endpoint maps, `x_L=F_L(p)` and `x_R=F_R(p)`, then compare `x_R−x_L` on the left-endpoint domain. Equivalently evaluate `F_R ∘ inverse(F_L)` where coverage is valid. Do not subtract two offset arrays at equal indices on different deformed grids. Without a qualified common source/domain correspondence to the reference pair, report this as a separate product-family check rather than a measured reference fit; G01 remains open.
4. Convert the current destination-grid inverse offset into an actual source-forward map or track source features through its renderer before scoring. Its `q−d(q)` sampler is an inverse-field definition, not automatically the candidate's forward `D`. Do not compare the single-endpoint `.21` response, an iris radius or a nominal cap directly with pairwise screenshot displacement.
5. Freeze source-selected fitting/held-out partitions and anatomical reporting groups before examining candidate agreement: iris texture, superior/inferior lids, nasal/temporal sclera, nasal transition, outer canthus and external protection. Preserve disagreements and match-rejection accounting. Sparse groups cannot be promoted into broad coverage.
6. Under G14, set component-wise dx/dy, contour/texture, support/quiet-region and inverse tolerances from qualified correspondence uncertainty, control experiments and the intended output scale. State the acceptance coverage and missing observations. Dense-method disagreement alone is neither a target tolerance nor an excuse for an arbitrary error budget.

**Acceptance:** identity and known local expansion/follow controls establish sign, coordinate conversion and comparator sensitivity; a deliberately fixed-lid candidate fails the lid-follow effect oracle. These controls establish comparator behaviour, not reference reproduction.

**Stop:** if the local evidence cannot be replayed, the held-out target is inadequate, or meaningful G14 criteria cannot be frozen, retain a research result only. Do not choose thresholds after observing a preferred candidate.

### IR-02 — Fit the smallest core and following support

**Dependencies:** IR-01; G02/G03. **Output:** a source-frozen field and an aggregate fit/hold-out report.

1. Use reliable source eye axes, iris-centre/radius evidence and the visible eyelid aperture already available to the SDK. Record geometric uncertainty. A detector ring crossing an occluding lid does not prove a visible circular iris boundary; no complete hidden anatomy is inferred from it.
2. Start from the [candidate](实现方案.md): a compact expansion with separate horizontal/vertical gains. Fit internal motion first, then support/falloff. Compare a simpler isotropic fit before adding anisotropy; keep whichever independent residuals support. A plateau, polynomial envelope or radial kernel is a hypothesis, not a required copy of the closed-source algorithm.
3. Fit lid and sclera follow explicitly. The source aperture may describe observed anatomy, but it must not multiply the displacement to zero at the very lid margins that move. Fit the return toward quiet outer canthal and external regions, permitting the measured nasal follow. Do not expand support merely to satisfy a gradient budget.
4. Score moving texture and stationary texture separately, and report upper/lower and nasal/temporal errors separately. Retain the conflicting lower-lid correspondence and dense-method sensitivity at occlusion boundaries. A good all-pixel median or a correct iris diameter cannot hide a lid/support failure.
5. Reject source geometry or samples that need unsupported hidden tissue. First test whether the fitted geometric map can use observed source pixels with a valid footprint. Donor reconstruction, affine white fields and glint restoration from the old path are not automatically part of this target; retain one only after an independently demonstrated need and a separately stated appearance contract.

**Acceptance:** held-out vectors and actual warped contours support the same low-complexity field; lids and sclera follow while qualified quiet regions remain quiet under IR-01 criteria. Report per-eye results without assuming equal bilateral gains.

**Stop:** unresolved G02/G03 that changes the selected mechanism, prevents a trustworthy transition fit, or requires unsupported source material blocks effect qualification. A safe but fixed-lid output is not an acceptable substitute.

### IR-03 — Replace the active owner and raster gate

**Dependencies:** IR-02 and the safety design in IR-04. **Output:** a development-only selectable route with one iris geometry owner.

1. Trace and change both full-resolution and preview entry paths. Dense support currently removes `pupilSize` from `BeautyContinuousEyeMap`, and `BeautyStillImageGeometryStage`/`BeautyIrisPreviewCutpoint` invoke `BeautyIrisScaleRemap` separately. Replace that ownership deliberately; merely changing the dormant dense iris branch in the continuous map does not migrate production behaviour.
2. Route admitted `pupilSize` into the following field once. Remove the new route's fixed source-aperture destination erosion and hard preview owner that suppress lid motion. Replace them with the field's qualified support plus complete immutable-source sampling ownership. Source pixels outside the old iris aperture can be observed, valid lid/skin input; they are not automatically unknown merely because the old gate excluded them.
3. Retain genuine safety restrictions: finite dimensions/geometry, fresh selected-face evidence, peer/protected-feature ownership, valid source coverage, alpha and full sampling-footprint checks. Recompute protections against the new support. Widening a changed-pixel domain does not authorize transparent, out-of-image, masked/unknown or hidden donors.
4. Prevent duplicate application across the dedicated iris path, continuous eye branch and `EyeWarpProvider` proxies. Failed new admission must still suppress the old proxy for the same request. A sparse compatibility path must either qualify the new mechanism on its own evidence or return an explicit no-op; it must not silently restore fixed-lid scaling.
5. Until promotion, a development selector may keep the currently shipped implementation independently inspectable. Its outputs and tests must be labelled as the old contract. It is not a runtime fallback after the new route refuses, and it does not count as successful execution of the new behaviour.

**Acceptance:** routing tests show exactly one new owner for dense iris requests and no old-path execution after refusal; both preview and full resolution can carry qualified lid pixels. Public parameter decoding and sibling strengths remain unchanged.

**Stop:** if either cutpoint still clips valid lid follow, applies both mechanisms, or reports a legacy result as a new-route success, keep host promotion blocked.

### IR-04 — Establish safe inverse composition and one eye sample

**Dependencies:** IR-01/IR-02; G13. **Output:** the checked coordinate map and renderer contract used by IR-03.

1. Define the new source-forward field and full derivatives, including support/protection gradients. For the bilinear representation, bound every cell interior or provide an equivalent complete argument. Check image coverage and global injectivity; positive sampled determinant alone is insufficient.
2. Solve the target-to-source inverse under the declared method and verify the residual. For a contraction method, prove the applicable bound/domain; otherwise use a separately verified inverse. Do not transplant one subtraction of a source-forward displacement as an exact inverse.
3. First qualify an **eye-only** request with other geometric refiners inactive. Compose the iris field with the directly interacting eye controls on frozen source geometry, or declare an explicit order and use the chain rule. Sample the immutable canonical source for the eye geometry once through the composed inverse. If the existing colour prefix is part of that immutable input, name it and preserve its single application; do not sample a previously iris-warped raster.
4. Carry the same map/ownership policy to original-resolution export and preview. Check fractional preview footprints and colour-prefix order without importing the old iris-only clipping domain. Diagnostics must distinguish actual preview work and admission rather than report an iris completion from changed pixels alone.
5. Limit this phase to the eye path and its actual preview/full-resolution cutpoints. Other nose/mouth/brow/face/translation stages remain a declared G13 boundary until specifically composed and checked. Do not claim whole-pipeline single sampling or initiate a repository-wide renderer rewrite. Before general UI promotion, qualify the combinations the host actually allows; unsupported combinations must not be advertised as qualified.

**Acceptance:** full-domain safety/inverse checks pass for the declared route and signed parameter range; instrumentation shows one geometric eye sample; directly affected mixed-eye cases preserve intended motion and protection without sequential iris/eye raster warps. Preview/full-resolution CPU/Metal paths agree within a frozen, appropriate tolerance.

**Stop:** unsafe support, missing source coverage, inverse nonconvergence or conflicting ownership returns original affected source pixels and a distinguishable refusal/no-op. Do not partially clamp a few nodes, widen support into protected anatomy, or retry the old fixed-lid mechanism and call the result successful.

This plan supplies no invented latency budget.

## Minimum future validation scope

The [implementation record](实施与验证.md) lists the exact tests already run for the restricted research slice. The remaining default/host migration should select individual methods/suites according to actual edits:

1. Comparator/field change: run new known-field, full-vector fit and inverse/safety tests plus the affected iris cases in `BeautyIrisScaleRemapTests`, `BeautyIrisExposedScleraTests` and `BeautyContinuousEyeWarpTests`. Review retained local reference output separately; synthetic tests alone do not satisfy the effect gate.
2. Routing/preview change: add only the affected methods in `BeautyStillImageGeometryStageTests`, `BeautyEngineRetainedIrisIntegrationTests`, `BeautyEngineIrisPreviewTests` and `BeautyEngineIrisPreviewFractionalProtectionTests`; include the directly interacting eye-sibling cases and applicable actual-backend parity.
3. API/host promotion: use iris-specific `BeautyEyeSliderContractTests`, `BeautyEngineEyeSliderTests` and `EditorTests` cases, binding checks, actual preview/export and the allowed interaction path. Expand to a dependency only when the change demonstrates that dependency is affected. No default all-SDK or all-feature regression is prescribed.
4. If an iOS native validation is necessary at promotion, follow the existing shared-simulator claim/build guides, use one existing compatible free device with parallel testing disabled, and record the exact scope. No simulator, runtime or model creation/download is part of this plan.

Record which gate passed, which inputs/platforms were exercised, and which evidence gaps remain. A local safety pass, pair-relative fit or host interaction pass must retain its own limited claim.
