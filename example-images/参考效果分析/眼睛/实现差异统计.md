# Reference documents versus the current implementation

**Fresh eleven-control review:** [Current implementation comparison](十一项当前实现对照.md) rechecks the latest working code and separates default iris behavior from its explicit research route, and the measured tilt baseline from the original unmeasured-core audit below.

Audit date: **2026-10-17**. [Eye reference index](README.md) · [Measurement limits](验证记录.md) · [Candidate mathematics](实现公共约定.md)

This is the **original read-only implementation comparison**, including the then-current working-tree changes on `codex/eye-displacement-analysis-20261016` (base HEAD `606ee7f9`). That audit changed no SDK/editor algorithm and ran no tests/builds/new measurements. Source symbols, routing, parameter contracts, host availability and existing test definitions were inspected.

**Subsequent iris implementation, 2026-10-17:** [Implementation and directed validation](眼瞳大小/实施与验证.md) records a new explicit package research route with lid/sclera following, checked inverse sampling, stage/preview integration and actual directed results. It has not passed reference-effect qualification or replaced the default/public/editor route. The 17-item counts and default-behavior comparison below therefore remain applicable; the iris gap now has a tested candidate, not a qualified production replacement. Other item classifications are unchanged.

**Next-feature research:** [去脂 test-only geometry](去脂/实施与验证.md) adds mathematical/replay experiments without production SDK/host edits. It does not replace the retained RGB relief scalar or close the source-relative attribution/ownership gaps. The behavior/count comparison below remains the production baseline.

**Tilt follow-up:** the owner deferred further 去脂 work. The [current tilt baseline/comparator](倾斜/实施与验证.md) now adds actual conditional endpoint replay and 30 distinct directed passes while retaining the production tilt formula. The original audit classifications below are not replaced by a claim of reference acceptance.

The documents contain measured observations and conditional candidates. A different formula is not automatically an implementation bug. A source-relative observation is not an isolated control target. Conversely, existing implementation tests do not qualify agreement with the new reference measurements.

## The active implementation routes

For observed eye support, the eleven signed controls are owned by [BeautyContinuousEyeMap, lines 10–24](../../../BeautySDK/Sources/BeautyEffects/Render/BeautyContinuousEyeMap.swift#L10). [BeautyStillImageGeometryStage, lines 111–158](../../../BeautySDK/Sources/BeautyEffects/Render/BeautyStillImageGeometryStage.swift#L111) creates the continuous map and suppresses the corresponding legacy point controls when observed support owns the stage. Local rejection does not revive those old point pulls.

**Dense iris size is an exception:** its `pupilSize` is removed from the continuous map, then [BeautyIrisScaleRemap](../../../BeautySDK/Sources/BeautyEffects/Render/BeautyIrisScaleRemap.swift#L306) renders it separately. Treating the continuous map's iris branch or `EyeWarpProvider` as the current dense-iris production route would give the wrong comparison. 提肌、眼神矫正 and 对称 still use their admitted control-point routes. 去脂 and 祛红血丝 use canonical still-image local composition via [BeautyEngine, lines 394–451](../../../BeautySDK/Sources/BeautySDK/BeautyEngine.swift#L394).

## Shared contract differences

### Response and neutral assumptions

[BeautyEyeShapeSlider, lines 8–35](../../../BeautySDK/Sources/BeautyCore/Models/BeautyEyeShapeSlider.swift#L8) fixes neutral at `.5`, applies signed linear `(2p−1)*cap*polarity`, and gives tilt the opposite polarity. The eleven screenshot pairs show no numeric values or certified neutral. Therefore centered/symmetric strength and intermediate parameter response are **existing product choices, not measured reference results**. A linear parameter mapping also does not imply linear pixel motion after the inverse map and safety scaling.

### Inverse offsets versus forward displacement

The document defines `F(p)=p+D(p)` on source coordinates. The code's [applyRGBA, lines 957–965](../../../BeautySDK/Sources/BeautyEffects/Render/BeautyContinuousEyeMap.swift#L957) interpolates a destination-grid offset and directly samples `source=(x−d.x,y−d.y)`. This can be an intentional inverse-field definition; it does not automatically need an iterative forward solver. It **does** require conversion before comparing code coefficients with measured source-forward vectors. If the code's nominal field were instead interpreted as the document's forward D, the current single subtraction would only approximate its inverse.

For an ideal unattenuated linear core, current sampling gives:

```text
p_source = q − k*u*(q−c)
forward gain at u = 1/(1−k*u)
relative gain from u=−1 to u=+1 = (1+k)/(1−k)
```

Thus `.063` gives approximately **1.1345**, `.066` gives **1.1413**, and ideal central `.200` gives **1.5**. Their scale is compatible with the documents' approximate size/length/height endpoint gains. Actual envelope, iris attenuation, local saturation, pose, component and joint admission alter the result. Comparing `.063` to a measured 13% span and concluding “half the strength” would be incorrect.

Similarly, an ideal constant-coefficient linear rotational inverse field can yield a relative ±endpoint rotation of `2 atan(k)` while its single-endpoint scale factors cancel. For `.069`, that ideal relative angle is about **7.89°**. This does not qualify the actual tilt field: its y-only attenuation and saturation introduce spatial non-rigidity. The required comparison is a same-source endpoint map with full dx/dy and pairwise geometry, not a coefficient-versus-angle subtraction.

### Support and protection are implemented, but not fitted to this study

The map uses fixed orbital shape radii approximately `1.08L/.75L` with `.22L` transition, and spacing radii `1.12L/.85L` with `.30L` transition, alongside feature/peer/bridge protections: [Map 136–152, 200–233, 574–605](../../../BeautySDK/Sources/BeautyEffects/Render/BeautyContinuousEyeMap.swift#L574). Height/length have interior iris attenuation; position/spacing translate the core without that multiplier. These are different contracts, not one generic missing-protection defect.

The study identifies some quiet regions and following texture, but not these exact support constants, hard zeros or plateau shapes. Independent matching at the transition is required before changing them on reference grounds. “Protected” is not equivalent to “the reference is reproduced.”

### Safety admission exists

[Map, lines 315–415](../../../BeautySDK/Sources/BeautyEffects/Render/BeautyContinuousEyeMap.swift#L315) performs component and combined bounds, including a bilinear-field gradient limit `.45`, displacement limit `.15*minimumSpan`, and pose scaling. The implementation is not an unchecked control-point core. Its safety admission is separate from reference agreement, and those limits also mean the nominal per-control coefficient is not always the final amplitude.

### Composition and source sampling differ

Ordinary continuous eye terms are accumulated into one eye-map pass. Dense iris first creates a separate raster, however; combined nose/mouth/brow/face/eye/translation stages then operate in order. See [Stage 132–136, 226–229](../../../BeautySDK/Sources/BeautyEffects/Render/BeautyStillImageGeometryStage.swift#L132) and [Geometry pipeline 271–279](../../../BeautySDK/Sources/BeautyEffects/Render/BeautyGeometryEffectPipeline.swift#L271). When multiple geometric stages are active, this is sequential raster resampling, whereas the document proposes composing inverse coordinates and sampling the original once. The resulting quality/coordinate impact was not measured in this audit. A single eye-only operation must not be described as necessarily running every resampling stage.
