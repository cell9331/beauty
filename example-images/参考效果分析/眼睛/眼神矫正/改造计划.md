# Gaze-correction menu item: migration plan

Planning date: 2026-10-17. **Status: planned only; no implementation or test execution.** [Shared sequence and gates](../改造计划.md) · [Evidence gaps](../证据缺口.md) · [Current item evidence](README.md)

## Current behavior and change decision

The SDK moves each qualified observed pupil toward its own eye center with bounded blending and aperture containment; the editor control is disabled. The reference target is unknown.

Establish what gaze is corrected toward before changing the current own-eye-center behavior. Keep fail-closed ownership and the retained public compatibility route.

Current change location: [EyeWarpProvider.swift](../../../../BeautySDK/Sources/BeautyEffects/Warp/EyeWarpProvider.swift#L257); inspect only the term and shared helpers actually affected.

## Ordered tasks

1. Collect controlled selected pairs for asymmetric gaze, an already aligned negative, a one-valid-eye case and occluded/ambiguous iris support. Record target direction and whether eyes are coupled.
2. Use source iris/sclera/lid observations to compare own-eye-center, a shared intended gaze target and any reference-supported asymmetry. Do not infer gaze direction from the menu name.
3. Only if target semantics differ, design an explicitly identified route/migration. Reuse trusted iris/support ownership, bounded aperture/source coverage and one-source sampling; preserve the existing strict unobserved-side rejection.

Use the shared C0 comparator before fitting; C1 field/inverse rules and C2 ownership/composition apply only to changes actually selected. Do not silently change centered slider, serialized scalar or unavailable-host semantics. A field-coefficient change must be evaluated through the actual admitted forward/relative map, including pose and safety scaling.
