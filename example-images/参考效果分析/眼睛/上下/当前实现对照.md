## Reference facts

`IMG_1930 → IMG_1931` shows approximate downward core translation: independent median dy +19.52/+18.40 px, with dx near zero. Rigid-fit P95 is 0.37/0.52 px. These are observed endpoint spans. See [evidence](分析链路.md).

## Active implementation

The nominal inverse term is `(0, .0603*visibleSpan*u*shapeWeight)` in image axes. The shared envelope supplies a central plateau subject to feature protection. Source span determines each eye's amplitude. See [image-y term](../../../../BeautySDK/Sources/BeautyEffects/Render/BeautyContinuousEyeMap.swift#L718).

## What differs

Both describe a translating core. The [candidate](实现方案.md) proposes a source-local inferior direction and independently fitted bilateral amplitudes; code chooses image-y and one normalized coefficient. The near-frontal reference does not establish behavior under head roll. Unequal measured pixel travel does not disprove a shared normalized gain, because source spans can differ. Transition widths and amplitude have not been compared on actual admitted maps.

## Qualification and missing discriminator

No same-pair actual Swift vector/raster baseline is recorded. The candidate's rotated local direction is a proposal, not a recovered product rule. A same-material endpoint replay can compare frontal displacement and falloff; a qualified rolled reference is needed to decide pose axes.

Numerical constants above describe existing code or measured aggregates; they are not replacement defaults. See the shared comparison for inverse/forward domains, strength polarity, admission and source-sampling limits.
