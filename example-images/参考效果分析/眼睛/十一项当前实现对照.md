**Reviewed 2026-10-17 against the current working files, including uncommitted changes.** This is a fresh comparison of the eleven requested controls: 大小、上下、眼高、长度、眼距、眼瞳大小、眼睑下至、眼尾上扬、倾斜、内眼角、外眼角. 去脂 and the five menu-only controls are outside this review. The owner's deferred 去脂 decision remains unchanged.

All eleven have implemented routes for supported/admitted input. This is not eleven missing functions. The clearest supported default-path conflict is **iris size: fixed eyelid/aperture preservation versus measured lid/sclera following**. **Tilt now has a measured conditional current-baseline discrepancy**, with its production formula deliberately retained. The other **nine** broadly match the observed direction/mechanism; their axes, anchors, internal weighting, support and response remain unqualified against this image batch. Structural differences from a proposed formula are not automatically demonstrated reference failures.

No SDK/host code, parameter, safety limit, route default or algorithm was changed by this review. No new image measurement, Swift build, test, simulator or device run was performed. Previously recorded iris/tilt runs are identified as historical evidence, not rerun results.

## Shared contracts that change how the comparison must be read

### Forward measured motion versus inverse sampling

The reference documents measure `F(p)=p+D(p)` on source material. The current ordinary lattice stores an inverse-sampling offset. In array sample-index coordinates, its [actual sampler](../../../BeautySDK/Sources/BeautyEffects/Render/BeautyContinuousEyeMap.swift#L902) and [coordinate probe](../../../BeautySDK/Sources/BeautyEffects/Render/BeautyContinuousEyeMap.swift#L875) imply:

```text
B_u(q) = q - d_u(q + (0.5, 0.5))
H(r) = inverse(B_high)(B_low(r))
```

`H` compares the same material between endpoints. Subtracting the two destination-grid offset arrays at equal indices does not produce that forward endpoint map. The ordinary probe refuses unsupported iris/clamping cases; it must not be repurposed as a dense-iris oracle.

Consequently, nominal inverse coefficients are not reference endpoint amplitudes. In an ideal unsaturated unit-envelope linear expansion, the relative ±endpoint gain is `(1+k)/(1-k)`: `.063 → 1.1345`, `.066 → 1.1413`, `.200 → 1.5`. These are algebraic controls, not measurements of actual admitted output. For ideal linear rotational inverse endpoints the relative angle is `2*atan(k)`; `.069 → about 7.89°`. Attenuation, saturation, protection, admission, pose and geometry change the real fields. None of these calculations proves a match or an amplitude defect.

### Neutral, axes and parameter response

The [public slider](../../../BeautySDK/Sources/BeautyCore/Models/BeautyEyeShapeSlider.swift#L8) uses a centered neutral `.5` and signed linear parameter travel; tilt reverses the direct API polarity. The screenshot pairs show no numeric values or certified reset/neutral. The existing public mapping is a product contract, not a recovered reference curve. Endpoint motion must not be halved into invented neutral measurements.

Size, length and height use the source eye tangent/normal. Vertical position and spacing choose image-y/image-x; lower-lid and tail terms use image-y, corner pulls use image-x. Several candidates propose local anatomical axes instead. The near-frontal evidence does not identify the correct rolled-pose rule, so those candidate differences do not justify silently changing production axes. A local-tangent/normal motion can itself produce both image components; conversely small uncertain orthogonal observations do not alone justify another parameter.

### Support, interior attenuation and safety admission

The code already has substantial source geometry/protection. [Ordinary shape/spacing envelopes](../../../BeautySDK/Sources/BeautyEffects/Render/BeautyContinuousEyeMap.swift#L574) have predefined scales, protected-distance transitions and bridge handling. [Interior attenuation](../../../BeautySDK/Sources/BeautyEffects/Render/BeautyContinuousEyeMap.swift#L610) is smooth/contour-weighted: it must not be described as freezing the whole iris or eyelid. Position/spacing do not use that attenuation; tilt also avoids its iris multiplier. Dense iris has a different fixed-aperture contract.

[Component admission](../../../BeautySDK/Sources/BeautyEffects/Render/BeautyContinuousEyeMap.swift#L379) and [joint/pose scaling](../../../BeautySDK/Sources/BeautyEffects/Render/BeautyContinuousEyeMap.swift#L415) constrain actual amplitude, including gradient `.45` and displacement `.15*span` budgets. The post-admission `.93` outer-corner gain is another current choice. Those are existing lattice/admission rules, not proof of reference fidelity, universal ownership or a fitted target. No limit is weakened by this comparison.

### Composition and original sampling

Ordinary continuous eye controls share an eye-field raster. Dense iris supplies a separate raster, and the [geometry pipeline](../../../BeautySDK/Sources/BeautyEffects/Render/BeautyGeometryEffectPipeline.swift#L266) can then apply other geometric stages in sequence. The reference candidate convention proposes inverse-coordinate composition with one final original sample. This is a shared composition difference for combined edits; it does not mean a single isolated eye control necessarily performs every raster pass. Quality/cost of a general composition replacement is not measured here.
