## Shared implementation prerequisites

<a id="c0"></a>
### C0 — Compare material points in one declared domain

Add a test-only comparator, provisionally `BeautySDK/Tests/BeautyEffectsTests/BeautyEyeReferenceComparisonTests.swift`, with reusable helpers beside the affected eye tests. Prefer narrow internal test access to existing evaluators over adding public coordinates/diagnostics. Preserve current output as a baseline before changing the model.

The current map is a destination-to-source function `G_u(q)=q−d_u(q)`. Its coefficients are not source-forward displacement coefficients. Under one declared, frozen code geometry and source carrier, compare endpoint material points as:

```text
r = observed low-endpoint source location
p0 = G_low(r)
solve G_high(q) = p0
predicted endpoint vector at r = q − r
```

Equivalently the relative map is `G_high^(-1) ∘ G_low`. Verify solver residual and domain/coverage; do not subtract the two offset arrays at the same grid index. For a new source-forward candidate `F_u`, compare `F_high ∘ F_low^(-1)` on those same low-endpoint points. If fitting a candidate directly to the observed pair, state that its source is the low endpoint and keep it separate from a neutral-based product route.

A convenient registered source carrier is not automatically an application neutral. Freeze how geometry is extracted and assess sensitivity to that carrier; preserve any confounding caused by unrecorded reset states. Do not use the ideal `(1+k)/(1−k)` gain or `2 atan(k)` rotation identities as acceptance of the actual weighted field. They are controls on interpretation, not fitted results.

Freeze input identities, state qualification, fit/holdout separation, source-only selection, signed component/profile/contour metrics, minimum moving and protected coverage, uncertainty and effect-fit bounds under G14 **before optimization**. Existing exploratory point sets can inform the model, but are not an unseen validation set. Dense-method disagreement is not ground-truth error and cannot automatically become the allowed reproduction error.

<a id="c1"></a>
### C1 — Candidate representation, support and inverse

Use reliable source geometry and explicit axes/scales. Keep internal movement separate from surrounding support/ownership. Reuse valid eye support and geometry checks; add a small field abstraction only where the current implementation cannot express a qualified target. Proposed helper/file names in per-feature plans are implementation locations, not new public APIs or mandatory frameworks.

For new forward fields, include the full support/protection/projection/normal derivatives in the Jacobian and justify a global inverse/coverage strategy. A contraction certificate or independently checked invertible representation is required; positive sampled determinants alone do not suffice. A direct inverse field may also be retained when its contract is explicit and its actual forward/relative behavior meets the target. Do not require an iterative solver merely because a field is expressed inversely.

Freeze a source-pixel inverse-residual budget and sampling policy separately from photographic effect-fit bounds. Test zero, known translation/expansion/rotation, compact edges, malformed geometry, unsafe transitions, inverse failure, source coverage, valid-peer isolation and exact exterior identity. Those checks qualify mathematics/safety on their inputs, not effect reproduction.

<a id="c2"></a>
### C2 — Eye-scoped composition and migration ownership

Start within the eye route. Keep existing canonical orientation/color/opacity behavior, face ownership, detection reuse, still-image limits and request-private geometry. Preserve unrelated face, nose, mouth and eyebrow behavior; this plan does not mandate a global renderer rewrite.

The current change points are [BeautyStillImageGeometryStage](../../../BeautySDK/Sources/BeautyEffects/Render/BeautyStillImageGeometryStage.swift), [BeautyContinuousEyeMap](../../../BeautySDK/Sources/BeautyEffects/Render/BeautyContinuousEyeMap.swift), [BeautyIrisScaleRemap](../../../BeautySDK/Sources/BeautyEffects/Render/BeautyIrisScaleRemap.swift) and the [iris preview cutpoint](../../../BeautySDK/Sources/BeautyEffects/Render/BeautyIrisPreviewCutpoint.swift). Adapt the selected eye mappings to a shared frozen source, compose their inverse coordinates in a declared order, and sample that source once. Preserve texture/ownership restrictions that remain independently justified; do not blend two displaced rasters to hide seams.

Do not apply new iris deformation both through the dedicated remap and the continuous map. Do not reinterpret a color-retouch proposal as a displacement field for 去脂. Declare overlap, source-coverage and unsupported-combination behavior. Failed new-route admission must not silently revive a retired wrong-target proxy; preserve local identity or an explicit unsupported/refusal result according to the declared route. A valid independent peer remains usable when its ownership is sound.

Admit combined controls only after the affected coordinate/ownership and output comparisons pass. If only isolated operations qualify, keep the new route restricted accordingly, with explicit unsupported-combination semantics. Expand tests to other geometric stages only when a real dependency is affected. Measure incremental raster work, memory and cost on exposed preview/original-size paths; do not infer speedup from fewer source samples or report macOS measurements as iOS performance.

### C3 — Compatibility, release and deliberate rollback

Preserve existing serialized fields, slider identities/defaults, sibling independence and still/realtime boundaries. A new reference-derived target that changes intentionally maintained behavior needs an explicit migration/version decision and tests for both retained compatibility and the new route. 去脂's retained brightness scalar is not silently converted into geometric semantics. No model download, public API change, default discovery revival or host re-enablement occurs in this documentation task.

Release gates are independent: **reference-effect fit**, **mathematical/input/protection safety**, **compatibility and composition**, then **host availability** for the affected flow. A failing effect gate cannot be repaired by weakening the protection oracle; a passing safety gate does not establish useful appearance. Preserve failures and the current stable behavior outside the deliberately selected migration. Rollback selects an explicitly identified previous compatible route; per-request failure on the new route must not claim successful reproduction through an unqualified fallback.

## Minimum sufficient future verification

For each future code change, select the named feature tests and directly affected shared route tests only. Existing coverage must be reviewed for its purpose: replace fixed-lid **target** assertions when moving to the qualified iris-follow target, while retaining independent canthal/exterior/invalid-input/alpha and ownership **safety** assertions. Keep old compatibility tests when a route remains supported. Never remove a verifier, suppress a failed positive, or use a no-op test command to satisfy a gate.

Extend verification only for a specific changed dependency. A shared eye-map change justifies directly affected sibling cases and exposed backend parity, not the entire SDK suite. Canonicalization changes would justify relevant orientation/profile/opacity tests; merely reusing the canonical carrier does not trigger its whole historical matrix. No full SDK or all-feature regression is a default task here.

Native checks are required only when an actual backend/device/host path changes. At that time reuse stable package/editor caches, one existing compatible idle claimed simulator, and the normal requested environment; disable parallel simulator runners, release the device promptly, and do not create/clone devices or expand device/font/orientation matrices. No simulator/device/build operation is performed now. If a host flow later changes, inspect that changed flow's real screenshots/interaction and follow its applicable safe-area guidance then.
